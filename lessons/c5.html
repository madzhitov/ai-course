Claude Code — CLI для разработчиков

Цель: освоить Claude Code как ежедневный инструмент разработчика Время: ~60 минут Источник: docs.claude.com/claude-code

Зачем тебе этот урок

Anthropic выпустил Claude Code — агентский CLI для разработчиков. Это один из самых быстрорастущих инструментов в индустрии: в отличие от Cursor (IDE с AI) или Copilot (автокомплит), Claude Code — это агент в терминале, который сам читает проект, пишет и рефакторит код, запускает тесты, дебажит, коммитит и открывает PR.

Если ты разработчик и ещё не пробовал — обязательно. Если ты не пишешь код — этот урок поможет понять, чем сейчас работают коллеги вокруг тебя.

Важно: за последний год Claude Code сильно вырос. Кроме базового «напиши код» появились subagents, hooks, plan mode, MCP-интеграция, фоновые задачи. Этот урок — про актуальную версию.

1. Что такое Claude Code

Это агентский CLI, который:

  • Запускается в твоём проекте одной командой: claude
  • Читает и пишет файлы, запускает команды в терминале, ищет по коду
  • Держит контекст всего проекта (через CLAUDE.md)
  • Использует Claude Sonnet / Opus / Haiku как «мозг»
  • Работает по подписке Claude Pro/Max ИЛИ по API-ключу (об этом ниже)

В отличие от Cursor или Copilot, Claude Code не привязан к редактору. Ты в любом терминале, в любом проекте, на любой машине. Есть и расширения для VS Code / JetBrains, но ядро — терминал.

2. Установка и старт за 5 минут

# 1. Установка (нужен Node.js 18+)
npm install -g @anthropic-ai/claude-code

# 2. Запуск в проекте
cd ~/your-project
claude

При первом запуске Claude предложит войти. Два варианта оплаты:

  • Подписка Claude Pro/Max — логинишься своим аккаунтом claude.ai. Удобно: фиксированная цена в месяц, не считаешь токены. Max-тариф даёт большой лимит для плотной работы.
  • API-ключ — export ANTHROPIC_API_KEY=sk-ant-.... Платишь по факту за токены. Удобно для CI/автоматизации.

Открывается интерактивный режим. Пиши задачу обычным языком — Claude её делает.

3. Основные сценарии использования

Генерация кода

> Напиши функцию, которая парсит CSV и возвращает массив объектов
[Claude читает существующий код, понимает стиль, пишет функцию,
 предлагает добавить тесты]

Рефакторинг

> Раздели UserService на два класса: UserRepository (БД) и UserService
(бизнес-логика). Сохрани публичный API.
[Claude находит все файлы, делает изменения атомарно]

Дебаг

> Тест UserService.test.ts падает с "expected 5 got 4". Найди причину.
[Claude запускает тест, читает stacktrace, ищет в коде, предлагает фикс]

Документация и ревью

> Прочитай весь src/api и напиши README с описанием эндпоинтов
> Сделай ревью изменений в текущей ветке — безопасность и стиль

4. CLAUDE.md — контекстный файл

Главный секрет эффективного Claude Code — файл CLAUDE.md в корне проекта. В нём ты описываешь проект так, как объяснил бы новому коллеге:

  • Что это за проект и стек
  • Где что лежит (структура)
  • Конвенции кода
  • Что НЕЛЬЗЯ делать
  • Команды для тестов, билда, линта
# CLAUDE.md

## Что это
SaaS для управления подписками. B2B, средний бизнес.

## Стек
- Backend: Python 3.12, FastAPI, SQLAlchemy 2, Postgres 16
- Frontend: React 19, TypeScript, Tanstack Query
- Тесты: pytest, vitest

## Структура
- src/api — HTTP-эндпоинты
- src/services — бизнес-логика
- src/db — модели и миграции (Alembic)

## Конвенции
- Type hints везде, mypy в strict
- async/await в API-слое
- Тесты для всего в src/services

## Не делай
- Не добавляй новые ORM-зависимости
- Не пиши в main без PR

## Команды
- Запуск: `make dev`  ·  Тесты: `make test`  ·  Линт: `make lint`

Команда /init сгенерирует первую версию CLAUDE.md автоматически — потом дополни руками. Чем подробнее файл — тем точнее работает агент. Можно держать CLAUDE.md и в подпапках (для монорепо), и глобально (~/.claude/CLAUDE.md).

5. Slash-команды

В интерактивном режиме — команды через /:

  • /init — сгенерировать CLAUDE.md из проекта
  • /clear — очистить контекст (новая задача с нуля)
  • /compact — сжать историю, сохранив суть (когда контекст разросся)
  • /model — переключить модель (Sonnet ↔ Opus ↔ Haiku)
  • /agents — управление субагентами (см. ниже)
  • /mcp — статус подключённых MCP-серверов
  • /cost — расход за сессию (если на API)
  • /help — полная справка

6. Кастомные команды и Skills

Кастомные команды — шаблоны для повторяющихся задач, файлы в .claude/commands/. Файл .claude/commands/review.md:

---
description: Code review текущей ветки с фокусом на безопасность
---

Сделай тщательное ревью:
1. Прочитай git diff против main
2. Проверь: SQL-инъекции, XSS, утечки секретов, missing auth
3. Сверь стиль с конвенциями из CLAUDE.md
4. Отчёт: Critical / Suggested / Style

Теперь набираешь /review — и шаблон запускается.

Skills — более мощный механизм: папка с SKILL.md и вспомогательными файлами/скриптами, которую Claude подхватывает сам, когда задача подходит под описание. В отличие от команды (её надо вызвать вручную через /), Skill активируется автоматически. Подробно — в уроке c9 «Claude Skills». Claude Code читает Skills из .claude/skills/.

7. Субагенты — параллельная работа

Одна из самых сильных фич. Субагент — это отдельный «работник» со своим контекстом, которому Claude делегирует подзадачу. Зачем:

  • Параллелизм: запустить 3 агента одновременно — например, написать 3 независимых модуля сразу
  • Чистота контекста: агент исследует большой кусок кода и возвращает выжимку, не засоряя главный диалог
  • Специализация: агент-ревьюер, агент-тестировщик, агент-исследователь со своими инструкциями

Свои субагенты описываются в .claude/agents/ — markdown-файл с ролью, инструментами и системным промптом. Управление — через /agents. Пример: агент code-reviewer, который Claude вызывает после каждого крупного изменения.

8. Hooks — автоматизация по событиям

Hooks — это твои команды, которые Claude Code запускает автоматически на определённых событиях. Настраиваются в settings.json. События:

  • PreToolUse — перед действием (например, заблокировать запись в защищённые файлы)
  • PostToolUse — после (например, прогнать prettier после каждого редактирования файла)
  • Stop — когда Claude закончил (например, запустить тесты)

Пример: hook, который автоматически форматирует код после каждого изменения — тебе не надо просить «отформатируй», это происходит само. Hooks выполняет сам Claude Code (не модель), поэтому они детерминированы — то, что «всегда должно происходить», лучше делать хуком, а не просьбой в промпте.

9. Plan mode, checkpoints и память

Plan mode

Режим, в котором Claude сначала исследует и составляет план, ничего не меняя, и показывает тебе на утверждение. Включается через Shift+Tab. Незаменимо для крупных задач: видишь стратегию до того, как агент начнёт писать код.

Checkpoints (откат)

Claude Code сохраняет состояние перед изменениями. Двойной Esc — откатиться назад по диалогу и по файлам, если агент пошёл не туда. Безопасная сеть: всегда можно вернуться.

Память

Быстрая команда # в начале сообщения — добавить факт в память (в CLAUDE.md). Например: # всегда используй pytest, не unittest — и это запомнится для будущих сессий.

Возобновление сессий

claude --continue продолжает последнюю сессию, claude --resume — выбрать из истории. Контекст и история сохраняются между запусками.

10. MCP — подключение внешних инструментов

Claude Code умеет подключать MCP-серверы (см. урок c3) — это даёт агенту доступ к внешним системам прямо из терминала: твоя база данных, Notion, Linear, GitHub, Sentry, браузер. Например, с MCP-сервером Postgres Claude может сам посмотреть схему БД; с MCP браузера — открыть и протестировать страницу.

Подключение — через claude mcp add или в конфиге. Статус — /mcp. Это превращает Claude Code из «агента по коду» в «агента по всей твоей инфраструктуре».

11. Headless-режим — Claude Code в CI и скриптах

Claude Code можно запускать без интерактива — для автоматизации:

# Одна задача, вывод в stdout, без диалога
claude -p "Просуммируй изменения в этой ветке и проверь на security-проблемы"

# В CI: автоматическое ревью каждого PR
# В pre-commit хуке: проверка перед коммитом

Есть и официальная GitHub-интеграция: Claude Code как GitHub Action — отвечает на PR, делает ревью, реализует issue по упоминанию. Это уже не «помощник в терминале», а часть пайплайна.

12. Безопасность и разрешения — критично

Claude Code может удалить файлы, запушить в репо, потратить токены. Поэтому:

  • Перед опасными действиями (rm, git push, запись файлов) Claude спрашивает подтверждение
  • Разрешения настраиваются в settings.json: что разрешено без спроса (allow), что запрещено (deny). Например, разрешить npm test, но запретить git push
  • Hooks (PreToolUse) могут жёстко блокировать действия — детерминированная защита, не зависящая от «настроения» модели
  • Не давай доступ к продакшен-секретам. Запускай в проекте под git — всегда есть откат

13. Стоимость

Два пути оплаты:

  • Подписка Claude Pro/Max — фиксированная цена в месяц, не считаешь токены. Max-тариф рассчитан на плотную ежедневную работу. Для большинства разработчиков — самый предсказуемый вариант.
  • API (pay-per-token) — Sonnet ~$3/$15 за M входных/выходных токенов, Opus дороже, Haiku дешевле. Типичная сессия 30 минут — несколько долларов. Удобно для CI и эпизодического использования.

Цены и тарифы меняются. Актуальное — на anthropic.com/pricing. Совет: на API включи prompt caching (урок c6) — на длинных контекстах экономит до 90%.

15. Глоссарий

  • Claude Code — агентский CLI Anthropic для разработчиков
  • CLAUDE.md — контекстный файл проекта (стек, конвенции, команды)
  • Субагент — отдельный агент со своим контекстом для подзадачи (.claude/agents/)
  • Hook — команда, запускаемая автоматически на событии (settings.json)
  • Plan mode — режим планирования без изменений (Shift+Tab)
  • Кастомная команда — шаблон в .claude/commands/, вызов через /
  • Skill — авто-подхватываемый навык (.claude/skills/, см. c9)
  • MCP-сервер — внешний инструмент для агента (см. c3)
  • Headless — запуск без интерактива (claude -p) для CI/скриптов

16. Практика (60 минут)

Упражнение 1. Установка и /init (15 минут)

Установи Claude Code, запусти в своём проекте, выполни /init. Проверь сгенерированный CLAUDE.md, допиши конвенции и запреты.

Упражнение 2. Plan mode на реальной задаче (15 минут)

Возьми задачу из бэклога. Включи plan mode (Shift+Tab), дай задачу. Посмотри план до выполнения — оцени, насколько Claude понял задачу правильно.

Упражнение 3. Кастомная команда (15 минут)

Создай .claude/commands/review.md со своими правилами ревью. Протестируй /review на текущих изменениях.

Упражнение 4. Hook (15 минут)

Настрой PostToolUse-hook, который прогоняет форматтер (prettier / black) после каждого изменения файла. Сделай правку — убедись, что код форматируется автоматически.

17. Проверь себя

1. Что такое Claude Code в одном предложении?
Агентский CLI от Anthropic — читает/пишет код, запускает команды, дебажит, автоматизирует, работает по подписке или API.

2. Чем CLAUDE.md полезен?
Контекстный файл проекта: стек, структура, конвенции, запреты, команды. Чем подробнее — тем точнее агент.

3. Что такое субагенты и зачем они?
Отдельные агенты со своим контекстом для подзадач. Дают параллелизм, чистоту главного контекста и специализацию (ревьюер, тестировщик).

4. Что делают hooks?
Запускают твои команды автоматически на событиях (до/после действия, по завершении). Например, авто-форматирование или блокировка записи в защищённые файлы. Детерминированы — выполняет сам Claude Code, не модель.

5. Что такое plan mode и когда он нужен?
Режим планирования (Shift+Tab): Claude исследует и показывает план, ничего не меняя. Нужен для крупных задач — увидеть стратегию до выполнения.

6. Как Claude Code оплачивается?
Подписка Claude Pro/Max (фиксированная цена) ИЛИ API-ключ (pay-per-token). Подписка предсказуемее для ежедневной работы.

7. Чем кастомная команда отличается от Skill?
Команду вызываешь вручную через /. Skill Claude подхватывает сам, когда задача подходит под описание. Подробнее про Skills — урок c9.

8. Зачем подключать MCP к Claude Code?
Чтобы агент работал не только с кодом, а со всей инфраструктурой: БД, Notion, Linear, браузер, Sentry. См. урок c3.

9. Можно ли запускать без интерактива?
Да, headless-режим: claude -p "задача". Используется в CI, pre-commit хуках, GitHub Actions для авто-ревью PR.

10. Главные риски и как защититься?
Может удалить, запушить, потратить токены. Защита: подтверждение опасных действий, настройка allow/deny в settings.json, PreToolUse-хуки, проект под git (откат), не давать продакшен-секреты.

18. Что должно остаться в голове

  1. Claude Code = агент в терминале. Не IDE, не плагин — самостоятельный инструмент, который сам делает многошаговые задачи.
  2. CLAUDE.md — фундамент. Без него агент действует наугад. Это онбординг проекта для AI.
  3. Автоматизируй детерминированное хуками, делегируй параллельное субагентам. То, что «всегда должно происходить» — хук, а не просьба.
  4. Plan mode для крупных задач. Сначала план и согласование, потом код — экономит часы переделок.
  5. Подписка или API. Pro/Max — предсказуемая цена для ежедневной работы; API — для CI и эпизодов, с prompt caching (c6).
