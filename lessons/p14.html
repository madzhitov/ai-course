Проект «За 1 час»: Локальный AI на Ollama — всё на твоём ноутбуке, без облака

Что построим: локальный LLM-сервер с REST API, без подписок и интернета Время: ~75 минут Уровень: базовый Python + понимание REST

Что в итоге будет

У тебя на ноуте крутится Ollama — это локальный сервер, который раздаёт большие языковые модели по REST API на localhost:11434. Подключаешь его из Python, из браузера, из своего скрипта. Платишь — только электричеством. Документы из NDA — не утекают. Интернета нет — работает.

На выходе ты понимаешь, что реально умеют локальные модели в 2026 году (спойлер: больше, чем кажется), на каком железе они летают, а где упираются, и как встраивать их в свои проекты вместо облачных API.

Требования

  • macOS (M1 и новее лучше всего), Linux, или Windows 10+.
  • 16 GB RAM минимум для 8B-моделей, 32 GB — комфортно. На 8 GB — только модели до 3B.
  • ~10 GB места на диске под пару моделей.
  • Python 3.10+.

Шаг 1. Устанавливаем Ollama

macOS: скачай .dmg, перетащи в Applications, запусти. Появится иконка в menu bar — это и есть сервер. Альтернативно brew install ollama + brew services start ollama.

Linux:

curl -fsSL https://ollama.com/install.sh | sh
# поднимется как systemd-сервис автоматически

Windows: установщик с сайта. Сразу появляется в системном трее.

Проверь, что сервер живой:

curl http://localhost:11434/api/version
# {"version":"0.3.x"}

Шаг 2. Скачиваем модель

Ollama использует команду pull по аналогии с docker.

ollama pull llama3.1:8b

Это качает ~4.7 GB. После — сразу можно говорить:

ollama run llama3.1:8b
>>> Привет, кто ты?
Я — Llama, ассистент от Meta...
>>> /bye

Какую модель выбрать под железо

Ориентир по RAM (а на Mac — по объединённой памяти):

  • 8 GB: llama3.2:3b, qwen2.5:3b, gemma2:2b. Маленькие, но удивительно разумные для саммари и простых задач.
  • 16 GB: llama3.1:8b, qwen2.5:7b, mistral:7b, gemma2:9b. Базовый разумный диапазон.
  • 32 GB+: qwen2.5:14b, llama3.1:8b-instruct-q8_0 (более точная квантизация), mixtral:8x7b.
  • 64+ GB / M3 Max и выше: qwen2.5:32b, llama3.3:70b в квантизации q4 — медленно, но реально умно.

Тег после двоеточия — это размер модели в миллиардах параметров и квантизация. По умолчанию идёт q4_K_M — компромисс качества и размера. q8_0 точнее, но в 2 раза больше и медленнее.

У меня на повседнев — qwen2.5:7b для кода и llama3.1:8b для общих задач. Скачай обе:

ollama pull qwen2.5:7b
ollama list   # покажет всё скачанное

Шаг 3. Архитектура и REST API

Ollama — это HTTP-сервер на 11434. Два основных эндпоинта:

  • POST /api/generate — single-shot completion.
  • POST /api/chat — диалог с историей сообщений (как у OpenAI/Anthropic).

Простейший вызов через curl:

curl http://localhost:11434/api/chat -d '{
  "model": "llama3.1:8b",
  "messages": [
    {"role": "user", "content": "одной фразой: что такое RAG?"}
  ],
  "stream": false
}'

Шаг 4. Питон-клиент

Есть официальный ollama-python, но он тонкая обёртка над requests. Покажу оба варианта.

Файл ollama_client.py:

import requests

OLLAMA_URL = "http://localhost:11434"


def chat(model: str, messages: list[dict], stream: bool = False) -> str:
    """Простейший синхронный чат."""
    resp = requests.post(
        f"{OLLAMA_URL}/api/chat",
        json={"model": model, "messages": messages, "stream": stream},
        timeout=180,
    )
    resp.raise_for_status()
    return resp.json()["message"]["content"]


def chat_stream(model: str, messages: list[dict]):
    """Генератор: выдаёт ответ по кусочкам по мере генерации."""
    with requests.post(
        f"{OLLAMA_URL}/api/chat",
        json={"model": model, "messages": messages, "stream": True},
        stream=True,
        timeout=180,
    ) as resp:
        resp.raise_for_status()
        for line in resp.iter_lines():
            if not line:
                continue
            import json
            chunk = json.loads(line)
            if chunk.get("done"):
                break
            yield chunk["message"]["content"]


if __name__ == "__main__":
    msgs = [{"role": "user",
             "content": "напиши 3 punchy названия для подкаста про инженеров и ИИ"}]

    # синхронный вариант
    print("--- sync ---")
    print(chat("llama3.1:8b", msgs))

    # streaming - сразу видно, как печатает
    print("\n--- stream ---")
    for piece in chat_stream("llama3.1:8b", msgs):
        print(piece, end="", flush=True)
    print()

С ollama-python то же самое выглядит компактнее:

import ollama   # pip install ollama

resp = ollama.chat(model="llama3.1:8b",
                   messages=[{"role": "user", "content": "..."}])
print(resp["message"]["content"])

Шаг 5. Замеряем скорость на своём железе

Полезно сразу проверить, что вообще ожидать. Сохрани как bench.py:

import time
from ollama_client import chat

PROMPT = "Объясни одним абзацем (5-7 предложений), как работает Transformer."

for model in ["llama3.2:3b", "llama3.1:8b", "qwen2.5:7b"]:
    try:
        start = time.time()
        text = chat(model, [{"role": "user", "content": PROMPT}])
        elapsed = time.time() - start
        # грубая оценка: 1 токен ≈ 4 символа
        tokens = len(text) / 4
        tps = tokens / elapsed
        print(f"{model:<18} {elapsed:5.2f}s | ~{tps:5.1f} t/s | {len(text)} chars")
    except Exception as e:
        print(f"{model:<18} skipped: {e}")

Мои замеры на разных машинах (модель llama3.1:8b):

  • MacBook Air M2, 16 GB: ~24 токена/сек. Комфортно для интерактива.
  • MacBook Pro M3 Max, 64 GB: ~55 t/s. Заметно быстрее Claude в API.
  • Mac mini M4, 24 GB: ~35 t/s.
  • Десктоп с RTX 4090: ~95 t/s (через CUDA backend).
  • Линукс-сервер на чистом CPU, Xeon, без GPU: ~3 t/s. Болезненно.

Правило: без Apple Silicon или nVidia GPU — локальные LLM не для интерактива. С M-серией начиная с M1 — уже комфортно.

Шаг 6. Сравнение качества с Claude

Гонял один и тот же набор задач через llama3.1:8b, qwen2.5:7b и Claude Sonnet 4.5. Субъективная сводка:

Задача Local 7-8B Claude Sonnet
Саммари статьи на 3 абзацаНормЧуть точнее
Простой Python-скрипт (50 строк)Работает, может багатьПочти всегда работает
Перевод RU↔ENАдекватно, идиомы хромаютЗаметно лучше
Сложный код / архитектурные вопросыСлабоСильно лучше
Структурный JSON-outputМожет ломать схемуСтабильно
Длинный контекст (50k+)Часто не помещается200k без вопросов

Грубо: локальная 7-8B модель — это уровень GPT-3.5 двухлетней давности с поправкой на свежесть. Для простых внутренних задач — за глаза. Для сложного — упирается.

Шаг 7. Use cases: где локальный AI реально нужен

  • Приватные документы. Контракт под NDA, медицинская карта, корпоративная переписка — нельзя в облако, можно в Ollama.
  • Офлайн. Самолёт, дача, командировка с плохим интернетом. Локальная модель просто работает.
  • Без оплаты за токен. Если генеришь миллион саммари в день — облако разорит. Локально — фикс на электричество.
  • Гарантированная скорость. API облака может тормозить из-за нагрузки. Локально — стабильные t/s.
  • Скрытые промпты. Хочешь подвести модель под продакт, где сами промпты — IP — локально они не уходят в логи провайдера.
  • Эксперименты. Когда отлаживаешь pipeline и делаешь тысячи вызовов — отлично гонять на локалке.

Шаг 8. Подключаем Ollama к существующим инструментам

OpenAI-совместимый эндпоинт

Ollama умеет говорить «как OpenAI» на localhost:11434/v1. Это значит, что любой клиент, поддерживающий OpenAI API, можно перенаправить в локалку — поменяв только base URL.

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"   # любая строка
)

resp = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "Привет"}]
)
print(resp.choices[0].message.content)

Так заменяется backend в десятках open-source проектов (LibreChat, AnythingLLM, Continue для VS Code и т.д.) — пишешь свой base_url, и всё локально.

Continue в VS Code

Расширение Continue — это вкладка чата прямо в IDE. В настройках выбираешь Ollama, указываешь модель, и получаешь локального помощника по коду без подписки. Качество — на уровне GPT-3.5 (см. выше), но для рутинных рефакторингов и автодополнений нормально.

Локальный RAG без облака

В уроке 8 разбирался RAG, который ходил в облако за эмбеддингами и за LLM. Полностью локальный аналог:

  • Эмбеддинги: ollama pull nomic-embed-text, далее POST /api/embeddings.
  • Векторное хранилище: chromadb или faiss — оба ставятся через pip, работают локально.
  • Генерация ответа: тот же llama3.1:8b через /api/chat.

Получается RAG, который вообще никуда наружу не ходит. Идеально для тех самых NDA-документов.

Шаг 9. Кастомизация модели через Modelfile

Ollama позволяет делать «свою» модель с предзаданным системным промптом и параметрами — это аналог GPTs.

Файл Modelfile:

FROM llama3.1:8b

PARAMETER temperature 0.3
PARAMETER num_ctx 8192

SYSTEM """
Ты — критичный код-ревьюер. Отвечай только на русском.
Никаких преамбул вроде "Конечно, я готов помочь".
Сразу указывай на 1-3 главных проблемы кода. Без воды.
"""

Создание и использование:

ollama create code-critic -f Modelfile
ollama run code-critic
>>> вставь код для ревью

Можно держать пачку таких — для перевода, для рерайтинга, для саммари — и переключаться одной командой.

Расширения

  • Ollama как backend для голосового агента из p11: заменяешь Anthropic SDK на ollama.chat() — получаешь полностью офлайн ассистента.
  • Самостоятельный JSON-output: у Ollama есть параметр "format": "json" — модель форсированно выдаёт валидный JSON. Полезно для пайплайнов.
  • Доступ с другого устройства: измени переменную OLLAMA_HOST=0.0.0.0:11434 — и ноут становится LLM-сервером для всей домашней сети. Только осторожнее с firewall — без аутентификации.
  • Локальный CodeLlama для VS Code: Continue + codellama:7b-instruct = автодополнение, не уходящее в облако.
  • GUI: Open WebUI: docker-контейнер с ChatGPT-подобным интерфейсом поверх Ollama. Несколько пользователей, история, RAG из коробки.
  • Дообучение под себя: через unsloth и LoRA можно тюнить локальные модели под свои данные на одной 24GB видеокарте. Это уже отдельная история, но дверь открыта.

Подводные камни

  • Не дотягивает до фронтиров. Локальные 7-8B не заменят Claude Sonnet или GPT-4. Для сложного reasoning — облако.
  • Контекстное окно меньше. По умолчанию у llama3.1 — 8k токенов (хотя теоретически поддерживает 128k). Чтобы расширить — PARAMETER num_ctx 32768 в Modelfile, и потребление RAM растёт квадратично.
  • Греет ноут. Большая модель на полную грузит CPU/GPU. На MacBook Air ощутимо тёплый корпус и вентилятор (которого там, формально, нет). Заметно ест батарею.
  • Качество русского. Llama 3.1 знает русский, но иногда мешает с английским в одном предложении. Qwen2.5 русский знает увереннее.
  • Первый вызов медленный. Модель грузится в память ~3-10 сек. После — быстро. Через 5 минут idle — выгружается, придётся грузить снова. Лечится OLLAMA_KEEP_ALIVE=24h.
  • Структурированный output. Модели меньше 30B плохо держат JSON-schema. Если нужен жёсткий формат — облако или хитрая постобработка.
  • Тулинг отстаёт. Tool use в локальных моделях работает заметно хуже Claude. Если строишь агента с десятком инструментов — облако пока надёжнее.

Что в итоге

На руках:

  1. Рабочий локальный LLM-сервер с REST API.
  2. Опыт замеров: ясно, что 7B модель на M-серии — это рабочий инструмент, а не игрушка.
  3. Способ перенаправить любой OpenAI-совместимый клиент на локалку одной строкой.
  4. Понимание, где локальные модели сильны (приватность, оффлайн, объём), а где — нет (фронтир-задачи, длинный контекст, надёжный JSON).
  5. Modelfile-ы для тонкой настройки моделей под свои сценарии.

Реалистичный сценарий 2026 года — гибрид: 80% запросов закрываешь локально (быстро, бесплатно, приватно), а 20% сложного — отправляешь Claude. Эта связка экономит и деньги, и приватность, и нервы.

Совет: поставь Ollama прямо сейчас, даже если планируешь работать с облаком. Иметь под рукой бесплатную модель на 24 t/s — это базовая гигиена инженера 2026 года. Когда упрётся в лимиты облачного API в неудобный момент — поблагодаришь себя.
