Урок 26. Microsoft Agent Framework

Цель: понять, что такое Microsoft Agent Framework, чем он отличается от Semantic Kernel и AutoGen, и когда его стоит выбирать Время: ~55 минут Источник: Microsoft Learn / agent-framework docs

Зачем тебе этот урок

В уроке 17 фреймворки Microsoft уместились в строку: «AutoGen / Agent Framework — multi-agent collaboration». Для обзора хватало, для выбора инструмента под энтерпрайз-задачу — нет.

Microsoft несколько лет держала два конкурирующих фреймворка для агентов. Осенью 2025 это закончилось: Agent Framework (MAF) объединил их в одну кодовую базу. Понимать, что стало с предшественниками, полезно даже вне стека Python/.NET/Azure — показательный кейс взросления экосистемы агентов.

1. Откуда взялась путаница с двумя фреймворками

До осени 2025 у Microsoft было два отдельных инструмента: Semantic Kernel — SDK для продакшена (плагины, память, единый интерфейс к LLM-провайдерам, интеграция с .NET), стабильный, но со скромными мульти-агентными возможностями; и AutoGen — исследовательский фреймворк, где несколько LLM-агентов общаются и проверяют результаты друг друга, гибкий, но слабее заточен под наблюдаемость и безопасность продакшена. Два SDK, две философии — непонятно, какая переживёт следующий год.

Agent Framework — не третий конкурент, а слияние: продакшен-инфраструктура Semantic Kernel плюс мульти-агентные паттерны AutoGen в одном SDK с единым API на Python и .NET.

2. Что такое Agent Framework на практике

Agent Framework — открытый фреймворк для AI-агентов и мульти-агентных систем. Три источника задают структуру: базовые блоки агента (модель, инструкции, инструменты, память — наследие Semantic Kernel), workflows (явные графы оркестрации — развитие идей AutoGen с детерминированным каркасом) и интеграция с открытыми стандартами (MCP, A2A, OpenTelemetry). Фреймворк cloud-agnostic и provider-agnostic: агент работает на Azure OpenAI, обычном OpenAI API или совместимом провайдере, модель не зашита в архитектуру. Писать можно локально, деплоить — куда угодно.

3. Базовые блоки: агент, threads, tools, middleware

Агент определяется провайдером модели, инструкциями и опционально именем — в мульти-агентных сценариях имя различает, кто что сказал. Threads хранят историю сообщений между пользователем и агентом или между агентами: тред создаётся заново под запуск либо сериализуется между сессиями — тот же принцип долговременной памяти, только со встроенной сериализацией.

Tools — функции с описанием и типизированными параметрами (проектирование — урок 19), прикрепляются при создании агента или передаются разово. Middleware — перехватчики между агентом и функцией либо моделью: логирование, авторизация, rate-limiting без изменения логики. Именно middleware делает агента наблюдаемым в продакшене.

4. Workflows и интеграция с экосистемой

Главное отличие от «просто дай двум агентам поговорить» — workflows: явные графы, где узлы — агенты или код, а рёбра — правила перехода сообщения от узла к узлу. Так решается проблема чистого AutoGen: без структуры поведение трудно предсказать и продебажить. Workflow превращает мульти-агентную систему в подобие конечного автомата.

Базовые паттерны оркестрации: sequential — по цепочке; concurrent — параллельно, с последующей сборкой результатов; handoff — передача задачи другому при смене специализации, как перевод звонка; group chat — общая беседа, порядок реплик управляется framework. Рёбра бывают прямыми, условными, switch-case, с разветвлением или сбором в одну точку.

Agent Framework опирается на открытые протоколы agentic-экосистемы: MCP — единый протокол для внешних инструментов и данных; A2A — обнаружение агентами друг друга и обмен задачами между фреймворками (оба подробно — урок 28); OpenTelemetry — стандарт наблюдаемости для трассировки вызовов и оркестрации; Azure AI Foundry — управляемый хостинг с ролевым доступом, не обязательный, но удобный для команд в Azure.

5. Agent Framework против LangGraph и CrewAI

Сильный выбор: команда живёт в экосистеме Microsoft/Azure или на .NET, нужна энтерпрайз-наблюдаемость из коробки, сценарий должен быть предсказуемым графом, важна provider-agnostic архитектура без привязки к облаку или модели.

Присмотрись к LangGraph или CrewAI, если стек уже на LangChain, нужен быстрый прототип за час (CrewAI — «опиши команду и запусти»), или важна зрелость экосистемы: Agent Framework анонсирован только осенью 2025, кейсов пока меньше. Правило прежнее: фреймворк выбирают под задачу, а не потому что «это делает Microsoft».

6. Простой пример: агент с инструментом

Концептуальный скелет на Python — не код для прода: фреймворк молодой, синтаксис API меняется, сверься с актуальными доками agent-framework перед использованием.

# Концептуальный пример — сверь синтаксис с текущими доками
from agent_framework.openai import OpenAIChatClient
from typing import Annotated
from pydantic import Field

def get_attractions(
    location: Annotated[str, Field(description="Город для поиска достопримечательностей")]
) -> str:
    """Вернуть топ достопримечательностей для города."""
    return f"Топ для {location}: набережная, старый город, музей."

chat_client = OpenAIChatClient(model_id="gpt-4o")

# Агент = провайдер + инструкции + инструменты + имя
travel_agent = chat_client.create_agent(
    instructions="Ты помогаешь находить интересные места в городах.",
    name="travel_agent",
    tools=[get_attractions],
)

async def main():
    result = await travel_agent.run("Что посмотреть в Стокгольме?")
    print(result.text)

# Тред — только если нужна история между сообщениями:
# thread = travel_agent.get_new_thread()

Инструмент — типизированная функция, агент — из трёх частей (модель, инструкции, инструменты), вызов — асинхронный run.

7. Миграция и выбор инструмента под задачу

Экстренно переписывать рабочий проект на Semantic Kernel или AutoGen не нужно — оба продолжают поддерживаться. Agent Framework — путь вперёд для новых проектов и для тех, кто упирается в старые ограничения: нехватку мульти-агентных паттернов в Semantic Kernel или продакшен-инфраструктуры в AutoGen. Для нового проекта в Azure/.NET-контексте логичнее стартовать сразу с MAF.

Глоссарий

Microsoft Agent Framework (MAF)

Открытый фреймворк Microsoft для AI-агентов, объединивший продакшен-инфраструктуру Semantic Kernel и мульти-агентные паттерны AutoGen. Анонсирован осенью 2025.

Thread (агентский)

Объект, хранящий историю диалога между пользователем и агентом или между агентами. Может быть временным или сериализован между сессиями.

Workflow

Явный граф из узлов (агентов или кода) и рёбер (правил передачи сообщений), задающий предсказуемую оркестрацию мульти-агентного процесса.

Executor

Узел workflow, принимающий сообщение и передающий результат дальше. Бывает AI-агентом или обычной функцией.

Handoff

Паттерн оркестрации: один агент передаёт задачу другому, когда нужна иная специализация.

Middleware (агентское)

Перехватчик между агентом и функцией либо агентом и моделью — для логирования и контроля без изменения логики агента.

Проверь себя

Из слияния каких двух фреймворков Microsoft возник Agent Framework?
Semantic Kernel (продакшен-инфраструктура) и AutoGen (мульти-агентные паттерны).

Чем workflow отличается от свободной переписки агентов друг с другом?
Workflow — явный граф с заранее известными узлами и рёбрами, переходы предсказуемы. Свободная переписка сложнее предсказать и продебажить.

Назови три базовых паттерна оркестрации workflows в Agent Framework.
Sequential, concurrent, handoff, group chat — любые три.

Какие два открытых протокола использует Agent Framework для внешних инструментов и общения между агентами?
MCP — для инструментов и данных, A2A — для общения между агентами.

Когда LangGraph или CrewAI предпочтительнее Agent Framework?
Когда стек уже на LangChain (LangGraph) или нужен быстрый декларативный прототип без явного графа (CrewAI).

Что должно остаться в голове

  1. Agent Framework — не третий конкурент Semantic Kernel и AutoGen, а их слияние в SDK.
  2. Semantic Kernel дал продакшен-инфраструктуру, AutoGen — мульти-агентные паттерны.
  3. Базовые блоки агента: провайдер модели, инструкции, tools, threads для состояния диалога.
  4. Middleware — перехватчики между агентом и функцией/моделью для логирования без изменения логики.
  5. Workflows превращают мульти-агентную систему в явный граф вместо непредсказуемой переписки.
  6. Базовые паттерны оркестрации: sequential, concurrent, handoff, group chat.
  7. Framework provider-agnostic и cloud-agnostic: модель и место деплоя не зашиты намертво.
  8. MCP подключает инструменты, A2A — общение между агентами, OpenTelemetry — наблюдаемость (урок 28).
  9. Фреймворк молодой — API меняется, сверяйся с доками перед реальным кодом.
  10. Semantic Kernel и AutoGen не требуют немедленной миграции — оба поддерживаются.
