MCP — Model Context Protocol

Цель: понять, что такое MCP и зачем он меняет правила игры с агентами Время: ~50 минут Источник: modelcontextprotocol.io, anthropic.com/news

Зачем тебе этот урок

В ноябре 2024 Anthropic анонсировал MCP — Model Context Protocol, и за полгода он стал чем-то вроде «USB-C для ИИ». Ты подключил MCP-сервер один раз — и любой ИИ-клиент с поддержкой MCP получает к нему доступ. Никаких отдельных интеграций для каждого агента.

Если раньше каждое ИИ-приложение строило свои конкретные коннекторы (агент к Slack, агент к Notion, агент к БД — разные коды), то с MCP интеграция пишется один раз. Это резко снижает порог входа и создаёт экосистему.

Сегодня MCP поддерживают: Claude Desktop, Cursor, Windsurf, Cline, Zed, Continue, и десятки других. Ты сейчас на 100% точно столкнёшься с MCP в работе с агентами в ближайший год.

1. Что такое MCP в одном предложении

MCP — это открытый протокол, который стандартизирует, как ИИ-приложения подключаются к внешним источникам данных и инструментам.

Аналогия:

  • До USB: у каждого устройства свой разъём. Принтер ↔ компьютер — свой кабель. Клавиатура — свой. Хочешь новое устройство — новый адаптер.
  • После USB: один разъём. Любое устройство, любой компьютер.

В мире ИИ-агентов:

  • До MCP: каждый агент имел свои самописные интеграции. Для Slack — одни. Для Postgres — другие. Для GitHub — третьи.
  • После MCP: один протокол. Любой клиент (Claude Desktop, Cursor, ваше приложение) → любой сервер (Slack, Postgres, GitHub).

2. Архитектура: серверы и клиенты

В MCP две роли.

MCP-сервер

Программа, которая что-то умеет делать и предоставляет это через MCP. Например:

  • Сервер файловой системы — позволяет читать/писать файлы.
  • Сервер GitHub — даёт доступ к репозиториям, issue, PR.
  • Сервер Postgres — выполняет SQL запросы.
  • Сервер Slack — отправляет сообщения, читает каналы.
  • Сервер Brave Search — веб-поиск.
  • Свой кастомный сервер — что угодно.

Серверы запускаются как отдельные процессы (или как HTTP-сервисы) и говорят с клиентом через JSON-RPC.

MCP-клиент

Это ИИ-приложение, которое подключает серверы и даёт их LLM как доступные инструменты. Примеры клиентов:

  • Claude Desktop — приложение Anthropic, поддерживает MCP из коробки.
  • Cursor / Windsurf — IDE с ИИ.
  • Continue, Cline, Zed — другие IDE-плагины.
  • Своё приложение на Anthropic SDK с MCP-библиотекой.

Как они общаются

┌─────────────┐  JSON-RPC   ┌─────────────┐
│   Клиент    │ ←─────────→ │   Сервер    │
│  (Claude    │             │  (filesystem│
│   Desktop)  │             │  / GitHub / │
│             │             │   etc)      │
└─────────────┘             └─────────────┘
       ↑
       │ запросы пользователя
       │
┌─────────────┐
│ Пользователь│
└─────────────┘

Транспорты:

  • stdio — сервер запускается как локальный процесс, общение через stdin/stdout. Самый частый вариант.
  • Streamable HTTP: для удалённых серверов. Старый транспорт HTTP+SSE устарел и в актуальной спецификации не описан.

3. Что MCP-сервер может предоставлять

Три вида «способностей»:

Tools (инструменты)

Похоже на function calling в обычной LLM API. Сервер объявляет: «у меня есть функция create_issue(repo, title, body)». Клиент даёт LLM возможность её вызвать. Когда LLM решает — вызов идёт к серверу, тот выполняет, возвращает результат.

Примеры:

  • read_file(path) — читает файл.
  • execute_sql(query) — выполняет SQL.
  • send_slack_message(channel, text) — пишет в Slack.

Resources (ресурсы)

Read-only данные, на которые LLM может ссылаться. Например:

  • Содержимое файла как ресурс.
  • Snapshot базы данных.
  • Лог недавних событий.

Отличие от tools: tools — это действия, resources — данные.

Prompts (промпты-шаблоны)

Сервер может предоставлять готовые шаблоны промптов, которые пользователь явно вызывает. Пример: GitHub-сервер даёт промпт «summarize_pr» — прокручивает весь PR и просит модель сделать summary.

На практике prompts используются меньше, чем tools и resources.

4. Реальные серверы — что доступно сейчас

В репозитории github.com/modelcontextprotocol/servers сейчас семь эталонных (reference) серверов. Остальные, включая github, postgres, sqlite, brave-search, slack, puppeteer, gdrive и sentry, перенесены в архив (servers-archived) и не поддерживаются. Готовые серверы от самих сервисов ищи в официальном реестре registry.modelcontextprotocol.io.

5. Подключение к Claude Desktop — за 5 минут

Самый простой способ попробовать MCP — Claude Desktop.

Шаг 1. Установить Claude Desktop

Скачай с claude.ai/download (Mac/Windows). Залогинься.

Шаг 2. Найти конфиг

На Mac:

~/Library/Application Support/Claude/claude_desktop_config.json

На Windows:

%APPDATA%\Claude\claude_desktop_config.json

Шаг 3. Добавить filesystem-сервер

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/yourusername/Documents"
      ]
    }
  }
}

Замени путь на свой. Этот сервер даст Claude доступ к указанной папке.

Шаг 4. Перезапусти Claude Desktop

В чате слева внизу должна появиться иконка молотка 🔨 — это значит MCP-инструменты подключились. Кликнув на неё, увидишь список доступных tools.

Шаг 5. Попробуй

Спроси Claude:

  • «Какие файлы есть в папке?»
  • «Прочитай мой todo.md и подскажи, с чего начать сегодня».
  • «Создай файл plan.md с планом на неделю».

Claude будет вызывать read_text_file, list_directory, write_file. Каждый вызов он спросит у тебя «можно?» — это safety-фича, не пропусти.

6. Подключение нескольких серверов одновременно

Можно подключать сколько угодно серверов:

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/Documents"]
    },
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..."
      }
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    },
    "memory": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"]
    }
  }
}

Получаешь Claude, который умеет:

  • Читать твои файлы.
  • Создавать issue в GitHub.
  • Загружать веб-страницы.
  • Помнить факты между сессиями.

7. Свой MCP-сервер за 30 минут

Anthropic предоставляет SDK для TypeScript и Python. Соберём минимальный сервер, который возвращает погоду (можно подменить на любую другую логику).

TypeScript

npm init -y
npm install @modelcontextprotocol/sdk zod

Файл weather-server.ts:

import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  { name: "weather-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

// Описание доступных tools
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [{
    name: "get_weather",
    description: "Получить текущую погоду в городе",
    inputSchema: {
      type: "object",
      properties: {
        city: { type: "string", description: "Название города" }
      },
      required: ["city"]
    }
  }]
}));

// Обработка вызовов
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "get_weather") {
    const city = request.params.arguments?.city as string;
    // тут была бы реальная API-погода
    const fakeData = { city, temp: 18, condition: "облачно" };
    return {
      content: [{
        type: "text",
        text: `В городе ${city}: ${fakeData.temp}°C, ${fakeData.condition}`
      }]
    };
  }
  throw new Error("Unknown tool");
});

const transport = new StdioServerTransport();
await server.connect(transport);
console.error("Weather server running on stdio");

Скомпилируй (tsc) и подключи к Claude Desktop:

{
  "mcpServers": {
    "weather": {
      "command": "node",
      "args": ["/path/to/weather-server.js"]
    }
  }
}

Перезапусти Claude Desktop. Теперь спроси «какая погода в Москве?» — Claude вызовет твой сервер.

Python

pip install mcp
from mcp.server import MCPServer

mcp = MCPServer("weather-server")

@mcp.tool()
def get_weather(city: str) -> str:
    """Получить погоду"""
    return f"В {city}: +18°C, облачно"

mcp.run()  # по умолчанию транспорт stdio

8. MCP vs Function Calling — в чём разница

На первый взгляд MCP похож на function calling из Урока 13. Но есть существенные отличия.

АспектFunction CallingMCP
Где определены функцииВ коде твоего приложенияВ отдельном MCP-сервере
ПереиспользованиеНужно копировать код в каждое приложениеОдин сервер — много клиентов
СтандартизацияКаждый делает по-своемуЕдиный протокол
ИзоляцияФункции в том же процессе что и LLM-логикаСервер — отдельный процесс с правами
Динамическая загрузкаНужно перезапускать приложениеМожно подключать/отключать без рестарта
БезопасностьПолагается на код приложенияОтдельный процесс, но не песочница: сервер работает с правами твоего пользователя

Function calling — для случаев «у меня одно приложение, я контролирую всё». MCP — когда «я хочу подключить много инструментов многим клиентам».

9. Тонкости и подводные камни

Безопасность

MCP-серверы могут читать твой диск, дёргать API, отправлять сообщения. Все они работают с правами твоего пользователя и видят твои секреты в env. Подключай только серверы, которым доверяешь.

Для filesystem-сервера — указывай конкретные папки, не корень. Для github — давай токен с минимальными правами.

Производительность

Каждый MCP-сервер запускается в отдельном процессе (для stdio). При старте Claude Desktop запускает их все. Если у тебя 10 серверов — 10 процессов в фоне.

Дебаггинг

Если сервер падает — Claude Desktop напишет в логе «Failed to connect to ». Логи на Mac:

~/Library/Logs/Claude/mcp.log
~/Library/Logs/Claude/mcp-server-XXX.log

Версионирование

Серверы развиваются. Если обновился MCP-протокол, старый сервер может не работать. Закрепляй версию: @modelcontextprotocol/server-filesystem@2026.8.31 (номер возьми из npm) и обновляй осознанно.

Не все клиенты одинаково умеют

  • Claude Desktop — полная поддержка tools, resources, prompts.
  • Cursor — поддерживает tools, resources частично.
  • Continue — постепенно догоняет.

10. Глоссарий

  • MCP (Model Context Protocol): открытый протокол, созданный Anthropic (с декабря 2025 развивается в Agentic AI Foundation при Linux Foundation), для подключения LLM к данным/инструментам.
  • MCP-сервер — программа, предоставляющая tools/resources через MCP.
  • MCP-клиент — приложение, использующее MCP-серверы.
  • Tools — функции, которые LLM может вызывать через сервер.
  • Resources — read-only данные с сервера.
  • Prompts — шаблоны промптов от сервера.
  • JSON-RPC — формат сообщений между клиентом и сервером.
  • stdio transport — сервер как локальный процесс, общение через stdin/stdout.
  • Streamable HTTP transport: транспорт для удалённых серверов (заменил устаревший HTTP+SSE).
  • Capabilities — что сервер умеет (tools / resources / prompts).

11. Практика (60 минут)

Упражнение 1. Filesystem-сервер (15 минут)

  1. Установи Claude Desktop.
  2. Открой claude_desktop_config.json, добавь filesystem-сервер с путём к одной из своих папок.
  3. Перезапусти Claude Desktop.
  4. Кликни на иконку 🔨 в чате — увидишь список tools (read_text_file, list_directory, write_file и др.).
  5. Попроси Claude рассказать, какие файлы у тебя есть, и предложить идеи структуры.

Упражнение 2. GitHub-сервер (15 минут)

  1. На GitHub: Settings → Developer Settings → Personal Access Tokens → создай токен с правом repo.
  2. Добавь github-сервер в конфиг с этим токеном.
  3. Перезапусти Claude Desktop.
  4. Попроси: «покажи мои последние 5 issue в репо X», «создай issue про баг Y».

Упражнение 3. Memory-сервер (15 минут)

  1. Добавь memory-сервер в конфиг.
  2. Расскажи Claude факты о себе: «я работаю над курсом по ИИ», «мой основной проект — TG-бот для саммари».
  3. В новой сессии спроси «над чем я сейчас работаю?» — должен помнить.

Упражнение 4. Свой сервер (30 минут — для разработчиков)

  1. Реализуй weather-сервер (или любой другой) на TypeScript / Python из урока.
  2. Подключи к Claude Desktop.
  3. Используй в чате.

12. Проверь себя

1. MCP в одном предложении?
Открытый протокол для подключения ИИ-приложений к внешним данным и инструментам стандартным способом.

2. Кто такие сервер и клиент в MCP?
Сервер — программа, предоставляющая tools/resources. Клиент — ИИ-приложение, использующее их (Claude Desktop, Cursor).

3. Tools vs resources?
Tools — действия (функции, которые LLM может вызвать). Resources — read-only данные.

4. Как добавить сервер в Claude Desktop?
Отредактировать claude_desktop_config.json, добавить запись в mcpServers, перезапустить Claude Desktop.

5. Чем MCP лучше function calling?
Один сервер — много клиентов. Стандартизация. Изоляция в отдельном процессе (но это не песочница: сервер работает с твоими правами).

6. Главные риски безопасности?
Серверы работают с правами пользователя. Подключай только доверенные. Минимизируй scope (конкретные папки, токены с минимальными правами).

7. Какой transport использовать?
stdio для локальных серверов, Streamable HTTP для удалённых (старый HTTP+SSE устарел).

8. Где смотреть логи если сервер упал?
Mac: ~/Library/Logs/Claude/mcp.log и mcp-server-XXX.log.

9. Как написать свой сервер?
TypeScript SDK @modelcontextprotocol/sdk или Python mcp. Объявить tools через ListToolsRequestSchema, обрабатывать вызовы через CallToolRequestSchema.

10. Где найти готовые серверы?
github.com/modelcontextprotocol/servers (официальные) и pulsemcp.com (community-каталог 1000+ серверов).

13. Что должно остаться в голове

  1. MCP — это «USB-C для ИИ»: один протокол → много клиентов и серверов.
  2. Сервер = программа с tools/resources. Клиент = ИИ-приложение.
  3. Claude Desktop поддерживает MCP из коробки — самый простой вход.
  4. Каталог серверов: эталонные filesystem, git, memory, fetch и тысячи серверов от сервисов в официальном реестре MCP.
  5. Свой сервер пишется за 30 минут на TS/Python.
  6. Безопасность критична: серверы работают с правами пользователя.
  7. MCP — это будущее агентских инструментов; в 2026 это станет стандартом для ИИ-IDE и десктоп-агентов.
