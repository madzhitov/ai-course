Computer Use — Claude управляет компьютером

Цель: понять Computer Use — что это, когда полезно, как использовать Время: ~50 минут Источник: docs.claude.com/computer-use, anthropic.com/news

Зачем тебе этот урок

В октябре 2024 Anthropic выпустил Computer Use — возможность Claude видеть экран компьютера и управлять им мышкой и клавиатурой. К началу 2026 эта возможность стала стабильной, и теперь её используют в продакшене — для автоматизации, тестирования, помощи пользователям.

Для русскоязычной индустрии это пока почти не освоено. На английском — десятки use-case'ов, на русском — единицы. Если хочешь делать ИИ-автоматизацию работы (а это огромный рынок), MCP (предыдущий урок) и Computer Use (этот) — твои базовые инструменты.

1. Что такое Computer Use

Это API-фича Claude (не доступная пока в claude.ai как фича для пользователя), которая даёт модели три инструмента:

  1. computer — делать скриншоты, двигать мышь, кликать, набирать текст.
  2. bash — выполнять команды в shell.
  3. text_editor — читать и редактировать файлы напрямую.

В цикле:

Запрос пользователя
     ↓
Claude делает screenshot
     ↓
Видит экран → решает что делать
     ↓
Вызывает action: «click(345, 200)» или «type("hello")»
     ↓
Действие выполняется на машине
     ↓
Claude делает новый screenshot
     ↓
... повторяется пока задача не выполнена

Это и есть «агент общего назначения для компьютера». В отличие от агентов с узкими tools (как в уроках 16-19 из главного пути), Computer Use может работать в любом приложении — браузер, Excel, Photoshop, твой кастомный софт.

2. Реальные use-case'ы

Автоматизация рутинных задач

  • «Каждый понедельник зайди в админку, скачай отчёт за прошлую неделю, открой Excel, сделай pivot-таблицу, отправь в Slack».
  • «Проверь все мои чаты в Telegram, сделай summary за день».
  • «Зайди в кабинет банка, скачай выписку, импортируй в Notion».

QA-тестирование

  • «Прокликай весь user-flow регистрации, протестируй edge cases».
  • «Зайди на лендинг, сделай скрин, проверь что всё на месте».

Заполнение форм

  • «Возьми этот PDF договор, заполни на сайте контрагента форму с нужными полями».
  • «Заполни анкеты для подачи в визовые центры по списку клиентов».

Извлечение данных из старых систем

  • Legacy ERP без API? Computer Use может работать с UI напрямую.

Работа с приложениями без API

  • Photoshop, Figma, Excel — агент может делать действия в GUI.

Пользовательский ассистент

  • «Покажи как настроить VPN на этом маке» — агент берёт мышь, открывает System Preferences, показывает.

3. Архитектура: как это работает технически

Computer Use — это не магия. Это просто API loop:

# Псевдокод
def agent_loop(task):
    messages = [{"role": "user", "content": task}]
    while True:
        response = anthropic.messages.create(
            model="claude-sonnet-4-5",
            tools=[
                {"type": "computer_20250124", "name": "computer", ...},
                {"type": "bash_20250124", "name": "bash"},
                {"type": "text_editor_20250124", "name": "text_editor"}
            ],
            messages=messages,
            betas=["computer-use-2025-01-24"]
        )

        if response.stop_reason == "end_turn":
            return  # задача готова

        for block in response.content:
            if block.type == "tool_use":
                result = execute_tool(block.name, block.input)
                messages.append({...})  # добавить результат в контекст

Каждое действие — отдельный API-запрос. Claude видит скриншот (как картинку в multimodal-входе), решает действие, ты выполняешь его на реальной/виртуальной машине, шлёшь результат назад.

4. Безопасность — это критично

Computer Use может удалить файлы, отправить деньги, опубликовать в соцсети. Поэтому Anthropic не рекомендует запускать на твоей основной машине.

Стандартный подход:

  1. Виртуальная машина или Docker-контейнер — изолированная среда.
  2. Ограниченный доступ к интернету (whitelist).
  3. Никаких сохранённых паролей в браузере.
  4. Логирование всех действий.
  5. Human-in-the-loop для критических операций (перевод денег, удаление, отправка email).

Anthropic выпустил reference implementation — Docker-образ с Ubuntu, Firefox, libreoffice, всё в песочнице.

5. Запуск demo за 15 минут

Шаг 1. Установи Docker

Скачай Docker Desktop с docker.com.

Шаг 2. Получи API-ключ

На console.anthropic.com создай ключ.

Шаг 3. Запусти reference image

export ANTHROPIC_API_KEY=sk-ant-...

docker run \
  -e ANTHROPIC_API_KEY=$ANTHROPIC_API_KEY \
  -v $HOME/.anthropic:/home/computeruse/.anthropic \
  -p 5900:5900 \
  -p 8501:8501 \
  -p 6080:6080 \
  -p 8080:8080 \
  -it ghcr.io/anthropics/anthropic-quickstarts:computer-use-demo-latest

Шаг 4. Открой браузер

Перейди на http://localhost:8080. Слева — чат с Claude. Справа — рабочий стол виртуальной машины.

Шаг 5. Попробуй задачи

  • «Открой Firefox и зайди на github.com».
  • «Скачай файл отчёта с этого URL и открой в LibreOffice».
  • «Открой текстовый редактор и напиши хайку».
  • «Открой калькулятор и посчитай 137 * 89».

Будешь видеть как Claude делает скриншоты, кликает, набирает текст — в реальном времени.

6. Стоимость и скорость

Скорость

  • Каждое действие = 5–30 секунд (скриншот + раздумье + выполнение).
  • Простая задача (открыть приложение, сделать одно действие): 30–60 сек.
  • Средняя (заполнить форму): 2–5 минут.
  • Сложная (multi-step с проверками): 10–30 минут.

Это медленно. Если задачу можно решить через API напрямую — делай через API.

Стоимость

  • Каждый screenshot — это картинка ~1.6 мегапикселя на вход.
  • Стоимость одного шага: ~$0.005–0.05 в зависимости от длины контекста.
  • Часовая работа агента: $1–5.

Не дёшево, но в сотни раз дешевле живого человека за рутинную работу.

7. Computer Use vs другие подходы

ПодходКогда братьНе подходит когда
Прямой APIУ сервиса есть APIAPI нет или ограничен

Computer Use — это «швейцарский нож». Хорош в общем случае, плох в узких.

8. Лимиты и ошибки

Что ломается

  • Капчи — Claude по политике не должен их обходить.
  • 2FA — нужен human-in-the-loop.
  • Динамические UI — если кнопка двигается между скриншотами, Claude может промахнуться.
  • Длинные задачи — на 50+ шагах вероятность ошибки растёт.

Best practices

  1. Делай задачи маленькими. «Скачай отчёт + сделай pivot + отправь» → три отдельных задачи.
  2. Проверяй промежуточные результаты. После каждого блока — пусть агент описывает что сделал.
  3. Логируй всё. Скриншоты + действия + reasoning — все сохраняй.
  4. Human-in-the-loop для критичных шагов: «прежде чем нажать "Отправить" — спроси меня».
  5. Не давай доступ к продакшену. Только staging / sandbox.

9. Что дальше: тренды 2026

Computer Use бурно развивается. На горизонте:

  • Прямой системный доступ вместо скриншотов (через accessibility API) — быстрее и точнее.
  • Локальные модели для Computer Use — не нужен облачный API, всё на своём GPU.
  • Долгие задачи на часы и дни — с памятью между перезапусками.
  • Multi-agent оркестрация — несколько Computer Use агентов работают параллельно над разными частями задачи.

OpenAI и Google запустили свои аналоги (Operator, Gemini Computer Use) — индустрия движется туда. Я бы поставил на 2026: Computer Use агенты будут стандартом для рутинной работы.

10. Глоссарий

  • Computer Use — возможность Claude управлять компьютером через скриншоты + действия.
  • computer tool — встроенный API-tool для скриншотов, мыши, клавиатуры.
  • bash tool — встроенный для shell-команд.
  • text_editor tool — для прямого редактирования файлов.
  • Agent loop — цикл «скриншот → действие → новый скриншот».
  • Reference implementation — Docker-образ Anthropic с готовой средой для Computer Use.
  • Human-in-the-loop — обязательное согласование критичных действий.
  • Operator — аналог Computer Use от OpenAI.

  2. Запусти reference image из секции 5.

Упражнение 2. Простая задача (15 минут)

В demo попроси: «открой LibreOffice Calc, создай таблицу из 10 строк с расходами на еду по дням недели, в последней строке — сумма».

Заметь:

  • Сколько времени заняло?
  • Где Claude промахнулся / переделывал?

Упражнение 3. Реальный кейс (15 минут)

Подумай о своей задаче, которую ты делаешь регулярно вручную и которая может быть автоматизирована Computer Use. Опиши:

  • Шаги (что делаешь руками)
  • Какие приложения используешь
  • Сколько времени занимает
  • Что может пойти не так если автоматизировать

Если хочешь — попробуй автоматизировать в demo (для безопасности — без реальных аккаунтов, на тестовых данных).

Упражнение 4. Сравнение (15 минут)

Выбери web-задачу. Реализуй её двумя способами:

  1. Через Playwright (если знаешь).
  2. Через Computer Use.

Сравни: время разработки, стоимость, скорость выполнения, надёжность. Ответ обычно: Playwright побеждает в скорости и надёжности, Computer Use — в гибкости и скорости разработки.

12. Проверь себя

1. Какие три инструмента доступны Claude в Computer Use?
computer (скриншот, мышь, клавиатура), bash (shell), text_editor (файлы).

2. Как работает agent loop?
Claude делает скриншот → решает действие → выполняет → новый скриншот → повторяет пока задача не готова.

3. Где запускать Computer Use?
В виртуальной машине / Docker-контейнере. Никогда не на основной машине.

4. Когда не использовать Computer Use?
Когда есть API (быстрее, дешевле, надёжнее). Когда задача скорость-критичная. Когда нужна 100% надёжность.

5. Сколько примерно стоит час работы агента?
$1–5 в зависимости от сложности и количества скриншотов.

6. Главные риски?
Удаление файлов, отправка денег, публикация в соцсети, обход паролей. Митигация: sandbox + ограниченный доступ + HITL для критичного.

7. Что делать с капчами?
По политике Anthropic, Claude не должен их обходить. Нужен HITL — спросить пользователя.

8. Computer Use vs Playwright?
Playwright — быстрее, надёжнее, дешевле для повторяющихся web-задач. Computer Use — гибче, работает где угодно (не только в браузере), быстрее в разработке.

9. Что делать чтобы повысить надёжность?
Маленькие задачи, проверка промежуточных результатов, логирование, HITL на критичных шагах, не давать доступ к продакшену.

10. Будущее Computer Use?
Прямой системный доступ через accessibility API (не скриншоты), локальные модели, долгие задачи с памятью, multi-agent оркестрация. На 2026 — это становится стандартом для рутинной автоматизации.

13. Что должно остаться в голове

  1. Computer Use = «универсальный пользователь компьютера» — может работать в любом приложении.
  2. Цикл: скриншот → действие → скриншот.
  3. Sandbox обязателен. Не запускать на основной машине.
  4. Медленно и дорого по сравнению с прямым API. Использовать когда API нет или нужна гибкость.
  5. Reference image — Docker от Anthropic, можно попробовать за 15 минут.
  6. HITL для критичных шагов — обязателен.
  7. 2026 — год Computer Use. Конкуренты: Operator (OpenAI), Gemini Computer Use (Google).
📌 Закрепление: Computer Use радикально расширяет, что может ИИ. Но он не заменяет узкоспециализированные инструменты — он их дополняет. Думай о Computer Use как о «когда у меня нет API и нет времени писать интеграцию».
