13. Деплой — как код становится сайтом

Что такое деплой

Деплой (deploy) — процесс публикации кода на сервер, чтобы сайт стал доступен по URL. Это последний шаг: написал код → задеплоил → пользователи видят.

Этапы деплоя

Код на твоём компьютере
    ↓ git push
GitHub (репозиторий)
    ↓ автоматический триггер
Vercel (CI/CD pipeline)
    ↓ npm install → npm run build → проверки
Продакшен (https://mysite.com)

CI/CD

CI (Continuous Integration) — автоматическая проверка кода при каждом push: тесты, линтинг, сборка. Если что-то сломалось — деплой не пройдёт.

CD (Continuous Deployment) — автоматический деплой после прохождения всех проверок. Push в main → через 30-60 секунд новая версия на сайте.

Preview Deployments

Vercel создаёт отдельный URL для каждой ветки и каждого pull request. Ты можешь запушить экспериментальную ветку, получить уникальный URL, показать клиенту для проверки и слить в main только когда всё ок.

Домены

Vercel даёт бесплатный домен (project.vercel.app). Для продакшена подключаешь свой: в DNS-настройках домена указываешь CNAME-запись на Vercel, в Vercel Dashboard добавляешь домен. SSL (HTTPS) настраивается автоматически.

Serverless vs Server

Serverless (Vercel, AWS Lambda) — код запускается по запросу. Нет постоянного сервера. Платишь за использование. Масштабируется автоматически. Идеально для сайтов и API.

Server (VPS, Dedicated) — постоянно работающий сервер. Нужен для WebSocket, фоновых задач, тяжёлых вычислений. Примеры: DigitalOcean, Hetzner.

Для большинства проектов serverless — оптимальный выбор.

🏋️ Практика

  1. Зарегистрируйся на vercel.com через GitHub
  2. Нажми «Add New Project» → импортируй свой репозиторий с GitHub
  3. Vercel сам определит, что это Next.js, и настроит всё
  4. Через минуту сайт будет доступен по URL вида my-app.vercel.app
  5. Измени что-нибудь в коде, сделай git push — через 30 секунд изменения на сайте

14. Мобильная разработка — отличия от веба

Три подхода

Нативные приложения — Swift (iOS) / Kotlin (Android), отдельный код для каждой платформы. Максимальная производительность, полный доступ к функциям устройства. Но два разных проекта.

Кроссплатформенные — один код для обеих платформ. - React Native / Expo — JavaScript/React. Если знаешь React для веба — порог входа минимальный. Expo упрощает сборку и публикацию. - Flutter — Dart (язык от Google), быстрый рендеринг, красивые UI.

PWA (Progressive Web App) — веб-сайт, который работает как приложение. Добавляется на домашний экран, работает офлайн. Проще всего, но ограниченный доступ к устройству.

React Native + Expo

Один JavaScript/TypeScript код
    ↓
Expo компилирует
    ↓
├── iOS-приложение (App Store)
└── Android-приложение (Google Play)

Различия от веба: - Вместо HTML-тегов (<div>, <p>) — React Native компоненты (<View>, <Text>) - Вместо CSS — StyleSheet или NativeWind (Tailwind для мобайла) - Навигация через React Navigation, а не URL-роутинг - Доступ к камере, микрофону, уведомлениям через Expo SDK

// Веб (React)
<div className="p-4 bg-white rounded">
  <p className="text-lg font-bold">Привет</p>
</div>

// Мобайл (React Native)
<View style={styles.card}>
  <Text style={styles.title}>Привет</Text>
</View>

Supabase на мобайле

Тот же @supabase/supabase-js работает и в React Native. Один бэкенд для сайта и мобильного приложения — база, авторизация, хранилище файлов.

🏋️ Практика

  1. Установи Expo: npx create-expo-app my-mobile-app
  2. Запусти: cd my-mobile-app && npx expo start
  3. Скачай Expo Go на телефон, отсканируй QR-код — увидишь приложение на своём устройстве
  4. Измени текст в app/(tabs)/index.tsx, сохрани — приложение обновится мгновенно

15. Полная архитектура — как всё связано

Типовой интернет-магазин

                    Пользователь
                         │
                    Браузер / Телефон
                         │
                ┌────────┴────────┐
                │   Vercel CDN    │  ← Глобальная сеть серверов
                └────────┬────────┘
                         │
              ┌──────────┴──────────┐
              │    Next.js (App)    │  ← Работает на Node.js
              │                     │
              │  React + Tailwind   │  ← Интерфейс
              │  API Routes         │  ← Серверная логика
              └──────────┬──────────┘
                         │
        ┌───────┬────────┼────────┬──────────┐
        │       │        │        │          │
   Supabase   CMS     Платежи  Telegram   Email
   (данные)  (контент) (оплата)  (бот)    (письма)

Supabase — хранит пользователей, товары, заказы; авторизация; файлы (фотографии); realtime-обновления.

CMS (Sanity, Strapi, Contentful) — редактор контента. Маркетолог пишет статьи через удобный интерфейс, Next.js подтягивает контент на сайт.

Платежи (Stripe, ЮKassa) — обработка оплаты. Webhook уведомляет сервер об успешной оплате.

Telegram-бот — уведомления менеджерам о новых заказах.

Email (Resend, SendGrid) — подтверждение заказа, восстановление пароля.
