Урок 6. Первое приложение — генерация текста через API

Цель: перейти от чата в браузере к программному вызову LLM Время: ~60 минут Источник: generative-ai-for-beginners/06

Зачем тебе этот урок

До сих пор ты работал с LLM через ChatGPT/Claude.ai — браузерные интерфейсы. Это нормально для разовых задач. Но как только ты хочешь:

  • Автоматизировать что-то (обработать 1000 писем, не открывая чат каждый раз).
  • Встроить ИИ в свой продукт (приложение, бот, скрипт).
  • Контролировать temperature, формат, retries программно.
  • Логировать запросы и ответы.
  • Платить только за то, что используешь — без подписки на $20/мес.

...тебе нужен API. Это база всего, что мы будем делать дальше — чат-боты, поиск, RAG, агенты. К концу урока у тебя будет рабочий Python-скрипт, который вызывает GPT и возвращает ответ. Это последний барьер между «юзером ИИ» и «тем, кто строит на ИИ».

1. Что такое API и зачем он

API в одном предложении

API (Application Programming Interface) — это интерфейс для общения программ между собой. Веб-API — это URL, на который ты шлёшь HTTP-запрос с данными, и получаешь ответ.

В случае LLM-провайдеров: ты отправляешь POST-запрос на endpoint вида https://api.openai.com/v1/chat/completions с JSON-телом, описывающим что ты хочешь. В ответ получаешь JSON с сгенерированным текстом.

API ключ

Чтобы провайдер знал, кто ты и кому списывать деньги, к каждому запросу прикладывается API ключ — длинная строка вида sk-...XYZ. Это твой пароль и счётчик в одном.

⚠️ Правила безопасности с ключом:
  • Никогда не пиши ключ прямо в коде.
  • Никогда не коммить в git (даже в private репо).
  • Никогда не показывай в скринах, видео, демо.
  • Никогда не используй в JavaScript-коде на фронтенде (любой пользователь увидит в DevTools).
  • Всегда храни в переменных окружения (.env файл) или в secret manager.
  • Сразу отзови ключ, если случайно засветил.

Реальный кейс 2023: разработчики случайно закоммитили ключи на GitHub, боты-сканеры тут же нашли их и начали гонять GPT-4 на полную, у людей утром были счета на $5000–$50000. OpenAI стал автоматически отзывать такие ключи, но не всегда успевает.

2. Получение ключа

OpenAI

  1. Зайди на platform.openai.com (это не тот же что chat.openai.com — отдельный аккаунт для разработчиков).
  2. Зарегистрируйся или войди.
  3. Пополни баланс: Billing → Add to credit balance. Минимум $5. Этого хватит на тысячи запросов.
  4. Создай ключ: API keys → Create new secret key. Скопируй и сохрани в надёжное место — показывается один раз.
  5. Поставь ограничения: Settings → Limits → Monthly budget. Например, $20/мес. Это страховка от случайного слива денег.

Anthropic (Claude)

  1. Зайди на console.anthropic.com.
  2. Аналогично: пополни баланс, создай ключ, поставь лимиты.

Альтернативы для России

  • Yandex GPT — yandex.cloud, оплата с российской карты.
  • GigaChat от Сбера — sberbank.ru, требуется регистрация юрлица для API.
  • OpenRouter — единый API к десяткам моделей, может работать через российские карты.
  • Прокси-провайдеры (есть, но не все легальны — на свой риск).

4. Первый запрос

Минимальный пример

import os
from dotenv import load_dotenv
from openai import OpenAI

# Загружаем .env в переменные окружения
load_dotenv()

# Создаём клиента (он сам найдёт OPENAI_API_KEY в env)
client = OpenAI()

# Делаем запрос
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Ты помощник по русскому языку."},
        {"role": "user", "content": "Объясни, что такое деепричастие, в одном абзаце."}
    ],
    temperature=0.3,
    max_tokens=300
)

# Извлекаем текст
print(response.choices[0].message.content)

Сохрани как hello_ai.py, запусти:

python hello_ai.py

Получишь сгенерированный ответ в терминале. Поздравляю — ты только что вызвал LLM из своего кода.

5. Анатомия запроса

Разберём каждое поле:

model

Имя модели. Точные строки:

  • gpt-4o, gpt-4o-mini — флагман и эконом.
  • gpt-4-turbo, gpt-3.5-turbo — старые но дешёвые.
  • o1-preview, o1-mini — reasoning.

Anthropic: claude-3-5-sonnet-20241022, claude-3-haiku-20240307 и т.д. (точные имена меняются — смотри документацию).

messages

Массив сообщений диалога. Поддерживаемые роли:

  • system — инструкция модели на весь диалог.
  • user — сообщение пользователя.
  • assistant — предыдущий ответ модели (для контекста).
  • tool — результат вызова инструмента (для function calling — урок 13).

temperature

0–2. См. урок 4. Для фактических задач — 0–0.3, для креатива — 0.7–1.

max_tokens

Максимум токенов в ответе. Жёсткий лимит, остановит даже на полуслове. Считай чуть больше, чем нужно.

Другие полезные параметры

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[...],
    temperature=0.3,
    max_tokens=300,
    top_p=1.0,
    frequency_penalty=0.0,   # -2 до 2, штраф за повторы
    presence_penalty=0.0,    # -2 до 2, штраф за упоминание темы
    stop=["\n\n"],         # остановиться при появлении строки
    response_format={"type": "json_object"},  # только валидный JSON
    seed=42,                 # для воспроизводимости
    n=1                      # сколько вариантов сгенерировать
)

6. Анатомия ответа

Объект response содержит много данных:

{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1715000000,
  "model": "gpt-4o-mini-2024-07-18",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Деепричастие — это особая форма глагола..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 42,
    "completion_tokens": 187,
    "total_tokens": 229
  }
}

Что брать в работу

  • response.choices[0].message.content — сам сгенерированный текст.
  • response.choices[0].finish_reason:
    • stop — модель закончила нормально.
    • length — упёрлась в max_tokens, ответ обрезан.
    • content_filter — заблокировано фильтром.
    • tool_calls — попросила вызвать инструмент.
  • response.usage — твой счётчик стоимости.

7. Подсчёт стоимости

Цена считается отдельно для input и output по таблице из урока 2.

Расчёт на лету

def calculate_cost(usage, model="gpt-4o-mini"):
    prices = {
        "gpt-4o-mini":   {"input": 0.15, "output": 0.60},
        "gpt-4o":        {"input": 2.50, "output": 10.00},
        "o1-mini":       {"input": 3.00, "output": 12.00},
    }
    p = prices.get(model, prices["gpt-4o-mini"])
    cost = (
        usage.prompt_tokens * p["input"] +
        usage.completion_tokens * p["output"]
    ) / 1_000_000
    return cost

response = client.chat.completions.create(...)
print(f"Стоимость: ${calculate_cost(response.usage):.6f}")

Реальные цифры

Запрос с промптом 100 токенов и ответом 200 токенов на gpt-4o-mini:

  • Input: 100 × $0.15 / 1M = $0.000015
  • Output: 200 × $0.60 / 1M = $0.00012
  • Итого: ~$0.000135 = ~0.013 цента

1000 таких запросов = ~$0.14. Очень дёшево.

8. Streaming — печать ответа по словам

По умолчанию ответ возвращается целиком в конце генерации. Для чат-интерфейса это плохо — ждёшь 5 секунд белого экрана. Решение — streaming:

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Напиши хайку про код"}],
    stream=True  # ← включаем streaming
)

for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)
print()  # перенос строки в конце

Текст печатается по мере генерации — пользователь видит, что что-то происходит.

9. Обработка ошибок

В реальной жизни запросы падают. Сети нет, лимит исчерпан, модель перегружена, ключ невалидный. Обрабатывай:

from openai import OpenAI, OpenAIError, RateLimitError, APIConnectionError
import time

def safe_chat(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-4o-mini",
                messages=messages,
                timeout=30
            )
        except RateLimitError:
            wait = 2 ** attempt  # exponential backoff: 1, 2, 4 сек
            print(f"Rate limit, ждём {wait} сек...")
            time.sleep(wait)
        except APIConnectionError:
            print("Сеть упала, retry...")
            time.sleep(1)
        except OpenAIError as e:
            print(f"Ошибка OpenAI: {e}")
            return None
    return None

Принципы:

  • Retry на временные ошибки (rate limit, network) с экспоненциальной задержкой.
  • Не retry на logical ошибки (невалидный запрос, кончились деньги).
  • Timeout на каждый запрос — иначе один зависший вызов положит весь скрипт.
  • Логирование — пиши в файл, что и когда вызывалось.

10. Полный пример: генератор постов

import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI()

def generate_post(topic: str, tone: str = "neutral", count: int = 3) -> list[str]:
    """Генерирует N вариантов поста на заданную тему."""

    system = f"""Ты автор LinkedIn-постов в B2B-сегменте.
Тон: {tone}.
Длина: 500-700 знаков.
Формат: одна фраза-крючок, основная мысль, вывод.
Без хэштегов и эмодзи."""

    posts = []
    for i in range(count):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": system},
                {"role": "user", "content": f"Напиши пост на тему: {topic}"}
            ],
            temperature=0.9,  # высокая для разнообразия
            max_tokens=400
        )
        posts.append(response.choices[0].message.content.strip())

    return posts

if __name__ == "__main__":
    topic = input("Тема поста: ")
    tone = input("Тон (нейтральный / прямой / провокационный): ") or "нейтральный"

    posts = generate_post(topic, tone, count=3)

    for i, post in enumerate(posts, 1):
        print(f"\n--- Вариант {i} ---")
        print(post)

Запуск:

$ python generator.py
Тема поста: ошибки наставничества молодых разработчиков
Тон: прямой

--- Вариант 1 ---
[три варианта поста]

11. Тонкости и подводные камни

Кеширование запросов

Если ты делаешь много одинаковых запросов в разработке — кешируй ответы локально:

import hashlib, json, os

CACHE_DIR = ".llm_cache"
os.makedirs(CACHE_DIR, exist_ok=True)

def cached_chat(messages, model="gpt-4o-mini", **kwargs):
    key_str = json.dumps({"m": model, "msg": messages, **kwargs}, sort_keys=True)
    key = hashlib.md5(key_str.encode()).hexdigest()
    path = f"{CACHE_DIR}/{key}.json"

    if os.path.exists(path):
        with open(path) as f:
            return json.load(f)["content"]

    response = client.chat.completions.create(model=model, messages=messages, **kwargs)
    content = response.choices[0].message.content

    with open(path, "w") as f:
        json.dump({"content": content}, f)
    return content

Сэкономит и время, и деньги при разработке.

Логирование

Сохраняй все запросы и ответы — пригодится для дебага и анализа.

import logging
logging.basicConfig(filename="llm.log", level=logging.INFO)

logging.info(f"Request: {messages}")
logging.info(f"Response: {response.choices[0].message.content}")
logging.info(f"Tokens: {response.usage}")

Параллельные запросы

Если нужно обработать 100 промптов — не делай их последовательно. Используй asyncio или concurrent.futures:

from concurrent.futures import ThreadPoolExecutor

def process_one(text):
    return client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": text}]
    ).choices[0].message.content

with ThreadPoolExecutor(max_workers=10) as ex:
    results = list(ex.map(process_one, texts))

10x ускорение. Но осторожно с rate limits — у OpenAI обычно 5000 req/min.

Структурированный вывод (JSON mode)

Если ответ должен парситься программно:

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Отвечай только валидным JSON."},
        {"role": "user", "content": "Извлеки имя, возраст и роль из: 'Анна, 28 лет, фронтенд'"}
    ],
    response_format={"type": "json_object"},
    temperature=0
)

import json
data = json.loads(response.choices[0].message.content)
# data = {"name": "Анна", "age": 28, "role": "фронтенд"}

12. Глоссарий

  • API — Application Programming Interface, способ программного вызова сервиса.
  • API key — секретный токен для авторизации запросов.
  • Endpoint — конкретный URL API.
  • SDK — Software Development Kit, библиотека-обёртка над API.
  • .env — файл для секретов, не идёт в git.
  • Rate limit — лимит запросов в единицу времени.
  • Streaming — постепенный вывод ответа по мере генерации.
  • finish_reason — причина остановки генерации (stop / length / etc).
  • usage — статистика токенов в ответе.
  • Exponential backoff — растущая задержка между retries.
  • JSON mode — гарантированно валидный JSON в ответе.

14. Проверь себя

1. Где хранить API ключ?
В файле .env, который добавлен в .gitignore. Никогда не в коде, никогда в git, никогда на фронтенде.

2. Что в JSON-ответе содержит сам сгенерированный текст?
response.choices[0].message.content

3. finish_reason: "length" — что значит?
Модель упёрлась в max_tokens и ответ обрезан. Нужно увеличить лимит или сделать новый запрос с продолжением.

4. Как посчитать стоимость одного запроса?
Берём из response.usage поля prompt_tokens и completion_tokens, умножаем на цены модели за миллион токенов и делим на миллион.

5. Что такое rate limit?
Лимит запросов в единицу времени (обычно в минуту). У OpenAI бывает 5000 RPM для платных аккаунтов. При превышении — RateLimitError, нужно подождать.

6. Зачем streaming?
Чтобы пользователь видел текст по мере генерации, а не белый экран 5 секунд. Резко улучшает воспринимаемую скорость.

7. Что добавить в .gitignore при работе с API?
Минимум: .env, venv/, __pycache__/, *.pyc, .llm_cache/ (если используешь кеш).

8. Как сделать гарантированно валидный JSON в ответе?
response_format={"type": "json_object"} + явная инструкция в system prompt + temperature=0 + try/except json.loads на стороне кода.

9. Когда retry, а когда нет?
Retry на временные ошибки: rate limit, network timeout, 5xx. Не retry на логические: невалидный запрос (400), кончились деньги (402), неверный ключ (401).

10. Чем отличаются frequency_penalty и presence_penalty?
frequency_penalty штрафует за частоту повторений конкретного токена. presence_penalty — за сам факт упоминания темы. Оба от -2 до 2, по умолчанию 0.

15. Что должно остаться в голове

  1. API + ключ + .env — фундамент любого ИИ-приложения.
  2. Структура запроса: model + messages + параметры.
  3. Структура ответа: choices[0].message.content + usage.
  4. Считай стоимость в каждом скрипте — поможет не сжечь деньги случайно.
  5. Streaming для интерактивных интерфейсов.
  6. Retry с backoff на временные ошибки.
  7. JSON mode для парсинга ответов программно.
  8. Никогда не клади ключ в код / git / фронтенд.
