Урок 7. Чат-приложение с памятью

Цель: сделать чат-бот, который помнит контекст разговора Время: ~60 минут Источник: generative-ai-for-beginners/07

Зачем тебе этот урок

Скрипт из урока 6 — однократный вызов: «введи промпт → получи ответ → конец». Реальные ИИ-продукты — почти все чат-формата: бот помнит контекст, продолжает беседу, держит роль. ChatGPT, Claude.ai, корпоративные ассистенты — все построены на одной механике, которую ты освоишь сегодня.

Отдельная сложность — память. LLM stateless: ничего не помнит между вызовами. «Память» — это то, что ты сам подсовываешь в контекст. Этот урок — про разные стратегии, как это делать правильно.

1. Stateless API и иллюзия памяти

Вспомни урок 1: каждый запрос к LLM API независим. Модель не «помнит» прошлые сообщения. Если ты хочешь, чтобы она знала контекст — ты должен отправить весь контекст в массиве messages:

# Запрос 1
client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Меня зовут Иван"}]
)
# → "Приятно познакомиться, Иван!"

# Запрос 2 — модель ничего не помнит
client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Как меня зовут?"}]
)
# → "Я не знаю, как вас зовут"

# Запрос 2 правильный — передаём всю историю
client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Меня зовут Иван"},
        {"role": "assistant", "content": "Приятно познакомиться, Иван!"},
        {"role": "user", "content": "Как меня зовут?"}
    ]
)
# → "Вас зовут Иван."

Вся «память» чат-бота — это твой массив сообщений, который ты ведёшь на стороне приложения и каждый раз отправляешь целиком.

2. Простейший чат-бот

import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI()

class ChatBot:
    def __init__(self, system_prompt: str, model: str = "gpt-4o-mini"):
        self.model = model
        self.history = [{"role": "system", "content": system_prompt}]

    def chat(self, user_msg: str) -> str:
        self.history.append({"role": "user", "content": user_msg})

        response = client.chat.completions.create(
            model=self.model,
            messages=self.history,
            temperature=0.7
        )
        reply = response.choices[0].message.content

        # сохраняем ответ в историю — он понадобится в следующих запросах
        self.history.append({"role": "assistant", "content": reply})
        return reply


# Используем
bot = ChatBot("Ты помощник по фитнесу. Кратко, по делу. Спрашивай уточняющие вопросы.")

while True:
    msg = input("Ты: ")
    if msg.lower() in ("exit", "quit", "выход"):
        break
    print("Бот:", bot.chat(msg))

Запускаешь — получаешь рабочий чат с ботом, который помнит весь разговор.

3. Проблема: контекст растёт

На 5-м сообщении массив history содержит 11 элементов (1 system + 10 messages), на 50-м — уже 101. Что в этом плохого:

  1. Цена. Каждый запрос отправляет всю историю. На 50-м сообщении ты платишь за токены 50 предыдущих + новый.
  2. Лимит. Контекстное окно ограничено (128k у GPT-4o). На очень длинных диалогах упрёшься.
  3. Качество. «Lost in the middle» — модель хуже помнит середину длинного контекста.
  4. Latency. Большой контекст обрабатывается дольше.

Решение — стратегии управления историей.

4. Стратегия 1: Sliding Window (скользящее окно)

Идея

Хранить только последние N сообщений. Старое — забывать.

class ChatBot:
    def __init__(self, system_prompt: str, max_history: int = 10):
        self.system_prompt = system_prompt
        self.max_history = max_history
        self.history = []

    def chat(self, user_msg: str) -> str:
        self.history.append({"role": "user", "content": user_msg})

        # отрезаем sliding window
        recent = self.history[-self.max_history:]
        messages = [{"role": "system", "content": self.system_prompt}] + recent

        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            temperature=0.7
        )
        reply = response.choices[0].message.content
        self.history.append({"role": "assistant", "content": reply})
        return reply

Когда подходит

  • Короткие фокусные диалоги (helpdesk, FAQ).
  • Не нужно помнить детали из начала.

Минусы

  • Бот «забывает» имя, контекст, ранние решения.
  • Резкая граница: 10 сообщений помнит, 11-е — забыл начисто.

5. Стратегия 2: Summary (саммари)

Идея

Когда история становится длинной, просим модель суммировать старую часть и заменяем её на summary.

class ChatBot:
    def __init__(self, system_prompt: str, summarize_every: int = 20):
        self.system_prompt = system_prompt
        self.summarize_every = summarize_every
        self.summary = ""
        self.recent = []  # последние сообщения, не сжатые

    def _summarize_old(self, old_messages):
        text = "\n".join([f"{m['role']}: {m['content']}" for m in old_messages])
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "Сожми диалог в краткое саммари ключевых фактов и решений (1 абзац)."},
                {"role": "user", "content": text}
            ]
        )
        return response.choices[0].message.content

    def chat(self, user_msg: str) -> str:
        self.recent.append({"role": "user", "content": user_msg})

        # компонуем системный промпт с актуальным саммари
        sys = self.system_prompt
        if self.summary:
            sys += f"\n\nКонтекст из предыдущей части диалога: {self.summary}"

        messages = [{"role": "system", "content": sys}] + self.recent

        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            temperature=0.7
        )
        reply = response.choices[0].message.content
        self.recent.append({"role": "assistant", "content": reply})

        # если накопилось много — сжимаем старое
        if len(self.recent) >= self.summarize_every:
            old = self.recent[:-10]   # сжимаем всё кроме последних 10
            self.recent = self.recent[-10:]
            new_summary = self._summarize_old(old)
            self.summary = (
                f"{self.summary}\n{new_summary}" if self.summary else new_summary
            )

        return reply

Когда подходит

  • Длинные обучающие диалоги (репетитор, ментор).
  • Долгое сопровождение клиента.
  • Когда важны ранние решения и факты.

Минусы

  • Дополнительные вызовы LLM (1 саммари = 1 запрос).
  • Информация теряется при сжатии.
  • Качество саммари влияет на всё дальнейшее.

6. Стратегия 3: Hierarchical (иерархическая)

Гибрид:

  • Последние 5–10 сообщений — целиком.
  • Чуть более старые — суммаризированы по 5 в одну запись.
  • Древние — глобальное саммари «о чём вообще шёл разговор».

Сложнее в реализации, но даёт хороший баланс «точность недавнего» + «общее понимание».

7. Стратегия 4: Vector memory (векторная память)

Самая мощная: храним все сообщения в векторной БД, при каждом запросе достаём релевантные текущему вопросу. Это уже RAG — будем разбирать в уроке 14. Тут просто упомянем для полноты.

8. Подсчёт токенов и обрезка

Чтобы понять, когда применять стратегию — нужно считать токены. Есть библиотека tiktoken (для OpenAI):

pip install tiktoken
import tiktoken

def count_tokens(messages, model="gpt-4o-mini"):
    enc = tiktoken.encoding_for_model(model)
    total = 0
    for m in messages:
        # в реальности OpenAI добавляет ~4 токена на сообщение для метаданных
        total += len(enc.encode(m["content"])) + 4
    return total + 2  # +2 для приоритета

Перед запросом проверяй и обрезай:

MAX_CONTEXT = 100_000  # с запасом

while count_tokens(messages) > MAX_CONTEXT:
    # удаляем второе сообщение (после system)
    messages.pop(1)

9. System prompt — главный инструмент устойчивости

System prompt задаётся один раз и держит характер бота на весь диалог. Сюда кладём:

  • Роль и сфера.
  • Стиль общения (тон, длина ответов).
  • Правила поведения.
  • Что делать в граничных случаях.
  • Что НЕ делать.

Пример хорошего system prompt

SYSTEM = """Ты — Никита, виртуальный помощник студии веб-разработки.
Твоя задача — помочь клиенту понять, подойдём ли мы под его проект.

Стиль:
- Прямо и по делу, без воды.
- Короткие ответы (2-4 предложения).
- На "ты", дружелюбно, но профессионально.

Что ты делаешь:
- Спрашиваешь про проект клиента: цели, бюджет, сроки.
- Объясняешь наши услуги (разработка сайтов, мобильные приложения).
- Если клиент готов — предлагаешь созвон с менеджером.

Что ты НЕ делаешь:
- Не называешь конкретные цены — это решает менеджер на созвоне.
- Не обещаешь сроков.
- Не отвечаешь на вопросы вне темы (политика, погода и т.п.) —
  вежливо возвращаешь к теме проекта.

Если не знаешь ответа на технический вопрос — скажи прямо
"уточню у команды и вернусь" и предложи оставить контакты."""

10. Persistence — сохранение между сессиями

Если бот должен помнить тебя между запусками — сохраняй историю в файл:

import json
from pathlib import Path

class ChatBot:
    def __init__(self, system_prompt, history_file="chat_history.json"):
        self.system_prompt = system_prompt
        self.history_file = Path(history_file)
        self.history = self._load()

    def _load(self):
        if self.history_file.exists():
            with open(self.history_file) as f:
                return json.load(f)
        return []

    def _save(self):
        with open(self.history_file, "w") as f:
            json.dump(self.history, f, ensure_ascii=False, indent=2)

    def chat(self, user_msg):
        self.history.append({"role": "user", "content": user_msg})
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "system", "content": self.system_prompt}] + self.history[-20:],
            temperature=0.7
        )
        reply = response.choices[0].message.content
        self.history.append({"role": "assistant", "content": reply})
        self._save()
        return reply

Для production — лучше БД (SQLite, Postgres), не JSON-файл.

11. UI на Streamlit за 30 строк

Терминал — для отладки. Для пользователей — нужен веб-UI. Streamlit делает это за 5 минут.

pip install streamlit

Файл chat_app.py:

import streamlit as st
from openai import OpenAI
client = OpenAI()

st.title("🤖 Мой AI помощник")

if "messages" not in st.session_state:
    st.session_state.messages = []

SYSTEM = "Ты дружелюбный помощник."

# показать историю
for msg in st.session_state.messages:
    with st.chat_message(msg["role"]):
        st.markdown(msg["content"])

# поле ввода
if user_msg := st.chat_input("Напиши что-нибудь..."):
    st.session_state.messages.append({"role": "user", "content": user_msg})
    with st.chat_message("user"):
        st.markdown(user_msg)

    # генерируем ответ со streaming
    with st.chat_message("assistant"):
        stream = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "system", "content": SYSTEM}] +
                     st.session_state.messages,
            stream=True
        )
        reply = st.write_stream(stream)
    st.session_state.messages.append({"role": "assistant", "content": reply})

Запуск:

streamlit run chat_app.py

Откроется браузер. Получаешь полноценный чат-интерфейс с:

  • Аватарами user / assistant.
  • Историей в session.
  • Streaming ответа.
  • Адаптивным дизайном.

12. Тонкости

Не клади всё в system prompt

Если у тебя 50-страничный мануал, и ты пихаешь его в system prompt каждого запроса — ты платишь за него каждый раз. Лучше — RAG (урок 14): подгружать релевантные куски только когда нужно.

System prompt и role-confusion

Иногда модель «забывает» о своей роли в долгих диалогах, если пользователь активно её сбивает. Лекарство: повторять ключевые правила либо в начале, либо в конце контекста (помним про lost in the middle).

Идентификация пользователя

В мульти-пользовательском боте нельзя смешивать историю разных людей. Каждому юзеру — отдельный history, ключуй по user_id.

Цензура и фильтры

Если бот публичный — добавь Moderation API:

moderation = client.moderations.create(input=user_msg)
if moderation.results[0].flagged:
    return "Я не могу ответить на это."

Streaming + не блокирующий UI

В Streamlit это делается одной строкой st.write_stream(stream). В голом Flask/FastAPI — через Server-Sent Events.

13. Глоссарий

  • Conversation history — массив сообщений диалога.
  • Sliding window — окно последних N сообщений.
  • Summary memory — сжатие старого в короткое описание.
  • Hierarchical memory — многоуровневая память.
  • Vector memory — поиск релевантного по эмбеддингам (RAG).
  • tiktoken — библиотека OpenAI для подсчёта токенов.
  • Context overflow — переполнение контекстного окна.
  • Persistence — сохранение состояния между сессиями.
  • Streamlit — Python-фреймворк для быстрых веб-приложений.
  • Moderation API — фильтр вредного контента.

15. Проверь себя

1. Почему чат «помнит» если LLM stateless?
Приложение хранит историю на своей стороне и подставляет её в каждый запрос. Сама LLM ничего не помнит.

2. Что такое sliding window?
Стратегия памяти: храним только последние N сообщений, остальное выбрасываем.

3. Зачем считать токены?
Чтобы не упереться в лимит контекста и не платить за лишнее. Также — чтобы заранее обрезать историю.

4. Когда нужен summary вместо sliding window?
Когда важно помнить ранние решения/факты, но не каждое слово. Жертвуем точностью ради покрытия.

5. Что обязательно в system prompt?
Роль, стиль общения, что делать, чего не делать, что в граничных случаях.

6. У меня 100 пользователей бота. Что важно?
Хранить историю отдельно для каждого user_id, никогда не смешивать. Идентифицировать по сессии или auth.

7. Бот теряет роль на 30-м сообщении. Что делать?
(а) Проверить, не выпал ли system prompt из окна. (б) Дублировать ключевые правила в начале или конце контекста. (в) Использовать summary-стратегию, оставляя главное в саммари.

8. Streamlit vs голый Flask — что выбрать?
Streamlit — для быстрых прототипов и внутренних инструментов. 30 строк = рабочий чат. Flask/FastAPI — для production: контроль над HTTP, мульти-юзер, аутентификация.

9. Как сохранить историю на 1000 пользователей?
SQLite или Postgres, таблица (user_id, role, content, timestamp). JSON-файл подойдёт только для одного пользователя.

10. Как защитить чат от вредных запросов?
Moderation API на входе и/или выходе. Чёткий system prompt с явным «что не делать». Логирование и алерты на странные паттерны.

16. Что должно остаться в голове

  1. Память = массив messages[], который ведёшь сам.
  2. Sliding window — простой и часто достаточный вариант.
  3. Summary — для долгих диалогов с важной историей.
  4. Vector memory (RAG) — самая мощная, в уроке 14.
  5. System prompt — главный инструмент устойчивости характера.
  6. Persistence между сессиями — JSON для прототипа, БД для prod.
  7. Streamlit — UI за 30 строк.
  8. Moderation API для публичных ботов.
