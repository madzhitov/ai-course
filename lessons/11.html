Урок 11. UX для ИИ-приложений

Цель: понять, почему ChatGPT-стиль UX работает, и применить эти паттерны к своему AI-приложению Время: ~45 минут Источник: generative-ai-for-beginners/12 + собственная практика

Зачем тебе этот урок

Качество AI-приложения на 50% — это качество модели. На 50% — это UX. Плохой UX сводит на нет даже GPT-4.

AI-приложения отличаются от обычных тремя ключевыми вещами:

  • Долгий и непредсказуемый ответ (2–30 секунд, иногда больше).
  • Недетерминированный результат (один и тот же запрос — разные ответы).
  • Ошибки правдоподобные (галлюцинация выглядит как правильный ответ).

Это требует другого UX. Большинство паттернов уже изобретены в ChatGPT/Claude/Copilot — твоя задача знать их и применять.

1. Стриминг — главный паттерн

Никогда не показывай спиннер 15 секунд и потом весь ответ. Стримь токен за токеном. Это:

  • Делает приложение в 3 раза «быстрее» по ощущению, при той же фактической скорости.
  • Даёт пользователю возможность остановить генерацию, если ответ ушёл не туда (сэкономит токены).
  • Создаёт ощущение «думающего» собеседника, а не «работающей машины».

Все провайдеры (OpenAI, Anthropic, Google) поддерживают streaming в API. На стороне фронта — Server-Sent Events (SSE) или WebSocket. Если используешь Vercel AI SDK / Anthropic SDK — стриминг включается одной опцией.

2. Cancel — всегда

Кнопка «Stop». Обязательна. Это самая важная кнопка в AI-приложении после Send.

Почему: пользователь часто видит на первых словах, что модель уходит не туда. Без Stop он ждёт 20 секунд и потом перепишет промпт. Со Stop — отменяет за секунду, экономит токены и время.

3. Регенерация и сравнение вариантов

Regenerate — повторить запрос, получить другой ответ. ChatGPT, Claude — все умеют. В своём приложении: одна кнопка-завитушка. Технически — отправить тот же промпт с новым seed/случайностью.

Variations side-by-side. Полезно для генеративных задач (написание, картинки). Покажи 2–3 варианта рядом, пользователь выберет. Это меняет ментальную модель с «модель пытается угадать что я хочу» на «модель помогает мне выбрать».

4. Edit-and-resubmit вместо «отправь новое»

Когда промпт не сработал, пользователь обычно хочет чуть подправить, а не писать заново. ChatGPT даёт edit на каждом своём сообщении — это меняет всю динамику разговора.

Эта одна фича делает чат на 30% эффективнее.

5. Прозрачность: «что я могу / чего не могу»

AI-приложения часто страдают от «пустого input»: пользователь видит чат и не знает, что туда писать. Решения:

  • Примеры промптов при первом открытии (ChatGPT делает это: «Brainstorm names for...», «Suggest a recipe...»).
  • Slash-команды или кнопки быстрых действий — снижают barrier to entry.
  • Onboarding tour: 3 экрана с примерами.
  • Явное описание ограничений: «работаю с текстом, не вижу картинки», «знания до 2024», «не выхожу в интернет».

6. Источники и confidence — против галлюцинаций

Если приложение делает RAG (Урок 14) или работает с фактами:

  • Цитаты рядом с утверждениями. Perplexity делает [1], [2] — пользователь может проверить.
  • «Точно знаю / возможно / не уверен» — попроси модель явно ранжировать свою уверенность в системном промпте и покажи это в UI.
  • «Источник:» с гиперссылкой.
  • Когда модель не знает — пусть скажет «не знаю», а не придумывает. Это инструкция системного промпта.

7. Обработка ошибок

AI-вызов может упасть. Часто. Что бывает:

  • Rate limit (429) — слишком много запросов.
  • Context length exceeded — пользователь скормил 500-страничный PDF.
  • Content policy violation — модель отказывается.
  • Timeout — модель думает дольше 60 секунд.
  • API down — провайдер лежит.

Что делать:

  • Конкретные сообщения для каждого случая, а не «Something went wrong».
  • Кнопка «попробовать снова» с экспоненциальным бекоффом.
  • Сохраняй ввод пользователя. Никогда не теряй его промпт при ошибке.
  • Fallback на дешёвую/другую модель при rate-limit на дорогой.

8. Empty states

Каждое AI-приложение имеет «пустые» экраны: впервые открыли, нет истории, ничего не загружено. Это огромный шанс показать ценность.

Что должно быть в empty state:

  • Что приложение делает (одна строка).
  • 3–5 примеров реальных задач, на которые можно нажать.
  • Кнопка «Загрузить документ» / «Импортировать» — если применимо.

9. Микро-UX: что отличает топ-приложения

  • Indicator печатания — три точки, бегущий курсор, что-то живое.
  • Markdown в реальном времени — рендерь жирный/курсив/код пока идёт стрим.
  • Подсветка синтаксиса в коде — обязательно.
  • Кнопка «Copy» на блоках кода.
  • Кнопка «Share» / «Export PDF» для длинных диалогов.
  • Сохранение в localStorage или сервер — пользователи теряют диалог = катастрофа.
  • Темная тема — обязательна, юзеры часто работают вечером.
  • Keyboard shortcuts — Cmd+Enter для отправки, Cmd+K для поиска, ↑ для последнего промпта.

10. Анти-паттерны

🚩 Чего НЕ делать:
  • «Цикл барабана» на 30 секунд без какой-либо информации.
  • Скрытые галлюцинации — выдавать выдуманные факты как достоверные. Всегда указывай статус.
  • «Стерильный chat» без примеров и onboarding.
  • Отправка только по нажатию мыши — Enter должен работать.
  • Терять диалог при перезагрузке.
  • Молчаливая ошибка или generic «Something went wrong».
  • Бесконечные ответы без возможности остановить.
  • Сообщения 5000 символов сплошным куском — рендери markdown, разбивай на блоки.

11. Тонкости и подводные камни

  • Стриминг ломается на медленной сети. Тестируй на 3G.
  • Перевод стрима в markdown — в момент рендера буфер может быть незавершён («**жир» без закрытия). Используй проверенные парсеры (marked-streaming, react-markdown с потоковым режимом).
  • Cancel должен реально отменять backend-запрос, а не только UI. Иначе ты платишь за токены, которые не показал.
  • Сохранение в localStorage — лимит ~5MB. Длинные диалоги быстро упрутся.
  • Чувствительные данные — даже в локалшторадж не клади ключи API. Используй серверный прокси.

12. Глоссарий

Streaming

Постепенная отправка ответа токен за токеном через SSE/WebSocket вместо одного blocking-запроса.

Empty state

Состояние экрана, когда у пользователя ещё нет контента. Критичная точка для onboarding.

Optimistic UI

Сразу показываем сообщение пользователя в чате, не дожидаясь ответа сервера.

Citations

Ссылки на источники рядом с утверждениями. Главное оружие против галлюцинаций в UX.

13. Практика (45 минут)

  1. Возьми любое своё мини-AI-приложение (или используй пример из урока 7 — чат-бот).
  2. Добавь: streaming, кнопку Stop, кнопку Regenerate, сохранение истории в localStorage, базовые обработчики ошибок.
  3. Empty state: 3 примера-кнопки промптов на первом экране.
  4. Тёмная тема: переключатель.
  5. Дай попробовать другу. Запиши 3 вещи, которые он не понял — это твои UX-долги.

14. Проверь себя

1. Почему стриминг — главный UX-паттерн для AI?
Делает приложение «в 3 раза быстрее» по ощущению. Даёт возможность остановить плохой ответ. Создаёт ощущение собеседника.

2. Что должно быть в empty state AI-приложения?
Что приложение делает + 3–5 примеров промптов, на которые можно нажать.

3. Как UX борется с галлюцинациями?
Цитаты с источниками, явный уровень уверенности модели, «не знаю» вместо выдумки.

4. Что обязательно при ошибке API?
Не потерять промпт пользователя, показать конкретную причину, кнопку retry, fallback на другую модель если возможно.

5. Почему Edit-and-resubmit важнее Regenerate?
Пользователь обычно знает, как поправить промпт. Edit меняет «бросаем кубик заново» на «уточняем намерение».

15. Что должно остаться в голове

  1. Стриминг + Stop + Regenerate — три обязательные кнопки.
  2. Edit-and-resubmit умножает эффективность в разы.
  3. Empty state с примерами — твой главный onboarding.
  4. Цитаты и confidence-уровни — UX-броня против галлюцинаций.
  5. При ошибке: конкретный текст + сохранённый промпт + retry, никогда не «Something went wrong».
  6. Сохраняй историю. Тёмная тема. Keyboard shortcuts.
