Урок 39. Автоэнкодеры

Цель: понять обучение без учителя в нейросетях и идею латентного пространства Время: ~55 минут Источник: AI-For-Beginners + Goodfellow «Deep Learning» гл. 14

Зачем тебе этот урок

Все сети, которые ты обучал до сих пор, требовали разметки: вот картинка, вот правильный класс. Разметка — самое дорогое в машинном обучении. Автоэнкодер — первая архитектура в курсе, которой она не нужна.

К концу урока ты:

  • Поймёшь, как сеть учится, когда правильных ответов никто не давал.
  • Узнаешь про латентное пространство — идею, на которой держатся эмбеддинги (Урок 44) и генеративные модели (Урок 40).
  • Обучишь автоэнкодер на MNIST, почистишь картинки от шума, найдёшь аномалии и поймёшь, чем от всего этого отличается VAE.

1. Идея: цель обучения — сам вход

Обычная задача: дан x (картинка), предскажи y (класс) — нужна разметка. Задача автоэнкодера: дан x, предскажи x. Правильный ответ уже лежит на входе.

Звучит бессмысленно: сеть просто скопирует вход на выход и получит нулевой loss. Поэтому в середине делают узкое горлышко — слой заметно меньше входа. Скопировать через него не выйдет: 784 числа не пролезают в 16. Сеть вынуждена придумать, как ужать картинку так, чтобы её потом можно было восстановить. В этом «как ужать» и живёт всё интересное.

2. Три части: encoder, latent, decoder

x (784 числа) → encoder → z (16 чисел) → decoder → x_hat (784 числа)
                          bottleneck

loss = MSE(x_hat, x)

Encoder уменьшает размерность: 784 → 256 → 64 → 16. Latent (он же bottleneck, он же код) — тот самый узкий слой; вектор z и есть сжатое представление объекта. Decoder — зеркальная сеть: 16 → 64 → 256 → 784.

Loss — разница между входом и выходом: L = среднее((x_hat − x)²). Обучение — тот же цикл forward → loss → backward → update из Урока 34.

3. Почему узкое горлышко заставляет учить главное

Представь: нужно описать рукописную цифру по телефону, но разрешено сказать только 16 чисел. Яркость каждого пикселя не назовёшь — не хватит. Ты назовёшь саму цифру, наклон, толщину линии, ширину петли.

Ровно это делает сеть. Ограничение по объёму — принуждение к обобщению: она выбрасывает то, что восстанавливается по остальному, и оставляет факторы, которые различают объекты. Отсюда близость к сжатию: автоэнкодер — архиватор под конкретный тип данных, с потерями, которые выбирает сам.

Уберёшь ограничение — уберёшь смысл: слой размером с вход даст тождественную функцию и нулевое понимание данных. Узкое горлышко не деталь реализации, а вся конструкция.

4. Латентное пространство — главная мысль урока

После обучения encoder — это функция, сопоставляющая любому объекту точку в 16-мерном пространстве. Оно и называется латентным (скрытым).

  • Близкие точки — похожие объекты. Восстановить похожие картинки из далёких кодов дороже, поэтому сеть сама раскладывает похожее рядом.
  • Оси не случайны. Направления часто отвечают осмысленным факторам: наклон, толщина линии, ширина. Никто их не задавал — они выпали из данных.
  • Это компактное описание объекта. Вектор z можно подавать другим моделям вместо картинки: 16 чисел вместо 784.

Запомни схему: объект → вектор чисел → близость векторов означает похожесть объектов. В Уроке 44 встретишь её для слов, под именем эмбеддинга. В Уроке 40 из точки латентного пространства будут генерировать изображения.

5. Автоэнкодер против PCA

Снижать размерность умели и до нейросетей. PCA ищет направления наибольшего разброса и проецирует на них. Связь прямая: линейный автоэнкодер без активаций выучивает по сути то же подпространство, что и PCA. Выигрыш даёт только нелинейность.

PCAАвтоэнкодер
ПреобразованиеТолько линейноеЛюбое, какое выучит сеть
МногообразиеПлоскостьИзогнутая поверхность
ОсиУпорядочены по важностиРавноправны и перепутаны

Вывод: данные примерно на плоскости — бери PCA, он быстрее и понятнее. Структура изогнутая (а у картинок, звука и текста она такая) — автоэнкодер поймает то, что PCA размажет.

6. Автоэнкодер на PyTorch: полный код

MNIST, латентный вектор из 16 чисел, десять эпох. Опирается на всё из Урока 35.

import torch
import torch.nn as nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

device = "cuda" if torch.cuda.is_available() else "cpu"

train_ds = datasets.MNIST(root="./data", train=True, download=True,
                          transform=transforms.ToTensor())
train_dl = DataLoader(train_ds, batch_size=256, shuffle=True)


class Autoencoder(nn.Module):
    def __init__(self, latent_dim=16):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Flatten(),
            nn.Linear(28 * 28, 256), nn.ReLU(),
            nn.Linear(256, 64), nn.ReLU(),
            nn.Linear(64, latent_dim),              # bottleneck
        )
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 64), nn.ReLU(),
            nn.Linear(64, 256), nn.ReLU(),
            nn.Linear(256, 28 * 28), nn.Sigmoid(),  # пиксели в диапазоне [0, 1]
        )

    def forward(self, x):
        z = self.encoder(x)
        x_hat = self.decoder(z)
        return x_hat.view(-1, 1, 28, 28), z


model = Autoencoder().to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.MSELoss()

for epoch in range(10):
    total = 0.0
    for x, _ in train_dl:          # метки берём и сразу выбрасываем — они не нужны
        x = x.to(device)
        x_hat, _ = model(x)
        loss = loss_fn(x_hat, x)
        opt.zero_grad()
        loss.backward()
        opt.step()
        total += loss.item() * x.size(0)
    print(f"epoch {epoch}: loss {total / len(train_ds):.5f}")

Loss упадёт примерно до сотых. Прогони батч под torch.no_grad() и сохрани вход и x_hat рядом — увидишь узнаваемые цифры, но с мягкими краями. Почему мягкие — в разделе 11.

7. Шумоподавление: denoising autoencoder

Одна строчка меняет назначение модели: подаём зашумлённую картинку, а восстанавливать требуем чистую.

noise_level = 0.4
for x, _ in train_dl:
    x = x.to(device)
    x_noisy = (x + noise_level * torch.randn_like(x)).clamp(0, 1)
    x_hat, _ = model(x_noisy)      # вход — с шумом
    loss = loss_fn(x_hat, x)       # цель — чистая картинка
    opt.zero_grad(); loss.backward(); opt.step()

Теперь копировать вход на выход не просто трудно, а вредно: копия шума увеличит loss. Сеть обязана понять, как выглядит настоящая цифра, и достроить её. Побочный эффект — представление устойчивее, поэтому схему берут и когда шум чистить не надо.

8. Поиск аномалий по ошибке реконструкции

Обучаем только на нормальных данных. Сеть хорошо восстанавливает то, что видела, и плохо — всё остальное. Значит, большая ошибка реконструкции = объект не похож на норму.

@torch.no_grad()
def recon_error(batch):
    batch = batch.to(device)
    x_hat, _ = model(batch)
    return ((x_hat - batch) ** 2).flatten(1).mean(dim=1)   # ошибка на объект

fashion = datasets.FashionMNIST(root="./data", train=False, download=True,
                                transform=transforms.ToTensor())
fashion_dl = DataLoader(fashion, batch_size=256)

print("MNIST:  ", recon_error(next(iter(train_dl))[0]).mean().item())
print("Fashion:", recon_error(next(iter(fashion_dl))[0]).mean().item())  # выше

Порог берут по нормальной выборке: например, 99-й процентиль ошибки на обучающих данных, всё выше — на проверку. Так ищут брак на производстве, сбои по телеметрии, странные транзакции — везде, где аномалий мало и разметить нельзя.

9. Свёрточный автоэнкодер

Полносвязные слои для картинок расточительны — они игнорируют связь соседних пикселей. Свёртки из Урока 37 применимы напрямую: encoder собирают из nn.Conv2d со stride 2. Decoder делают из nn.ConvTranspose2d — это свёртка наоборот, она не сжимает, а увеличивает разрешение (подробно — Урок 42). Реконструкции выходят чётче, а параметров меньше.

10. Вариационный автоэнкодер (VAE) на пальцах

Соблазн очевидный: раз decoder превращает вектор в картинку, возьмём случайный вектор и получим новую цифру. Попробуй — получишь мусор.

Причина: обычный автоэнкодер кладёт объект в точку и ничем не обязан пространству между точками. Оно выходит дырявым — объекты сидят кучками, между кучками пустота, где decoder никогда не работал. VAE закрывает дыры двумя изменениями:

  1. Encoder выдаёт не точку, а облако: mu (центр) и sigma (разброс), а z берут случайной выборкой из облака. Объект каждый раз кодируется чуть иначе, и decoder вынужден работать не в точке, а в области вокруг неё.
  2. К loss добавляется штраф за расползание (KL-дивергенция), тянущий все облака к общему стандартному нормальному распределению. Итог: loss = реконструкция + вес · штраф.

Пространство заполняется плотно: случайный вектор из стандартного нормального распределения после decoder даёт осмысленную цифру, а прямая между кодами двух картинок — плавное превращение одной в другую. Цена: слагаемые тянут в разные стороны, усилишь штраф — пространство гладкое, но реконструкции размажутся.

Деталь, которую стоит знать по названию: случайность не пропускает градиент, поэтому семплирование пишут как z = mu + sigma · eps, где eps — шум извне. Это reparametrization trick.

11. Ограничения и почему картинки генерируют не этим

Реконструкции размытые, и это не баг настройки, а следствие loss. Если сеть не уверена, где проходит край штриха, выгоднее по MSE не выбрать вариант, а усреднить все правдоподобные. Среднее нескольких чётких картинок — размытая картинка.

GAN (Урок 40) обходит это, заменяя ручной loss на вторую сеть, которая учится отличать настоящее от сгенерированного: усреднять невыгодно, подделку сразу видно. Диффузионные модели идут дальше — пошагово убирают шум из чистого шума, и сегодня генераторы изображений построены на них. Но автоэнкодеры никуда не делись: снижение размерности, шумоподавление и поиск аномалий — их территория.

12. Тонкости и подводные камни

  • Слишком широкое горлышко = ничего не выучено. Loss прекрасный, представление бесполезное; реконструкции идеальны с первой эпохи — сужай bottleneck. Слишком узкое даёт обратное: два числа хороши для визуализации, но восстанавливают плохо. Разумно 16–32.
  • Активация выхода должна соответствовать данным. Пиксели от 0 до 1 → Sigmoid. Нормализованные со средним 0 → без активации вовсе. Забудешь — loss упрётся в плато.
  • Модель не переносится между датасетами. Обученный на MNIST автоэнкодер не сожмёт фотографии — он выучил структуру этих данных.
  • Для поиска аномалий обучай только на норме. Попали аномалии в выборку — сеть научится восстанавливать и их, и метод откажет ровно там, где нужен.

13. Глоссарий

Autoencoder

Сеть, восстанавливающая вход через узкое промежуточное представление. Без разметки.

Bottleneck

Узкий слой в середине. Ограничение размера заставляет сохранять только существенное.

Latent space

Пространство сжатых представлений. Близкие точки — похожие объекты.

Reconstruction error

Разница между входом и выходом: основа loss при обучении и признак аномалии при работе.

Denoising autoencoder

Вариант, где на вход подают зашумлённые данные, а целью остаётся чистый оригинал.

VAE

Вариационный автоэнкодер: encoder выдаёт распределение вместо точки, а штраф в loss делает пространство пригодным для генерации.

15. Проверь себя

1. Почему автоэнкодеру не нужна разметка?
Целью служит сам вход. Правильный ответ уже есть в данных, размечать нечего.

2. Что случится, если сделать латентный слой шире входа?
Сеть выучит тождественную функцию — скопирует вход на выход. Loss нулевой, представления нет.

3. Чем автоэнкодер лучше PCA?
Нелинейностью: PCA умеет только линейную проекцию, автоэнкодер с активациями ловит изогнутую структуру. Без активаций он сводится примерно к PCA.

4. Как искать аномалии автоэнкодером?
Обучить на нормальных данных и мерить ошибку реконструкции. Высокая ошибка = объект не похож на то, что сеть видела.

5. Почему обычный автоэнкодер плохо генерирует новое, а VAE лучше?
Обычный кодирует объект в точку, между точками остаются дыры, где decoder не обучался. VAE кодирует в распределение и штрафом стягивает их к общему стандартному — пространство плотное, случайный вектор даёт осмысленный результат.

16. Что должно остаться в голове

  1. Автоэнкодер восстанавливает вход из самого себя. Разметка не нужна — обучение без учителя.
  2. Три части: encoder → latent → decoder. Loss — расхождение входа и выхода, для картинок MSE.
  3. Узкое горлышко — весь смысл конструкции: оно принуждает выбрасывать несущественное.
  4. Латентное пространство: объект становится вектором, близкие векторы = похожие объекты. Та же идея вернётся в эмбеддингах (Урок 44).
  5. Линейный автоэнкодер примерно равен PCA. Всю прибавку даёт нелинейность.
  6. Шумоподавление — подаём грязное, требуем чистое; аномалии — учим на норме, ловим по высокой ошибке реконструкции.
  7. Для картинок encoder собирают из свёрток (Урок 37), decoder — из транспонированных.
  8. VAE = распределение вместо точки плюс штраф, стягивающий пространство. Генерация возможна ценой размытости; за резкими картинками — в Урок 40.
