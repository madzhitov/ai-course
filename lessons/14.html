Урок 14. RAG и векторные базы данных

Цель: понять как работает RAG и собрать поисковик по своим документам Время: ~55 минут Источник: generative-ai-for-beginners/15

Зачем тебе этот урок

Проблема, которую решает RAG, возникает у каждого кто строит AI-продукты:

  • Компания хочет чат-бота по своей документации — но документация закрытая, в LLM её нет.
  • Хочешь задавать вопросы своим заметкам — LLM их не видела при обучении.
  • Нужен помощник по актуальным ценам — у LLM данные устарели на год-два.
  • Бот даёт уверенные ответы но иногда явно врёт — нет способа проверить источник.

RAG (Retrieval-Augmented Generation) решает это: вместо того чтобы запихнуть всё в промпт, ты ищешь только нужное и даёшь LLM именно те фрагменты, которые релевантны вопросу.

1. Ментальная модель RAG

Аналогия: студент на устном экзамене. Обычный LLM — студент с феноменальной памятью, но не знает ничего про твою компанию. RAG — тот же студент, но с правом принести шпаргалки: перед ответом он листает нужные карточки и использует их в ответе.

RAG — конвейер из двух частей:

ЧАСТЬ 1: ИНДЕКСИРОВАНИЕ (один раз заранее)
Документы → Нарезка на чанки → Векторы → Сохранение в БД

ЧАСТЬ 2: РАБОТА С ПОЛЬЗОВАТЕЛЕМ (каждый запрос)
Вопрос → Вектор → Поиск похожих чанков → Отправка в LLM → Ответ

2. Embeddings — числовое представление смысла

Embedding — это способ превратить текст в список чисел так, чтобы похожие по смыслу тексты давали похожие числа.

Три фразы: «Кошка сидит на ковре», «Котёнок лежит на подстилке», «Процентная ставка ЦБ выросла». Первые две похожи по смыслу — их векторы будут близкими в пространстве, у третьей вектор далёкий.

Это лучше обычного поиска по ключевым словам: запрос «купить ноутбук» найдёт документ с фразой «приобрести лэптоп» — разные слова, но смысл близок. Можно спрашивать на русском, а находить документы на английском.

3. Чанкинг — нарезка документов

Почему нельзя один embedding для всего документа на 100 страниц?

  • Качество поиска падает. Один вектор — усреднение по всему содержимому. HR-раздел и финансовый смешаются.
  • Контекстное окно ограничено. Нашёл документ — но передать его целиком нельзя.
  • Стоимость. Чем больше токенов — тем дороже.

Стандарт: 500–600 слов с перекрытием 50–100 слов между чанками — чтобы не потерять смысл на границах. Лучше делить по абзацам или разделам, а не механически.

4. Векторная база данных

Обычные БД плохо подходят: они ищут по точным значениям, но не умеют «найти ближайших соседей в многомерном пространстве». Векторная БД — специализированное хранилище именно для такого поиска.

5. Как работает поиск: косинусное сходство

Косинусное сходство измеряет угол между двумя векторами:

  • = 1 → идентичны (угол 0°)
  • = 0 → не связаны (угол 90°)
  • = -1 → противоположны

Почему угол, а не расстояние? Длина вектора зависит от длины текста, угол — только от направления, то есть от смысла.

6. Полный RAG-конвейер

Этап 1: Индексирование

1. Загружаешь документы (PDF, .md, .txt)
2. Нарезаешь на чанки (~500 слов, с перекрытием)
3. Каждый чанк → embedding-модель → вектор
4. Сохраняешь в векторную БД: {вектор, текст, метаданные}

Этап 2: Ответ на вопрос

1. Пользователь задаёт вопрос
2. Вопрос → embedding → вектор вопроса
3. Ищем top-K (3–5) ближайших чанков
4. Составляем промпт: "Ответь используя только этот контекст: [чанки]"
5. LLM отвечает на основе контекста
6. Показываем пользователю источники

7. Важные нюансы

Одна и та же embedding-модель для индексации и поиска

Критично: если индексировал через text-embedding-ada-002, а вопросы переводишь через text-embedding-3-small — пространства несовместимы, поиск будет мусором.

8. Практика: RAG по своим документам

import os, json, chromadb
from openai import OpenAI

client = OpenAI(api_key="твой-ключ")
chroma = chromadb.Client()
collection = chroma.create_collection("docs", metadata={"hnsw:space": "cosine"})

def embed(text):
    return client.embeddings.create(
        model="text-embedding-3-small", input=text
    ).data[0].embedding

def index_file(filepath):
    with open(filepath, encoding="utf-8") as f:
        text = f.read()
    words = text.split()
    chunks = [" ".join(words[i:i+500]) for i in range(0, len(words), 450)]
    for i, chunk in enumerate(chunks):
        collection.add(
            ids=[f"{filepath}_{i}"],
            embeddings=[embed(chunk)],
            documents=[chunk],
            metadatas=[{"source": os.path.basename(filepath)}]
        )
    print(f"✅ {filepath}: {len(chunks)} чанков")

def ask(question, n=4):
    results = collection.query(query_embeddings=[embed(question)], n_results=n,
                               include=["documents", "metadatas", "distances"])
    chunks = [
        f"[{results['metadatas'][0][i]['source']}]
{results['documents'][0][i]}"
        for i in range(len(results["documents"][0]))
        if 1 - results["distances"][0][i] > 0.5
    ]
    if not chunks:
        return "❌ В документах нет информации по этому вопросу."
    
    context = "

---

".join(chunks)
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "Отвечай ТОЛЬКО на основе контекста. Если ответа нет — так и скажи."},
            {"role": "user", "content": f"Контекст:
{context}

Вопрос: {question}"}
        ],
        temperature=0.2
    )
    return response.choices[0].message.content

# Индексируем свои файлы
for f in ["notes.txt", "manual.txt"]:
    if os.path.exists(f):
        index_file(f)

# Интерактивный режим
while True:
    q = input("
Вопрос: ").strip()
    if q.lower() in ["выход", "exit"]: break
    print(ask(q))
