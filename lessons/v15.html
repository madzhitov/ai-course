Справочник: продвинутые темы

Цель: Отладка, тесты, кэш, мониторинг, SEO, безопасность. Что отличает прототип от продукта. Время: ~60 минут Главы гайда: 16–24

Зачем тебе этот урок

Этот урок — часть «Справочника по веб-разработке для не-разработчиков». Это не ката (как v1–v10), а карта территории. Здесь — концепты, которые AI генерирует в твоих проектах и которые тебе важно понимать, чтобы не быть слепым.

Без снобизма, без воды, с примерами из реальной жизни. После всех 5 модулей у тебя будет полная картина: от того, как браузер делает запрос, до того, как мониторить продакшен.

16. Отладка — как искать и чинить ошибки

Отладка (debugging) — это 50% времени разработчика. Код не работает — нужно понять почему.

Console.log — простейший инструмент

Вставляешь console.log() в код, чтобы увидеть, что происходит:

async function getProducts(categorySlug: string) {
  console.log('Запрос категории:', categorySlug);

  const { data, error } = await supabase
    .from('products')
    .select('*')
    .eq('category_slug', categorySlug);

  console.log('Данные:', data);
  console.log('Ошибка:', error);

  return data;
}

DevTools браузера

Cmd+Option+I (macOS) или F12 (Windows) в Chrome:

Console — логи, ошибки, предупреждения. Красные строки — ошибки. Кликни на ошибку — попадёшь в строку кода.

Network — все запросы страницы. Видишь: URL, метод, статус-код, время. Если 500 — проблема на сервере. Если 404 — неправильный URL.

Elements — живое дерево HTML/CSS. Можешь менять стили прямо в браузере.

Application — cookies, localStorage, сессии.

Чтение ошибок

Error: Cannot read properties of undefined (reading 'price')
    at ProductCard (src/components/ProductCard.tsx:12:24)

Читаем: файл ProductCard.tsx, строка 12. Пытаемся прочитать .price у undefined — значит, объект не передан или пустой.

Типичные ошибки

«Module not found» — пакет не установлен. Запусти npm install.

«Variable is undefined» — забыл добавить в .env.local или не перезапустил dev-сервер.

«CORS error» — фронтенд обращается к API на другом домене. Используй API Routes (один домен).

«Hydration mismatch» — сервер и клиент сгенерировали разный HTML. Обычно из-за window/document в серверном компоненте.

Отладка с AI

Самый эффективный подход: скопируй полный текст ошибки и вставь как промпт в AI. Не пересказывай ошибку своими словами — дай точный текст. AI видит паттерн и находит причину быстрее.

🏋️ Практика

  1. Открой DevTools → Console на любом сайте — посмотри, есть ли ошибки
  2. Специально сломай что-нибудь в своём проекте (удали import) — прочитай ошибку
  3. Скопируй ошибку в Claude или ChatGPT, попроси объяснить и починить

17. Тестирование — как проверять, что код работает

Тесты — это код, который проверяет другой код. Автоматически, при каждом изменении.

Три уровня

Юнит-тесты — проверяют одну функцию:

test('скидка 20% на 10000', () => {
  expect(calculateDiscount(10000, 20)).toBe(8000);
});

Интеграционные тесты — несколько частей вместе: API-роут + база данных.

test('GET /api/products возвращает товары', async () => {
  const response = await fetch('/api/products');
  expect(response.status).toBe(200);
  const data = await response.json();
  expect(data.length).toBeGreaterThan(0);
});

E2E тесты — весь сценарий от лица пользователя:

test('пользователь добавляет товар в корзину', async ({ page }) => {
  await page.goto('/catalog');
  await page.click('[data-testid="product-card"]');
  await page.click('button:has-text("В корзину")');
  await page.goto('/cart');
  await expect(page.locator('.cart-item')).toHaveCount(1);
});

Инструменты

  • Vitest — быстрый, современный, для юнит/интеграционных тестов
  • Playwright — E2E-тесты от Microsoft, в реальных браузерах
  • Cypress — E2E-тесты с красивым интерфейсом

Когда писать тесты

Золотое правило для вайб-кодинга: тестируй бизнес-логику (расчёты, валидации) и критические пути (авторизация, оплата). Не тестируй вёрстку — она меняется слишком часто.

🏋️ Практика

  1. Установи Vitest: npm install -D vitest
  2. Создай файл utils.test.ts, напиши простой тест для любой функции
  3. Запусти: npx vitest run
  4. Сломай функцию — увидишь, как тест ловит ошибку

18. Линтинг и форматирование — чистый код на автомате

ESLint — ловит ошибки

Анализирует код и находит проблемы: неиспользуемые переменные, потенциальные баги, нарушения стиля. Next.js включает ESLint по умолчанию.

npm run lint     # Проверить весь проект

Prettier — форматирует автоматически

Приводит код к единому стилю: отступы, кавычки, длина строк. Файл .prettierrc:

{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "all"
}

Настройка в VS Code

Установи расширения ESLint и Prettier, включи «Format on Save» — код форматируется при каждом сохранении автоматически.

Husky + lint-staged

Автоматическая проверка перед каждым коммитом. Если ESLint нашёл ошибку — коммит не пройдёт.

🏋️ Практика

  1. Выполни npm run lint в своём Next.js проекте
  2. Установи Prettier: npm install -D prettier
  3. Создай .prettierrc с настройками выше
  4. Установи расширение Prettier в VS Code, включи Format on Save

19. Middleware — промежуточный слой

Middleware — код между запросом пользователя и основным обработчиком. Как охранник на входе: проверяет пропуск, прежде чем пустить.

Middleware в Next.js

Файл middleware.ts в корне проекта:

import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // Защита приватных страниц
  if (request.nextUrl.pathname.startsWith('/account')) {
    const token = request.cookies.get('auth-token');
    if (!token) {
      return NextResponse.redirect(new URL('/login', request.url));
    }
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/account/:path*', '/admin/:path*'],
};

Типичные задачи

  • Авторизация — проверить токен до загрузки страницы
  • Локализация — определить язык и показать правильную версию
  • A/B тестирование — показать версию A или B
  • Rate limiting — ограничить количество запросов

🏋️ Практика

  1. Создай файл middleware.ts в корне Next.js проекта
  2. Добавь простой middleware, который логирует каждый запрос: console.log(request.nextUrl.pathname)
  3. Открой сайт и посмотри логи в терминале — увидишь каждый запрос

20. Кэширование — как ускорить сайт

Зачем

Без кэша: каждый раз сервер идёт в базу, достаёт данные, рендерит HTML. 500-2000мс. С кэшем: первый запрос 500мс, все следующие — 20мс.

Уровни кэша

Браузерный — браузер сохраняет картинки, CSS, JS. При повторном визите не скачивает заново.

CDN — серверы Vercel по миру сохраняют HTML. Пользователь получает страницу с ближайшего сервера.

Серверный — приложение сохраняет результаты запросов в память (Redis).

ISR (Incremental Static Regeneration) — золотая середина в Next.js:

// Страница обновляется каждые 60 секунд
export const revalidate = 60;

export default async function CatalogPage() {
  const products = await getProducts();
  return <ProductGrid products={products} />;
}

Первый посетитель — свежие данные за 500мс. Следующие 60 секунд — кэш за 20мс. Фоновое обновление.

Инвалидация

Когда кэш устарел? Два подхода: по времени (живёт N секунд) или по событию (обновили товар → сбросили кэш).

import { revalidatePath } from 'next/cache';

export async function updateProduct(id: number, data: any) {
  await supabase.from('products').update(data).eq('id', id);
  revalidatePath('/catalog');  // Сбросить кэш
}

Что кэшировать, а что нет

Кэшировать: каталог, статьи, статические страницы. Не кэшировать: корзину, личный кабинет, страницу оплаты — всё уникальное для пользователя.

🏋️ Практика

  1. Добавь export const revalidate = 60 в любую страницу Next.js
  2. Задеплой на Vercel
  3. Открой страницу, обнови — заметь скорость (она будет приходить из кэша)

21. WebSocket и Realtime — живые данные

Проблема

HTTP: клиент спрашивает → сервер отвечает → соединение закрыто. Для чата или уведомлений нужно, чтобы сервер мог сам послать данные.

WebSocket

Соединение открывается один раз и остаётся. Двусторонний обмен в реальном времени.

HTTP:       Клиент → Сервер → Клиент (закрыл)
WebSocket:  Клиент ↔ Сервер (постоянное соединение)

Supabase Realtime

Подписка на изменения таблицы:

const subscription = supabase
  .channel('orders')
  .on(
    'postgres_changes',
    { event: 'INSERT', schema: 'public', table: 'orders' },
    (payload) => {
      console.log('Новый заказ:', payload.new);
    }
  )
  .subscribe();

Где используется

Чаты, уведомления, live-дашборды, синхронизация между устройствами, стриминг ответов AI.

🏋️ Практика

  1. В Supabase Dashboard → Realtime → включи для таблицы products
  2. В коде подпишись на изменения (пример выше)
  3. Открой приложение и вручную добавь товар в Supabase — увидишь обновление без перезагрузки

22. Мониторинг — как узнать, что сайт упал

Без мониторинга ты узнаёшь о проблемах от клиентов. С мониторингом — получаешь уведомление за минуту до них.

Sentry — ловит ошибки

Перехватывает ошибки в продакшене: что сломалось, строка кода, какой пользователь пострадал.

npm install @sentry/nextjs
npx @sentry/wizard@latest -i nextjs

Бесплатный план — 5,000 ошибок в месяц.

Vercel Analytics

Встроено: Web Vitals, посещаемость, география. Включается одним кликом в Dashboard.

PostHog — продуктовая аналитика

Действия пользователей: какие страницы смотрят, куда кликают, где бросают корзину. Open source.

Uptime-мониторинг

UptimeRobot (бесплатный) — проверяет каждую минуту, работает ли сайт. Если упал — SMS/Telegram.

🏋️ Практика

  1. Зарегистрируйся на sentry.io (бесплатно)
  2. Установи Sentry в свой проект: npx @sentry/wizard@latest -i nextjs
  3. Задеплой и специально вызови ошибку — увидишь её в Sentry Dashboard

23. SEO для разработчика — чтобы Google нашёл

Почему SEO — дело разработчика

Если сайт на обычном React (SPA) — Google видит пустой <div id="root">. На Next.js с SSR — полноценную страницу. Техническая часть определяет, проиндексируется ли сайт вообще.

Meta-теги

export const metadata = {
  title: 'Мой магазин — кроссовки и аксессуары',
  description: 'Оригинальные кроссовки и аксессуары с доставкой по России.',
};

Open Graph — как ссылка выглядит в мессенджерах

Когда кто-то кидает ссылку в Telegram — Open Graph определяет картинку, заголовок и описание:

export const metadata = {
  openGraph: {
    title: 'Air Max 2026 — Мой магазин',
    description: 'Новая коллекция кроссовок',
    images: ['/images/air-max-og.jpg'],   // 1200x630px
  },
};

Sitemap и robots.txt

// src/app/sitemap.ts
export default async function sitemap() {
  const products = await getProducts();
  return [
    { url: 'https://myshop.com', lastModified: new Date() },
    ...products.map((p) => ({
      url: `https://myshop.com/catalog/${p.slug}`,
      lastModified: p.updated_at,
    })),
  ];
}

Structured Data (JSON-LD)

Помогает Google показать цену и рейтинг прямо в поиске:

<script type="application/ld+json">
{JSON.stringify({
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Кроссовки Air Max",
  "offers": {
    "@type": "Offer",
    "price": "12000",
    "priceCurrency": "RUB",
    "availability": "https://schema.org/InStock"
  }
})}
</script>

Core Web Vitals

Google измеряет: LCP (когда контент стал видим, цель < 2.5с), INP (реакция на клик, < 200мс), CLS (прыгает ли контент, < 0.1).

🏋️ Практика

  1. Добавь metadata с title и description в свой page.tsx
  2. Добавь Open Graph — скинь ссылку в Telegram, проверь, как выглядит
  3. Открой PageSpeed Insights (web.dev/measure), вбей URL — посмотри Core Web Vitals

24. Безопасность — от чего защищаться

XSS (Cross-Site Scripting)

Атакующий внедряет JavaScript в поле ввода. Защита: React автоматически экранирует текст. Не используй dangerouslySetInnerHTML с пользовательскими данными.

SQL-инъекции

Атакующий вставляет SQL-код в поле ввода. Защита: Supabase SDK и ORM используют параметризованные запросы — инъекция невозможна.

// ОПАСНО
const result = await db.query(`SELECT * FROM users WHERE id = '${userId}'`);

// БЕЗОПАСНО
const result = await supabase.from('users').select('*').eq('id', userId);

CSRF (Cross-Site Request Forgery)

Чужой сайт отправляет запрос от имени залогиненного пользователя. Защита: SameSite cookies, CSRF-токены. Next.js Server Actions имеют встроенную защиту.

CORS

Браузер запрещает запросы между разными доменами. Это защита — evil.com не может обратиться к твоему API. Если нужно разрешить — настрой заголовки явно.

Rate Limiting

Ограничение запросов от одного пользователя. Без него бот может положить сервер 10,000 запросами в секунду. Для продакшена: Vercel Edge Middleware или Upstash Redis.

Защита API-ключей

API-ключи никогда не попадают на фронтенд. Проверь: если ключ в переменной с NEXT_PUBLIC_ — он видим всем. Секретные ключи — только в серверном коде.

Supabase RLS — последний рубеж

Даже если весь код сломан, RLS не даст получить чужие данные:

ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
CREATE POLICY "users_own_orders" ON orders
  FOR ALL USING (auth.uid() = user_id);

Чеклист безопасности

  • RLS включён на всех таблицах с данными пользователей
  • API-ключи не начинаются с NEXT_PUBLIC_
  • .env.local в .gitignore
  • HTTPS (Vercel настраивает автоматически)
  • Rate limiting на публичных API
  • Webhook-подписи проверяются (Stripe, ЮKassa)

🏋️ Практика

  1. Проверь свой .gitignore — есть ли там .env.local?
  2. Зайди в Supabase → Table Editor → любая таблица → RLS — включён ли?
  3. Поищи в своём коде NEXT_PUBLIC_ — нет ли среди них секретных ключей?

SSE — Server-Sent Events. Односторонний стрим от сервера к клиенту.

SSG — Static Site Generation. HTML генерируется при сборке.

SSR — Server-Side Rendering. HTML генерируется при каждом запросе.

State — состояние компонента. Данные, которые меняются во времени.

Tailwind — утилитарный CSS-фреймворк. Стили через классы.

Token — цифровой пропуск для авторизации.

TypeScript — JavaScript с типами. Ловит ошибки до запуска.

Unit Test — тест отдельной функции в изоляции.

Uptime — время непрерывной работы сервиса.

URL — адрес ресурса в интернете.

Vercel — платформа для хостинга и деплоя.

Webhook — сервер присылает данные при событии.

WebSocket — двусторонняя связь в реальном времени.

XSS — Cross-Site Scripting. Атака через вредоносный JavaScript.
