Урок 22. Планирование задач агентом

Цель: научить агента делать сложные многошаговые задачи через явное планирование Время: ~55 минут Источник: ai-agents-for-beginners/07

Зачем тебе этот урок

Простой ReAct-агент (Урок 18) хорош для 2–10 шагов. На длинных задачах он начинает «теряться»: забывает цель, повторяет шаги, не замечает, что задача уже выполнена.

Решение — явное планирование. Сначала агент пишет план из всех шагов, потом выполняет его, отмечая прогресс. Это:

  • Делает поведение предсказуемым (план виден).
  • Снижает галлюцинации (модель «видит» что осталось).
  • Позволяет «вернуться к плану» если что-то пошло не так.
  • Даёт UX-выигрыш: пользователь видит чек-лист, понимает прогресс.

1. Plan-and-Execute паттерн

1. PLAN: модель пишет список шагов.
2. EXECUTE: для каждого шага — выполняет (tool calls).
3. UPDATE: после каждого шага — отмечает выполнено/нет.
4. REPLAN если нужно: что-то сломалось → перестроить план.
5. FINISH когда план завершён.

Это диаметрально противоположно ReAct, где модель «думает на каждом шагу». В Plan-and-Execute план — статичный, выполнение — детерминированное.

2. Структура плана

План — это JSON-список задач с зависимостями:

{
  "goal": "Собрать утренний дайджест и отправить в Slack",
  "steps": [
    { "id": 1, "task": "Получить погоду", "depends_on": [], "status": "pending" },
    { "id": 2, "task": "Получить топ-5 новостей tech", "depends_on": [], "status": "pending" },
    { "id": 3, "task": "Получить твои сегодня встречи из календаря", "depends_on": [], "status": "pending" },
    { "id": 4, "task": "Собрать всё в красивый markdown", "depends_on": [1,2,3], "status": "pending" },
    { "id": 5, "task": "Отправить в Slack #morning", "depends_on": [4], "status": "pending" }
  ]
}

Зависимости позволяют параллелить независимые шаги (1, 2, 3 — параллельно).

3. Промпт для планирования

Ты — планировщик задач. Составь план для выполнения цели.

Цель пользователя: {{user_request}}

Доступные инструменты: {{tools}}

Правила:
- Каждый шаг — атомарный (один tool call или одна задача модели).
- Указывай зависимости (depends_on).
- Не больше 10 шагов в плане. Если задача требует больше — разбей на под-цели.
- Параллельные шаги — без зависимостей друг от друга.

Возвращай ТОЛЬКО JSON.

4. Executor — выполнение шагов

Берёт план, выполняет шаги в правильном порядке.

def execute(plan):
    while not all_done(plan):
        ready = get_ready_steps(plan)  # все depends_on done
        # параллельно — независимые шаги
        results = await asyncio.gather(*[run_step(s) for s in ready])
        for step, result in zip(ready, results):
            step['status'] = 'done' if not result.error else 'failed'
            step['result'] = result
        if any(s['status'] == 'failed' for s in plan['steps']):
            return replan(plan)
    return finalize(plan)

5. Replanning — когда план не работает

Иногда:

  • Tool вернул unexpected результат.
  • Изначальный план был неверный (модель ошиблась с шагами).
  • Появилась новая информация.

Тогда — replan: модель видит текущий план + результаты + ошибки, и предлагает обновлённый план.

Ограничение: не больше 3 replan'ов на одну задачу. Иначе агент будет вечно «оптимизировать план» и не выполнять.

6. Когда Plan-and-Execute, а когда ReAct

СценарийПлюс
2–5 шагов, неизвестный порядокReAct
10+ шагов, известная цельPlan-and-Execute
Нужно показать прогресс пользователюPlan-and-Execute (план = UI)
Креативные задачи (написать статью)ReAct (нельзя планировать креатив)
Параллелизация важнаPlan-and-Execute
Стоимость критичнаPlan-and-Execute (один большой promp вместо 10 маленьких)

7. Hierarchical Planning

Для очень больших задач — два уровня:

  • High-level plan (от пользователя): «провести анализ конкурентов».
  • Это разворачивается в 3–5 подцелей: «найти конкурентов», «собрать их продукты», «сравнить цены», «суммировать».
  • Каждая подцель — отдельный mini-plan.

Это похоже на «оркестратор + работники» (Урок 18). Используется в AutoGPT и подобных «autonomous agents».

8. Tree-of-Thoughts: альтернатива

Иногда нужно не «один план», а «несколько вариантов плана». Tree-of-Thoughts (ToT):

  1. Модель генерирует 3–5 альтернативных планов.
  2. Каждый оценивается (другой моделью или эвристикой).
  3. Лучший — выполняется.

Дорого, но даёт лучшее качество на тонких задачах (математика, сложный код).

9. Тонкости и подводные камни

  • План слишком оптимистичный. Модель пишет 5 шагов, реально нужно 12. Решение: «оставь возможность добавить шаги в процессе».
  • Слепое следование плану. На шаге 3 стало ясно, что план неверный — но executor тупо продолжает. Делай health-check после каждого шага.
  • Replan loop. «План плохой → replan → новый план плохой → replan...». Ограничь max_replans=3.
  • Cache в долгих планах. Если задача занимает 5 минут — может вылететь по таймауту. Сохраняй промежуточный state, чтобы можно было продолжить.
  • Параллелизация ломает порядок. Если зависимости описаны неверно — параллельный запуск даст race condition.

10. UX выигрыш

Когда у тебя есть явный план — покажи его пользователю:

📋 Что я собираюсь сделать:
   ⏳ 1. Получить погоду в Москве
   ⏳ 2. Получить новости из RSS (тек 5 источников)
   ⏳ 3. Получить твой календарь на сегодня
   ⏳ 4. Собрать дайджест
   ⏳ 5. Отправить в Slack

[выполняется...]

   ✅ 1. Получить погоду (3°C, дождь)
   ✅ 2. Получить новости (15 заголовков)
   ⏳ 3. Получаю календарь...

Это снижает тревожность («что он делает?») и даёт ощущение контроля.

11. Глоссарий

Plan-and-Execute

Паттерн: сначала весь план, потом выполнение по плану.

Replanning

Перестроение плана в процессе выполнения, если что-то сломалось.

Hierarchical planning

Два уровня: high-level цель → подцели → конкретные шаги.

Tree-of-Thoughts

Несколько альтернативных планов, оценка, выбор лучшего.

12. Практика (55 минут)

  1. Возьми задачу: «утренний дайджест в Slack» (как в примере).
  2. Реализуй два варианта: ReAct и Plan-and-Execute.
  3. Сравни: время выполнения, токены, читаемость кода.
  4. В Plan-and-Execute добавь UI для пользователя (список шагов с галочками).
  5. Подбрось ошибку в одном из tools — посмотри как сработает replan.
  6. Запиши в progress.md: где Plan-and-Execute выиграл, где ReAct.

13. Проверь себя

1. Когда Plan-and-Execute лучше ReAct?
10+ шагов, нужна параллелизация, нужно показать прогресс пользователю, стоимость критична.

2. Что такое replanning?
Перестроение плана в процессе, если шаг провалился или появилась новая инфа. Max 3 раза.

3. Что описывают depends_on в шагах плана?
Зависимости. Шаг не выполняется, пока не выполнены все его dependencies. Независимые шаги — параллельно.

4. Что такое Tree-of-Thoughts?
Генерация нескольких альтернативных планов, оценка, выбор лучшего. Дорого, но даёт качество.

5. Главный UX-выигрыш от явного плана?
Пользователь видит, что агент собирается делать, и понимает прогресс. Снижает тревожность.

14. Что должно остаться в голове

  1. Plan-and-Execute = план целиком впереди, потом выполнение.
  2. Лучше ReAct когда: 10+ шагов, параллелизация, прогресс-UX.
  3. План = JSON с шагами и зависимостями.
  4. Replanning при ошибках, max 3 раза.
  5. Hierarchical для очень больших задач.
  6. Tree-of-Thoughts для тонких задач (математика, код).
  7. Покажи план пользователю — большой UX-выигрыш.
📌 Закрепление: хороший план = половина работы агента. Учись писать промпты для планировщика — это отдельный навык, не такой как для executor'а.
