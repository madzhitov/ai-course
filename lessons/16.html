Урок 16. Что такое ИИ-агенты

Цель: понять, что такое агент, чем он отличается от чат-бота и когда он нужен Время: ~45 минут Источник: ai-agents-for-beginners/01, anthropic.com/news, lilianweng.github.io

Зачем тебе этот урок

2024–2026 — это годы агентов. Slack-боты, code-агенты типа Cursor и Cline, browser-агенты типа Operator, корпоративные copilots — везде агенты. Если ты строишь AI-приложения, ты неизбежно перейдёшь от «один промпт — один ответ» к «много шагов, инструменты, цикл».

Но между «модным словом» и реально полезным агентом — пропасть. Большинство сегодняшних «агентов» — это просто чат-боты с громким названием. Этот урок — про то, что такое настоящий агент и когда он действительно даёт ценность.

1. Определение и анатомия

В простейшей форме:

Агент — это LLM, которая в цикле решает задачу, используя инструменты, пока не достигнет цели.

Четыре ключевых компонента:

  1. «Мозг» — LLM, которая принимает решения
  2. Цель — что нужно сделать (от пользователя)
  3. Инструменты — действия в мире (search, send_email, run_code, ...)
  4. Цикл — повторяющиеся итерации до достижения цели

Часто добавляют пятый компонент:

  1. Память — что агент знает о пользователе и о ходе выполнения задачи

2. Агент vs чат-бот vs RAG vs function calling

Эти термины часто смешивают. Разберём.

КонцептЧто делаетОднократно или в цикле?
Чат-ботОтвечает на сообщение текстом, держит контекст диалогаОдин цикл «запрос → ответ»
RAGПеред ответом достаёт релевантные документы и подмешивает в промптОдин цикл, но с предварительным retrieval
Function callingВ рамках одного ответа модель может вызвать функцию и получить результат1-2 цикла «решить → вызвать → ответить»
АгентМногошаговое решение задачи с инструментами и стратегией5–100 циклов в одной задаче

Главная разница — автономность и количество шагов. Function calling — это «один-два инструмента, в одном ответе». Агент — «десятки решений, несколько инструментов, стратегия, проверка результата».

3. Цикл ReAct — каркас почти всех современных агентов

Мы коротко касались ReAct в уроке 5. Здесь разберём подробнее как операционный паттерн.

На каждом шаге агент делает три вещи:

  1. Thought — рассуждает: «что мне нужно?», «какой шаг следующий?»
  2. Action — вызывает инструмент: search("погода в Москве")
  3. Observation — получает результат от инструмента и добавляет в контекст

Дальше — следующий Thought, и так до тех пор, пока не Thought = «всё, у меня есть ответ для пользователя».

Пример сессии агента, который должен ответить «Какая средняя температура в столицах G7?»:

Thought: Мне нужны столицы G7 и температура в каждой
Action: search("G7 страны и столицы")
Observation: США (Вашингтон), Япония (Токио), Германия (Берлин)...

Thought: Теперь нужна погода в каждой
Action: weather("Вашингтон")
Observation: +12°C

Thought: Следующая...
Action: weather("Токио")
Observation: +18°C
... (повторяется для всех)

Thought: У меня все данные. Считаю среднее.
Action: calculate(mean of [12, 18, 8, 11, 14, 9, 13])
Observation: 12.14

Final Answer: Средняя температура в столицах G7 — около 12°C.

Этот же паттерн крутится внутри Claude Desktop с MCP-серверами, внутри Cursor с инструментами, внутри Browser-Use агентов.

4. Реальные примеры агентов в 2026

Coding-агенты

  • Cursor / Cline / Continue — IDE-плагины. Получают «реализуй фичу X». Читают код, пишут, запускают тесты, чинят ошибки. Используют инструменты read_file, write_file, run_terminal.
  • Devin / GitHub Copilot Workspace — полностью автономные. Дай задачу — он делает PR.
  • Claude Code — CLI-агент от Anthropic. Про него отдельный урок c5.

Browser-агенты

  • OpenAI Operator — Claude управляет браузером для пользователя (бронирование, шопинг)
  • Browser-Use / Skyvern — open-source аналоги
  • Anthropic Computer Use — про него урок c4

Корпоративные ассистенты

  • Customer support агенты — отвечают на тикеты, ищут в базе знаний, эскалируют сложное
  • Sales SDR агенты — пишут письма, обновляют CRM, бронируют встречи
  • Research-агенты — мониторят рынок, пишут отчёты

Личные ассистенты

  • Notion AI agents — выполняют действия в Notion (создать страницу, обновить базу)
  • Раelfish-агенты — мониторят email и автоматизируют рутину

6. Когда нужен агент, а когда нет

Не нужен агент

  • Задача в один шаг — «переведи текст», «сделай summary». Используй просто LLM.
  • Задача с одним действием — «зарегистрируй пользователя». Используй function calling.
  • Задача поиска в документах — используй RAG.
  • Задача с известным алгоритмом — пиши обычный код.

Нужен агент

  • Задача требует нескольких шагов, и порядок шагов зависит от промежуточных результатов
  • Нужно гибко комбинировать инструменты
  • Нет жёсткого алгоритма — нужна стратегия
  • Готов мириться с тем, что задача может занять 1–10 минут вместо секунд

Простой тест: можешь ли ты заранее описать в коде последовательность шагов? Если да — пиши код, а не агент.

7. Тёмные стороны

Стоимость

10 шагов агента ≈ 10 LLM-вызовов ≈ в 10 раз дороже одного запроса. На сложных задачах — $1–5 за выполнение. Считай экономику.

Latency

30 секунд — 5 минут на типичную задачу. Не подходит для интерактива «спросил — получил».

Надёжность

Каждый шаг = потенциальная ошибка. Если каждый шаг работает в 95% случаев, после 10 шагов точность падает до 60%.

Поэтому: чем меньше шагов в одной сессии — тем надёжнее. Декомпозируй большие задачи.

Безопасность

Агент с инструментами может удалить файлы, отправить деньги, опубликовать что-то. Sandbox + human-in-the-loop для критичного. Подробно в уроке 21.

9. Глоссарий

  • Агент — LLM в цикле с инструментами для достижения цели
  • Tool / Инструмент — функция, которую агент может вызывать (search, send_email, run_code)
  • ReAct — паттерн «Thought → Action → Observation» в цикле
  • Plan-and-Execute — сначала составить план, потом выполнять шаги
  • Reflection — агент проверяет и улучшает свой ответ перед финалом
  • Multi-agent — несколько агентов в команде с разными ролями
  • Orchestrator — главный агент, координирующий остальных
  • Memory — что агент помнит между шагами и между задачами
  • Sandbox — изолированная среда исполнения для безопасности
  • Human-in-the-loop (HITL) — обязательное участие человека в критичных решениях

10. Практика (45 минут)

Упражнение 1. Анализ задач из жизни (15 минут)

Возьми 5 задач из своей работы. Для каждой реши:

  • Можно сделать одним LLM-вызовом? → не агент
  • Нужен один tool? → function calling
  • Нужно несколько шагов с условной логикой? → агент

Упражнение 2. Простой агент на 30 строк (30 минут)

Базовый ReAct-агент с одним инструментом — калькулятором:

from anthropic import Anthropic

client = Anthropic()

tools = [{
    "name": "calculator",
    "description": "Вычисляет математическое выражение",
    "input_schema": {
        "type": "object",
        "properties": {"expression": {"type": "string"}},
        "required": ["expression"]
    }
}]

def run_tool(name, args):
    if name == "calculator":
        try:
            return str(eval(args["expression"]))
        except Exception as e:
            return f"Ошибка: {e}"

def agent(task):
    messages = [{"role": "user", "content": task}]
    while True:
        response = client.messages.create(
            model="claude-sonnet-4-5",
            max_tokens=1024,
            tools=tools,
            messages=messages
        )
        if response.stop_reason == "end_turn":
            for block in response.content:
                if block.type == "text":
                    return block.text
        if response.stop_reason == "tool_use":
            messages.append({"role": "assistant", "content": response.content})
            tool_results = []
            for block in response.content:
                if block.type == "tool_use":
                    result = run_tool(block.name, block.input)
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block.id,
                        "content": result
                    })
            messages.append({"role": "user", "content": tool_results})

print(agent("Если книгу из 480 страниц читать по 30 страниц в день, а в субботу и воскресенье по 50, за сколько дней прочитаю?"))

Этот агент будет вызывать калькулятор несколько раз, рассуждая вслух, пока не получит ответ.

11. Проверь себя

1. Какие 4 ключевых компонента у агента?
Мозг (LLM), цель, инструменты, цикл выполнения. Плюс память — необязательный, но часто пятый.

2. Чем агент отличается от function calling?
Function calling — один-два инструмента в одном ответе. Агент — десятки шагов в цикле, со стратегией.

3. Что такое цикл ReAct?
Thought → Action → Observation, повторяется до достижения цели.

4. Когда не нужен агент?
Когда задача одношаговая, либо когда у тебя есть жёсткий алгоритм — лучше написать обычный код.

5. Что такое сложность ошибки в агенте?
Точность падает экспоненциально с числом шагов. 95% × 10 шагов ≈ 60% общей точности.

6. Назови 3 фреймворка для агентов.
LangChain/LangGraph, AutoGen, Pydantic AI, CrewAI, LlamaIndex — любые из них.

7. Что значит «sandbox» в контексте агентов?
Изолированная среда (Docker, VM), где агент может ошибаться без последствий для системы пользователя.

8. Когда нужен HITL?
На критичных шагах: трата денег, удаление, отправка во внешние системы, изменения с большим радиусом действия.

9. Сколько шагов идеально в одной агентской сессии?
Чем меньше, тем надёжнее. Если задача требует много шагов — лучше декомпозировать на несколько отдельных сессий с явной координацией.

10. Какой фреймворк я выберу для своего первого агента?
Прямой Anthropic SDK + Pydantic AI или LangChain (на выбор). Начинай простым — добавляй сложность по необходимости.

12. Что должно остаться в голове

  1. Агент = LLM + tools + цикл + цель. Запомни эту формулу.
  2. ReAct (Thought → Action → Observation) — основа почти всех агентов.
  3. Не каждая задача требует агента. Часто хватает RAG или function calling.
  4. Агенты дороже, медленнее, менее надёжны чем простые вызовы.
  5. Sandbox + HITL для production-агентов.
  6. Чем меньше шагов в сессии, тем выше надёжность.
