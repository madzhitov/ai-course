Claude Projects — память и контекст для задач

Цель: понять, когда Projects лучше обычного чата и как их грамотно использовать Время: ~35 минут Источник: docs.claude.com, claude.com/news

Зачем тебе этот урок

Если ты замечал, что объясняешь Claude одно и то же в каждом новом чате, делишься одним и тем же фоном — Projects решают эту боль. Это контейнеры для связанных диалогов с общим контекстом, инструкциями и файлами.

Простой пример: у тебя есть pet-проект. Каждый раз когда обращаешься к Claude по нему — приходится напоминать про стек, бизнес-логику, текущий этап. С Project всё это лежит в общей «памяти», и любой новый чат начинается с уже актуальным контекстом.

1. Что такое Project

Project в Claude — это:

  • Папка для чатов по одной теме / задаче / клиенту.
  • Project knowledge — файлы и тексты, которые Claude видит во всех чатах внутри.
  • Custom instructions — постоянный system prompt для всех чатов.
  • Активность — все диалоги и артефакты в одном месте.

Доступно на: Claude Pro ($20/мес), Team, Enterprise. На бесплатном тарифе — нет.

2. Когда стоит использовать Project

✅ Хорошо

  • Долгосрочные проекты — pet-project, рабочая инициатива, диссертация.
  • Работа с клиентом / компанией — где есть постоянная фоновая инфа.
  • Изучение темы — например, «Изучаю Rust» — складываешь туда заметки, ссылки.
  • Творческие проекты — роман, сериал, дизайн-система.
  • Регулярные операции — еженедельные отчёты, планирование, ретро.

❌ Не нужно

  • Разовые вопросы.
  • «Объясни что такое X» — обычный чат справится.
  • Кодинг-задачи без общего контекста.

3. Создание Project — пошагово

  1. В claude.ai нажми Projects в левой панели.
  2. Create Project.
  3. Имя — конкретное и понятное: «Курс по ИИ — контент» лучше чем «Учёба».
  4. Description — необязательно, но помогает.
  5. Add knowledge — перетащи файлы (PDF, MD, txt, код).
  6. Custom instructions — главный момент, см. секцию 4.

4. Custom Instructions — главный инструмент

Это system prompt уровня всего проекта. Сюда кладём:

  • Контекст: кто я, чем занимаюсь, какова цель проекта.
  • Роль: кем должен быть Claude в этом проекте.
  • Стиль общения: формальный/прямой, длина ответов.
  • Знания и предпочтения: используем X, не используем Y.
  • Что в knowledge: явно опиши, какие файлы загружены и зачем.

Пример сильного Custom Instructions

Контекст: Я Руслан, делаю курс по ИИ на русском, цель — стать
"тем, к кому ходят за объяснением ИИ для русскоязычных".

Роль: Ты мой соавтор и редактор курса. Думай как опытный
методист и продакт-менеджер.

Стиль:
- Прямо, без воды.
- Когда сомневаешься — задавай уточняющие вопросы.
- Не льсти, не соглашайся ради согласия.
- Если у меня плохая идея — скажи прямо и предложи лучше.

В knowledge:
- progress.md — мой журнал и планы по курсу.
- structure.md — структура 95 уроков.
- lesson-template.md — шаблон формата урока.
- audience.md — описание целевой аудитории.

Не используй: маркетинговые клише, "решение", "инновационный",
"уникальный", эмодзи в формальных текстах.

5. Project Knowledge — что и как загружать

Форматы

  • PDF, DOCX, TXT, MD — естественно.
  • CSV, JSON — данные.
  • Код любых языков.
  • Изображения с текстом (Claude умеет OCR).

Лимиты

  • До 200 KB на один файл текста (для PDF — больше).
  • Общий объём всех файлов в проекте — порядка 200k токенов.
  • Внутри одного чата — обычное контекстное окно (200k токенов).

Что класть, что не класть

Класть:

  • Стабильные референсы — то что не меняется (структуры, спецификации, гайды стиля).
  • Документы, на которые часто ссылаешься.
  • Свои промпт-шаблоны.
  • Примеры твоего стиля — Claude по ним подстроится.

Не класть:

  • Огромные папки кода — лучше точечно нужные файлы.
  • Часто меняющиеся данные — устареют.
  • Конфиденциальные данные, если Pro а не Enterprise (см. секцию 8).

6. Workflow: как работать в Project

Лучшая практика — один Project = один долгосрочный контекст. Внутри:

  • Каждый отдельный thread — конкретная задача.
  • Не пихай 50 разных задач в один thread — лучше создать новые.
  • Пользуйся поиском по чатам внутри проекта (Cmd+K).

Пример моего Workflow

Я (Claude в роли соавтора курса) могу описать так:

  1. Project «Курс по ИИ» с custom instructions из секции 4 и файлами курса в knowledge.
  2. Thread «Урок 9: генерация картинок» — пишу его.
  3. Thread «Структура Фазы 2» — обсуждаю порядок.
  4. Thread «Идеи для Фазы 4» — складываю.
  5. Thread «Планирование на неделю» — каждый понедельник новый.

Через месяц у меня история всех решений по курсу. Возвращаюсь — и не нужно объяснять контекст.

7. Cowork — совместная работа в Project

Cowork — это режим, когда несколько людей работают с одним Project параллельно. Появился в Team-тарифе в конце 2025-го и закрывает старую боль: «у меня в Project всё настроено, как поделиться с командой, не пересылая по 20 ссылок».

Что даёт Cowork

  • Один Project — много участников. Все видят одни и те же Knowledge и Custom Instructions. Никаких «у Маши версия v2, у Пети v3».
  • Общие threads. Коллега заходит и видит, что ты уже обсуждал с Клодом. Можно продолжить там же или форкнуть.
  • Личные threads внутри Project. Если нужно «мне для себя» — помечаешь thread как private, другие его не видят.
  • История изменений Knowledge. Кто и когда заменил файл стратегии — видно. Можно откатить.

Когда это меняет workflow

Типичный кейс — небольшая команда (3–8 человек) работает над одним продуктом / контентом / исследованием. Раньше каждый держал свой Project, копировал друг у друга промпты, рассинхронизировался. С Cowork: один Project «Маркетинг Q1», все туда заходят, видят те же материалы, обсуждают в общих threads.

Что не стоит делать

  • Не делай Cowork-Project на 50 человек. Knowledge превратится в свалку, threads — в хаос. Лучше 3–4 Project под подкоманды.
  • Не складывай туда чувствительные данные «потому что удобно». Если в Project ходит подрядчик — он видит всё. Используй роли (admin / member / viewer) или отдельный Project.
  • Не путай Cowork с чатом. Это не Slack. Сюда — рабочие сессии с Клодом и их история, не оперативное общение.

Как начать

  1. Тариф Team (или выше) — без него Cowork недоступен.
  2. В настройках Project → Share → добавляешь людей по email или приглашаешь всю Workspace.
  3. Задаёшь роль: admin (правит Knowledge и instructions), member (создаёт threads), viewer (только читает).
  4. Согласовываешь с командой простое правило: «общие threads — для рабочих обсуждений, private — для черновиков».

Cowork — это не «фича для галочки», это сдвиг: Project перестаёт быть «личной папкой с промптами» и становится рабочим пространством. Если работаешь не один — попробуй.

8. Топ-3 неправильных применения

❌ «Один Project на всё»

Создал «AI Helper» и пихаешь туда всё подряд. Knowledge превращается в свалку. Custom instructions расплывчатые. Не работает.

❌ Дамп всей кодовой базы в Knowledge

Загрузил 5 МБ кода → токены закончились на каждом запросе → ответы поверхностные. Лучше: точечно нужные файлы под текущую задачу через chat-attach.

❌ Custom instructions из 5 строк

«Будь полезным помощником» — это не custom instructions, это шум. Сильные instructions — 30+ строк со специфичной информацией.

9. Приватность — важно

Pro

Knowledge файлы хранятся у Anthropic. По умолчанию НЕ используются для обучения модели (это политика Anthropic с 2024). Удалить файл — он удалится из их хранилища тоже (но логи могут жить ещё месяц).

Team / Enterprise

Дополнительно — DPA, BAA для медицины, SOC 2, контроль над регионом хранения.

Что не клади даже на Pro

  • Полные персональные данные клиентов с реальными именами.
  • Закрытые контракты с реальными условиями.
  • Финансовые данные до публикации.
  • Не-анонсированные продуктовые планы.

Решение: anonymize. Замени имена на роли, цифры на формулы.

10. Прокачка через примеры

Пример A: Project для разработчика

  • Имя: «my-saas-backend».
  • Knowledge: README, архитектурный документ, OpenAPI spec, ключевые модели данных.
  • Custom instructions: технический стек, naming conventions, что не использовать (старые паттерны).

Пример B: Project для писателя

  • Имя: «Роман — Падение империи».
  • Knowledge: персонажи (имена, бэкграунд), мир (география, история), стиль (примеры предыдущих глав).
  • Custom instructions: жанр, тон, что не уместно.

Пример C: Project для маркетолога

  • Имя: «B2B SaaS — лидген».
  • Knowledge: бренд-гайд, ICP, кейсы, прошлые рассылки.
  • Custom instructions: тон бренда, запрещённые слова, формат.

11. Практика (30 минут)

Упражнение 1. Создай Project

  1. Реши: какой у тебя долгосрочный проект сейчас (работа над сайтом, обучение языку, ведение блога).
  2. Создай Project в claude.ai.
  3. Загрузи в Knowledge: 2–3 базовых файла (можно создать прямо в Markdown за 10 минут).
  4. Напиши Custom Instructions хотя бы на 20 строк по структуре из секции 4.

Упражнение 2. Сравни

Задай один и тот же сложный вопрос:

  • В обычном чате (нужно объяснять контекст).
  • В созданном Project.

Сравни качество и время ответа.

12. Проверь себя

1. Чем Project отличается от обычного чата?
Project — контейнер для связанных чатов с общим Knowledge (файлы) и Custom Instructions (system prompt). Обычный чат — изолированная сессия.

2. На каком тарифе доступны Projects?
Pro ($20/мес), Team, Enterprise. На бесплатном — нет.

3. Что класть в Custom Instructions?
Контекст (кто я, цель), роль Claude, стиль общения, что в Knowledge, что не использовать. Минимум 20+ строк для эффекта.

4. Сколько занимают файлы Knowledge?
До 200 КБ на файл текста, общий объём в районе 200к токенов.

5. Главный антипаттерн использования Projects?
Один Project на всё — превращается в свалку. Лучше много специализированных.

📌 Закрепление: Projects превращают Claude из «универсального ассистента» в «персонализированного коллегу» по конкретной задаче. Если ты используешь Claude больше 30 минут в день и платишь за Pro — обязательно осваивай.
