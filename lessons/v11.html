Фаза 1. Пользователь·V11

Справочник: основы веба

Цель: Как работает интернет, frontend, backend, Node.js, фреймворки. Карта территории, без воды. Время: ~50 минут Главы гайда: 1–5

Зачем тебе этот урок

Этот урок — часть «Справочника по веб-разработке для не-разработчиков». Это не ката (как v1–v10), а карта территории. Здесь — концепты, которые AI генерирует в твоих проектах и которые тебе важно понимать, чтобы не быть слепым.

Без снобизма, без воды, с примерами из реальной жизни. После всех 5 модулей у тебя будет полная картина: от того, как браузер делает запрос, до того, как мониторить продакшен.

1. Как работает интернет — базовая модель

Когда пользователь вводит адрес сайта в браузере, происходит четыре шага.

Шаг 1 — DNS. Браузер спрашивает у DNS-сервера: «Какой IP-адрес у этого домена?» DNS — это телефонная книга интернета. Домен — человекочитаемое имя (google.com), IP-адрес — числовой адрес сервера (142.250.80.46).

Шаг 2 — Запрос. Браузер отправляет HTTP-запрос на этот IP-адрес. Запрос содержит: метод (GET — дай мне страницу), URL (/catalog/shoes), заголовки (язык, тип браузера, куки).

Шаг 3 — Сервер. Сервер получает запрос, обрабатывает его (достаёт данные из базы, рендерит HTML) и отправляет ответ.

Шаг 4 — Рендеринг. Браузер получает HTML, CSS и JavaScript, рисует страницу на экране.

Всё, что ты строишь как разработчик — это про шаги 3 и 4: что происходит на сервере (backend) и что видит пользователь (frontend).

Протоколы

HTTP/HTTPS — протокол общения браузера с сервером. HTTPS — зашифрованная версия (замочек в адресной строке). Современные хостинги (Vercel, Netlify) настраивают HTTPS автоматически.

URL — адрес ресурса. Разберём: https://myshop.com/catalog/shoes?color=red&size=42 - https:// — протокол - myshop.com — домен - /catalog/shoes — путь (route) - ?color=red&size=42 — параметры запроса (query params)

🏋️ Практика

  1. Открой любой сайт и нажми Cmd+Option+I (Mac) или F12 (Windows)
  2. Перейди во вкладку Network
  3. Обнови страницу — увидишь все запросы, которые делает браузер
  4. Кликни на первый запрос — посмотри заголовки, статус-код, время ответа

2. Frontend — что видит пользователь

Frontend — это всё, что работает в браузере пользователя. Три базовых технологии:

HTML — структура

Скелет страницы. Определяет что на странице: заголовок, текст, картинка, кнопка, форма.

<header>
  <h1>Мой магазин</h1>
  <nav>
    <a href="/catalog">Каталог</a>
    <a href="/about">О нас</a>
  </nav>
</header>

CSS — внешний вид

Как это выглядит: цвета, шрифты, отступы, анимации.

header {
  background-color: #000;
  color: #fff;
  font-family: 'Helvetica', sans-serif;
  padding: 20px;
}

JavaScript — поведение

Что происходит при взаимодействии: нажал кнопку → открылось меню, прокрутил → появилась анимация, ввёл email → отправилась форма.

button.addEventListener('click', () => {
  menu.classList.toggle('open');
});

Tailwind CSS — утилитарный подход

Вместо написания CSS-файлов ты добавляешь классы прямо в HTML. Это как конструктор — собираешь внешний вид из готовых кубиков.

Обычный CSS:

.button { background: black; color: white; padding: 8px 16px; border-radius: 4px; }

Tailwind:

<button class="bg-black text-white px-4 py-2 rounded">Купить</button>

Результат одинаковый, но с Tailwind не нужно переключаться между файлами, а AI-модели генерируют его значительно лучше, чем обычный CSS.

React — компонентный подход

React разбивает интерфейс на переиспользуемые компоненты. Кнопка — компонент. Карточка товара — компонент. Шапка сайта — компонент.

function ProductCard({ name, price, image }) {
  return (
    <div className="border rounded p-4">
      <img src={image} alt={name} />
      <h3>{name}</h3>
      <p>{price} ₽</p>
      <button>В корзину</button>
    </div>
  );
}

Один раз написал ProductCard — используешь на странице каталога 50 раз с разными данными.

SPA vs SSR vs SSG

SPA (Single Page Application) — весь сайт загружается одним файлом, переходы между страницами без перезагрузки. Быстро работает, но Google плохо индексирует. Обычный React.

SSR (Server-Side Rendering) — сервер генерирует HTML для каждого запроса. Google видит готовую страницу. Медленнее первая загрузка, но лучше для SEO. Next.js умеет это.

SSG (Static Site Generation) — HTML генерируется один раз при сборке, а не при каждом запросе. Самый быстрый вариант для контента, который редко меняется. Идеально для блогов, лендингов, документации.

Next.js позволяет комбинировать все три подхода на одном сайте: каталог — SSR (данные актуальные), блог — SSG (контент статичный), личный кабинет — SPA (не нужен SEO).

🏋️ Практика

  1. Открой DevTools (Cmd+Option+I), вкладка Elements
  2. Найди любой элемент на странице, измени его текст или цвет прямо в браузере
  3. Обнови страницу — изменения пропадут (ты менял только свою локальную копию)
  4. Попробуй попросить AI (Claude, ChatGPT): «Создай карточку товара на React + Tailwind с фото, названием, ценой и кнопкой»

3. Backend — что работает на сервере

Backend — это код, который пользователь не видит. Он работает на сервере и отвечает за:

Бизнес-логику — «при оформлении заказа проверь наличие, рассчитай доставку, спиши деньги, отправь уведомление менеджеру».

Работу с данными — чтение и запись в базу данных.

Интеграции — общение с платёжными системами, отправка email, работа с внешними API.

Безопасность — проверка прав, валидация данных, защита от атак.

Языки бэкенда

  • JavaScript/TypeScript (через Node.js) — один язык для фронта и бэка, лучший выбор для вайб-кодинга
  • Python (Django, FastAPI) — популярен в ML/AI и data science
  • Go — быстрый, для высоконагруженных систем
  • PHP — WordPress, Laravel, старые проекты
  • Ruby — Ruby on Rails, стартапы

Для вайб-кодинга JavaScript/TypeScript — лучший выбор: один язык везде, AI-модели генерируют его лучше всего, огромная экосистема пакетов.

🏋️ Практика

  1. Открой DevTools → Network на любом сайте с авторизацией
  2. Залогинься и посмотри, какие запросы уходят: POST /api/login, какие данные отправляются, что приходит в ответ
  3. Обрати внимание: пароль не виден в ответе, только токен — это работа бэкенда

4. Node.js — движок всего

Что это

JavaScript изначально работал только в браузере — двигал кнопки, менял цвета. В 2009 году Райан Даль создал Node.js — среду, которая позволяет JavaScript работать на сервере, как Python или Java.

Зачем нужен

Без Node.js ты не можешь: - Запустить сервер, который обрабатывает запросы - Читать и писать файлы на диске - Работать с базой данных - Отправлять email - Запускать инструменты разработки (npm, webpack, ESLint)

Где он используется

  • Next.js работает поверх Node.js
  • npm — это часть Node.js
  • Claude Code установлен через npm, работает на Node.js
  • Vercel запускает твой код в Node.js runtime
  • Любой серверный JavaScript — это Node.js

Как установить

# через Homebrew на macOS
brew install node

# проверить версию
node --version
npm --version     # npm ставится вместе с Node.js

TypeScript

TypeScript — это JavaScript с типами. Вместо «переменная может быть чем угодно» ты говоришь «это число» или «это строка».

JavaScript:

function getPrice(product) {
  return product.price * 1.2;  // А если product.price — не число? Ошибка в рантайме.
}

TypeScript:

function getPrice(product: { price: number }): number {
  return product.price * 1.2;  // Компилятор не даст передать не-число
}

TypeScript ловит ошибки до запуска кода. Все современные проекты используют его. AI-модели генерируют TypeScript лучше, потому что типы дают им больше контекста.

🏋️ Практика

  1. Установи Node.js: brew install node (macOS) или скачай с nodejs.org
  2. Открой терминал и набери: node -e "console.log('Hello from Node.js!')"
  3. Создай файл test.js с содержимым console.log(2 + 2), запусти: node test.js
  4. Ты только что запустил JavaScript на сервере — без браузера

5. Фреймворки — почему не пишут с нуля

Фреймворк — это набор готовых решений для типовых задач. Без него каждый проект начинается с изобретения колеса: как делать роутинг, как обрабатывать формы, как оптимизировать загрузку.

Next.js — главный фреймворк для вайб-кодинга

Next.js = React + маршрутизация + серверный рендеринг + API-роуты + оптимизация. Создан командой Vercel — поэтому деплой на Vercel работает идеально.

App Router — структура папок определяет URL:

src/app/
├── page.tsx                    → mysite.com/
├── catalog/
│   ├── page.tsx                → /catalog
│   └── [slug]/
│       └── page.tsx            → /catalog/shoes, /catalog/bags, ...
├── about/
│   └── page.tsx                → /about
├── api/
│   └── orders/
│       └── route.ts            → API endpoint /api/orders
└── layout.tsx                  → Общий layout (шапка, подвал)

[slug] — динамический сегмент. Один файл обрабатывает /catalog/shoes, /catalog/bags и любой другой slug.

API Routes — серверные функции прямо в Next.js. Не нужен отдельный бэкенд:

// src/app/api/orders/route.ts
export async function POST(request: Request) {
  const body = await request.json();
  // сохранить заказ в базу
  // отправить уведомление менеджеру
  return Response.json({ success: true });
}

Другие фреймворки (для общей картины)

  • Express.js — минималистичный бэкенд-фреймворк для Node.js. Старый, но популярен
  • Nuxt.js — аналог Next.js, но для Vue вместо React
  • SvelteKit — аналог Next.js для Svelte. Модный, лаконичный
  • Remix — альтернатива Next.js от создателей React Router
  • Astro — для контентных сайтов, супер-быстрый

🏋️ Практика

  1. Создай проект: npx create-next-app@latest my-first-app --typescript --tailwind --app
  2. Зайди в папку: cd my-first-app
  3. Запусти: npm run dev
  4. Открой в браузере http://localhost:3000 — ты увидишь работающий сайт
  5. Открой файл src/app/page.tsx, измени текст, сохрани — страница обновится автоматически
