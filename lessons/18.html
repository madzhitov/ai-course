Урок 18. Паттерны проектирования агентов

Цель: освоить базовые паттерны проектирования агентов и понимать, какой применять в каком случае Время: ~60 минут Источник: ai-agents-for-beginners/04 + Anthropic «Building effective agents»

Зачем тебе этот урок

«Агент» — это не один паттерн, а целый зоопарк. Без знания паттернов ты будешь:

  • Делать сложного multi-agent там, где хватает простого workflow.
  • Делать примитивный ReAct там, где нужен Reflexion.
  • Не использовать роутинг и каждый раз тратить на полную модель.

Anthropic в 2024 разделили на два класса: workflows (детерминированные цепочки) и agents (LLM сам решает шаги). Этот урок проходит по обеим категориям.

Эвристика: начинай с workflow. Переходи на agent только когда видишь, что workflow не покрывает все ветки.

2. Базовые workflow-паттерны

Prompt chaining

Серия LLM-вызовов, выход одного — вход другого. Каждый шаг делает одну задачу. Между шагами можно вставить детерминированную проверку.

Пример: сделать пост в Telegram → LLM 1: написать тезисы → проверка длины → LLM 2: переписать как пост → LLM 3: добавить эмодзи и хештеги.

Routing

LLM-роутер классифицирует входящий запрос и направляет в правильный «специализированный» путь.

Пример: запрос в поддержку → LLM-классификатор: billing / technical / sales → нужный pipeline.

Выгода: каждая ветка может использовать другую модель (дешёвую для простого, дорогую для сложного) или другой системный промпт.

Parallelization

Один и тот же вход обрабатывается несколькими LLM параллельно, результаты агрегируются.

Sectioning: разделить большую задачу на параллельные подзадачи. «Проанализируй PR» = «безопасность» + «стиль» + «производительность» параллельно.

Voting: один и тот же запрос — N раз, мажоритарный ответ. Для критичных решений.

Orchestrator-Workers

Центральный LLM-«оркестратор» разбивает задачу на подзадачи и поручает их «работникам». В отличие от чистого parallelization, здесь оркестратор сам решает, на сколько подзадач разбить.

Пример: код-ревью большого PR — оркестратор смотрит структуру и поручает: «один работник смотрит auth/, другой db/, третий UI/».

Evaluator-Optimizer

Один LLM генерирует, другой критикует. Цикл, пока критик не одобрит.

Пример: «напиши SQL-запрос → SQL-эксперт проверит → если ошибка, перепиши».

3. Agent-паттерны

ReAct (Reasoning + Acting)

Базовый паттерн агента. LLM на каждом шаге пишет: «думаю: ... → действие: tool X с параметрами Y». Tool возвращает результат. Цикл продолжается, пока LLM не скажет «Готово».

Все современные LLM с tools = реализация ReAct под капотом.

Когда хорошо: однонаправленные задачи с 2–10 шагами.

Plan-and-Execute

В отличие от ReAct, агент сначала составляет план из всех шагов (planning step), затем выполняет шаги. Если что-то ломается — может перепланировать.

Когда хорошо: длинные задачи на 10+ шагов, где «думать на каждом шагу заново» нерационально.

Reflexion (self-critique)

После выполнения задачи агент сам критикует свой результат и итерирует. По сути — Evaluator-Optimizer, но один агент в обеих ролях.

Когда хорошо: код, который должен компилироваться и проходить тесты; решение математических задач.

Tool-using agent с retry/fallback

Продакшен-вариант ReAct. Каждый tool call обёрнут в try/except. При неудаче:

  • Retry с экспоненциальным бекоффом (transient errors).
  • Fallback на другую модель/tool.
  • Запись в audit log.

4. Multi-agent паттерны

Hierarchical (Supervisor + Workers)

Главный агент-супервизор делит задачу на подзадачи и распределяет их по «работникам». Каждый работник специализирован (Researcher, Writer, Critic, Coder).

Это масштабирование Orchestrator-Workers с LLM-оркестратором.

Collaborative (round-robin)

Несколько агентов равноправно общаются друг с другом. Используется в AutoGen и CrewAI.

Debate

Два агента занимают противоположные позиции. Третий-судья выносит решение. Полезно для:

  • Спорных вопросов (Pro vs Contra).
  • Качества ответа (один пишет, другой критикует).

5. Производственные паттерны (rеsilience)

  • Retry с экспоненциальным бекоффом — для transient errors (rate limits, network).
  • Circuit breaker — после N подряд ошибок прекращай попытки на T минут.
  • Timeout на каждый LLM-вызов и на весь агент целиком.
  • Idempotency keys — чтобы повторный запуск не сделал действие дважды.
  • Cost budget — лимит токенов на одну сессию агента.
  • Human-in-the-loop для критичных действий.

7. Тонкости и подводные камни

  • Чем сложнее паттерн, тем дороже. Multi-agent debate может стоить в 10 раз больше, чем простой запрос. Используй когда оправдано.
  • Каскадирующие ошибки. В цепочке из 10 шагов с 95% точностью каждый — итоговая точность ~60%. Считай заранее.
  • Перепланирование в Plan-and-Execute может зациклиться. Ограничивай число итераций.
  • Multi-agent не значит «лучше». Часто один хорошо настроенный агент превосходит трёх плохих.
  • Reflexion может ухудшать ответ. Если первоначальный ответ был хорошим, а критик придирается — повторная итерация может всё испортить. Тестируй.

8. Глоссарий

Workflow

Цепочка LLM-вызовов с детерминированными переходами в коде.

Agent

LLM сам решает следующий шаг и инструмент. Высокая гибкость, низкая предсказуемость.

ReAct

Reasoning + Acting. Базовый паттерн: «думаю → действую → наблюдаю → думаю».

Reflexion

Самокритика после выполнения, итерация до удовлетворительного результата.

Orchestrator-Workers

LLM-оркестратор разбивает задачу и распределяет по специализированным работникам.

Circuit breaker

Производственный паттерн: после N ошибок временно отключить компонент, не нагружать.

9. Практика (60 минут)

  1. Возьми задачу: «найди в этом репозитории все TODO и оцени, какие критичны».
  2. Реализуй сначала как workflow (chain: grep TODO → LLM rank).
  3. Реализуй как ReAct-агент (LLM с tools: list_files, read_file, grep).
  4. Реализуй как Orchestrator-Workers (один LLM решает на сколько папок разбить, по агенту на каждую).
  5. Сравни: время, токены, качество, простота кода.
  6. Запиши в progress.md, какой паттерн выиграл и почему.

10. Проверь себя

1. Когда workflow лучше agent?
Шаги структурированы и известны. Нужна предсказуемость и дешевизна.

2. Чем ReAct отличается от Plan-and-Execute?
ReAct думает шаг за шагом, Plan-and-Execute сначала строит весь план, потом выполняет.

3. Что такое Reflexion и зачем?
Самокритика после выполнения с итерацией. Когда качество критично (код, расчёты).

4. Почему «multi-agent ≠ всегда лучше»?
Стоимость растёт мультипликативно. Каскадирующие ошибки. Координация добавляет ошибок.

5. Что такое circuit breaker и от чего защищает?
После N подряд ошибок отключает компонент на T минут. Защищает от лавинного нагружения внешних сервисов.

11. Что должно остаться в голове

  1. Workflow (код решает) vs Agent (LLM решает). Начинай с workflow.
  2. Workflow-паттерны: chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer.
  3. Agent-паттерны: ReAct (база), Plan-and-Execute (длинные задачи), Reflexion (само-проверка).
  4. Multi-agent: hierarchical, collaborative, debate — оправданы только когда дают измеримый прирост.
  5. Производственные: retry, circuit breaker, timeout, idempotency, cost budget, human-in-the-loop.
  6. Считай каскадирующую точность — 10 шагов × 95% ≈ 60% общая.
