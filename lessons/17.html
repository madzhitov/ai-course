Урок 17. Обзор агентских фреймворков

Цель: разобраться в зоопарке фреймворков для агентов и выбрать подходящий Время: ~55 минут Источник: ai-agents-for-beginners/02 + актуальная экосистема 2025–2026

Зачем тебе этот урок

В Уроке 16 ты понял: агент — это «LLM в while-loop с инструментами». Можно написать с нуля. Можно взять фреймворк. Фреймворки решают: tools registry, retry/error handling, memory, observability, multi-step planning, multi-agent coordination.

Зоопарк большой и быстро меняется. Этот урок даёт карту, чтобы ты не учил каждый фреймворк отдельно — а понимал, что они делают, и выбирал под задачу.

2. LangChain — главный швейцарский нож

LangChain — самый известный. Идея: всё AI-приложение собирается из Runnables (компонентов), соединённых через | (pipe). Это даёт быстрый старт и обширную экосистему интеграций.

Плюсы:

  • 500+ интеграций (vectorstores, LLM, tools).
  • Большое сообщество, тонны примеров.
  • Быстрый прототип за день.

Минусы:

  • Часто меняет API — миграции болезненные.
  • Абстракции «протекают»: легко собрать, сложно отдебажить.
  • Для серьёзного прода часто переписывают в LangGraph или с нуля.

3. LangGraph — для продакшена

Создатели LangChain признали ограничения и в 2023 выпустили LangGraph. Это state machine для агентов: ты описываешь узлы (что делать) и переходы (когда). Каждый шаг сохраняется в state — можно остановить/возобновить.

Когда выбирать LangGraph:

  • Сложная логика: «если задача X → ветка A, иначе → ветка B».
  • Human-in-the-loop: пауза на подтверждение пользователя.
  • Длинные процессы: «обработай этот документ за 5 шагов с проверками».
  • Production reliability: retry, чекпоинты, observability.

4. LlamaIndex — RAG-first

LlamaIndex заточен под работу с данными: загрузить документы, разбить, проиндексировать, запросить. Если основная задача — «дай ответ по моим документам», LlamaIndex быстрее доведёт до результата, чем LangChain.

В 2024–2026 LlamaIndex добавил агентский слой поверх RAG. Это позиционирует его как «агенты для данных», а LangChain — «агенты для всего».

5. Microsoft AutoGen / Agent Framework

Главная идея: несколько агентов общаются друг с другом. Описываешь роли: «Researcher собирает данные, Writer пишет отчёт, Critic проверяет». Они автоматически делят задачу и сотрудничают.

Реально работает для:

  • Сложных аналитических задач (один ищет, другой синтезирует, третий проверяет).
  • Code generation с разделением на «архитектор + кодер + тестер».
  • Дебатных сценариев («Pro vs Contra» для лучшего ответа).

Цена: больше токенов и времени. Используй только когда multi-agent даёт реальный прирост качества.

6. CrewAI — декларативный multi-agent

CrewAI делает то же, что AutoGen, но с более простым декларативным API. Описываешь «команду» (Crew), её агентов и задачи на YAML или Python:

researcher = Agent(role="Researcher", goal="Find facts about X", tools=[search_tool])
writer = Agent(role="Writer", goal="Write blog post", tools=[])
crew = Crew(agents=[researcher, writer], tasks=[...])
crew.kickoff()

Хорош для быстрых прототипов multi-agent сценариев.

7. OpenAI Assistants API

Это managed-сервис. Создаёшь Assistant с инструментами, threads (диалоги), runs (один шаг). OpenAI хранит state, ты — только клиент.

Плюсы: не нужна своя инфраструктура. Code interpreter и file search встроены.

Минусы: привязка к OpenAI. Меньше гибкости. Дороже.

В 2024 OpenAI выпустили также Swarm — лёгкий multi-agent open-source.

8. Минималистский подход — Anthropic SDK + tools

Anthropic в своём блог-посте 2024 «Building effective agents» явно сказал: «В большинстве случаев вам не нужен фреймворк. Простой while-loop с tools достаточен.»

Реальный код агента на Anthropic SDK — ~50 строк Python:

while True:
    response = client.messages.create(model=..., messages=messages, tools=tools)
    if response.stop_reason == "end_turn": break
    for block in response.content:
        if block.type == "tool_use":
            result = execute_tool(block.name, block.input)
            messages.append({"role": "tool", "content": result})

Это работает. Для 70% задач достаточно. И ты понимаешь каждую строку.

10. Observability — обязательно

Что бы ты ни выбрал — подключи трейсинг с первого дня. Без него агент = чёрная коробка.

  • LangSmith (для LangChain/LangGraph).
  • Langfuse (open-source, для любого фреймворка).
  • Helicone (proxy-based, минимальная интеграция).
  • Phoenix от Arize (открытый стандарт OpenTelemetry).

Что должно записываться: каждый промпт, каждый ответ, каждый tool call, токены, латентность, ошибки.

11. Тонкости и подводные камни

  • «Фреймворк говорит, что это просто» — пока всё работает. На производстве абстракции мешают дебагу.
  • Vendor lock-in на уровне промптов. LangChain переписывает твои промпты внутри.
  • Зависимости. LangChain тащит десятки транзитивных пакетов. Конфликты версий бывают часто.
  • Версия фреймворка ≠ версия документации. 80% Stack Overflow-ответов устарели.
  • Не стартуй сразу с multi-agent. 90% задач решаются одним хорошим агентом.

12. Глоссарий

Runnable (LangChain)

Базовый компонент, который можно скомпоновать через |. LLM, retriever, parser — всё Runnable.

State machine (LangGraph)

Граф узлов и переходов между ними. Описывает поведение агента как конечный автомат.

Multi-agent system

Несколько LLM-агентов разных ролей, общающихся друг с другом для решения задачи.

Observability

Возможность видеть, что внутри: промпты, ответы, tool calls, токены, латентность.

13. Практика (55 минут)

  1. Возьми задачу: «получить погоду в городе + новости и собрать утренний дайджест».
  2. Реализуй трижды: на чистом Anthropic SDK, на LangChain, на LangGraph.
  3. Сравни: строк кода, время на дебаг, читаемость.
  4. Подключи Langfuse или LangSmith — посмотри трейс одного запуска.
  5. Запиши вывод в progress.md: какой подход подошёл тебе больше.

14. Проверь себя

1. Когда LangChain — правильный выбор?
Прототип за день, нужно много интеграций, команда уже знает.

2. Чем LangGraph отличается от LangChain?
State machine с чекпоинтами и human-in-the-loop. Заточен под продакшен.

3. Когда minimal (Anthropic SDK + цикл) — лучше фреймворка?
2–3 tool, простой while-loop, важна полная прозрачность кода.

4. Что такое multi-agent system и когда оправдан?
Несколько агентов разных ролей. Оправдан когда разделение труда даёт измеримый прирост качества и стоит дополнительных токенов.

5. Зачем observability с первого дня?
Без неё агент — чёрная коробка. Невозможно понять, почему он ошибся.

15. Что должно остаться в голове

  1. Фреймворки решают tools, memory, multi-step, multi-agent, observability.
  2. LangChain — для прототипов. LangGraph — для прода.
  3. LlamaIndex — если задача в основе про данные.
  4. AutoGen / CrewAI — когда multi-agent даёт реальный прирост качества.
  5. Anthropic SDK + tools — для минималистов; работает для 70% задач.
  6. Observability обязательна (Langfuse, LangSmith, Helicone, Phoenix).
