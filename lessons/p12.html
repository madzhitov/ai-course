Проект «За 1 час»: Свой Claude Skill — упаковываем рутину в навык

Что построим: Skill «Weekly PR Report», который Claude подхватывает сам Время: ~60 минут Уровень: базовый bash + Claude Desktop (или Claude Code)

Что в итоге будет

Папка с одним SKILL.md и парой скриптов, которую Claude Desktop / Claude Code автоматически использует, когда ты пишешь «сделай отчёт по PR за неделю». Никаких отдельных запусков, никаких копирований промптов — просто естественный запрос, который превращается в готовый markdown-отчёт.

После этого ты сможешь упаковывать любую свою рутину в Skill: утренний дайджест из почты, чек-лист публикации поста, журнал тренировок, протокол ретро — что угодно повторяющееся.

Теория за 30 секунд (подробности в c9)

Skill — это папка на диске с обязательным файлом SKILL.md. В YAML-фронтматтере описано, когда Skill применяется (триггеры). В теле — инструкции, что делать. Опционально рядом лежат вспомогательные скрипты, шаблоны, референсы.

Claude сам читает SKILL.md при старте сессии (точнее — заголовок и description), и когда видит подходящий запрос — подгружает тело Skill в контекст и выполняет инструкции. От тебя — только сформулировать задачу естественно.

Требования

  • Claude Code (CLI) или Claude Desktop с поддержкой Skills.
  • Git и GitHub CLI (gh) — для примера про PR-отчёт. brew install gh на маке.
  • ~60 минут.

Архитектура

~/.claude/skills/weekly-pr-report/
├── SKILL.md          ← триггеры + инструкции для Claude
├── scripts/
│   └── fetch_prs.sh  ← вспомогательный скрипт
└── templates/
    └── report.md     ← шаблон финального отчёта

Логика работы:

  1. Ты пишешь Claude: «собери мне отчёт по моим PR за неделю».
  2. Claude видит совпадение с триггерами Skill — загружает SKILL.md.
  3. По инструкции вызывает scripts/fetch_prs.sh через bash-tool.
  4. Парсит JSON, заполняет шаблон, отдаёт тебе готовый markdown.

Шаг 1. Создаём папку для Skill

Skills лежат либо глобально (~/.claude/skills/), либо в проекте (.claude/skills/ в корне репозитория). Глобальные доступны везде, проектные — только в этом проекте. Для нашего отчёта берём глобальный:

mkdir -p ~/.claude/skills/weekly-pr-report/scripts
mkdir -p ~/.claude/skills/weekly-pr-report/templates
cd ~/.claude/skills/weekly-pr-report

Шаг 2. Пишем SKILL.md

Самая важная часть — это description в frontmatter. Claude по ней решает, релевантен ли Skill запросу. Пиши конкретно, перечисляй типичные формулировки.

Файл SKILL.md:

---
name: weekly-pr-report
description: |
  Собирает markdown-отчёт по pull request'ам пользователя за последние 7 дней
  (или указанный период). Использует gh CLI и шаблон в templates/report.md.
  Применяется на запросы вида: "сделай отчёт по PR за неделю",
  "что я закодил на этой неделе", "weekly PR summary",
  "подведи итоги недели по гитхабу", "отчёт для тимлида".
---

# Weekly PR Report

Этот Skill готовит сводку по pull request'ам, в которых участвовал
пользователь за указанный период.

## Когда использовать

Активируйся, когда пользователь просит:
- отчёт / summary / итоги недели по pull request'ам или коммитам;
- подготовить материал для 1-1 с менеджером;
- сводку активности на GitHub.

Если не указан период — бери последние 7 дней.

## Как делать

1. Спроси у пользователя GitHub username, если его нет в контексте сессии
   и не получается узнать через `gh api user --jq .login`.
2. Запусти `bash scripts/fetch_prs.sh <USERNAME> <DAYS>`.
   Он печатает JSON-массив PR со всеми нужными полями.
3. Раздели PR по статусу: merged / open / closed-without-merge.
4. Возьми шаблон `templates/report.md`, подставь данные и верни
   пользователю готовый markdown. Не сокращай, не добавляй своих
   разделов поверх шаблона.

## Формат итогового отчёта

- Заголовок с диапазоном дат.
- Краткое резюме (1-2 предложения, что было главным).
- Списки PR по статусам с ссылками.
- В каждой строке: `#номер · название · репозиторий · +добавлено / −удалено`.

## Не делай

- Не вызывай GitHub API напрямую через curl — используй скрипт.
- Не показывай сырой JSON пользователю.
- Не выдумывай PR, которых нет в выводе скрипта.

Пара вещей, которые стоит подчеркнуть.

description в YAML — это единственное, что Claude видит без подгрузки полного Skill. Пиши так, чтобы по нему было ясно: что делает, на какие фразы реагирует. Списком формулировок повышаешь шанс срабатывания.

«Не делай» — отдельная секция, которая хорошо работает. Без неё Claude часто пытается «улучшить» — добавить рекомендации, переформатировать, посыпать эмодзи. С ней — следует шаблону.

Шаг 3. Скрипт fetch_prs.sh

Skill может выполнять любые shell-команды через bash-tool. Лучше выносить логику в отдельный скрипт — так Claude вызывает один понятный entry point, а не клеит сложную команду с пайпами в каждом запросе.

Файл scripts/fetch_prs.sh:

#!/usr/bin/env bash
set -euo pipefail

USERNAME="${1:-}"
DAYS="${2:-7}"

if [ -z "$USERNAME" ]; then
  echo "usage: fetch_prs.sh <github_username> [days]" >&2
  exit 1
fi

SINCE=$(date -u -v-"${DAYS}"d '+%Y-%m-%d' 2>/dev/null \
  || date -u -d "-${DAYS} days" '+%Y-%m-%d')

# gh search возвращает только метаданные. Чтобы получить diff stats,
# отдельно дергаем каждый PR через gh pr view.

gh search prs \
  --author "$USERNAME" \
  --updated ">=$SINCE" \
  --limit 100 \
  --json number,title,url,state,isDraft,repository,createdAt,updatedAt,closedAt \
  | jq '[.[] | {
      number,
      title,
      url,
      state,
      draft: .isDraft,
      repo: .repository.nameWithOwner,
      created: .createdAt,
      updated: .updatedAt,
      closed: .closedAt
    }]'

Сделай исполняемым:

chmod +x ~/.claude/skills/weekly-pr-report/scripts/fetch_prs.sh

На macOS флаг даты другой (-v-7d), на Linux — -d "-7 days". В скрипте обработаны оба случая.

Шаг 4. Шаблон отчёта

Файл templates/report.md:

# Weekly PR Report
**Период:** {{from}} — {{to}}
**Автор:** @{{username}}

## TL;DR

{{summary_1_2_sentences}}

## ✅ Merged ({{merged_count}})

{{merged_list}}

## 🔄 In progress ({{open_count}})

{{open_list}}

## ❌ Closed without merge ({{closed_count}})

{{closed_list}}

---

Шаблон строки PR: `- [#{number}]({url}) — {title} · \`{repo}\``

Claude знает, что {{...}} — это плейсхолдеры, и заполнит их сам. Никаких jinja или mustache не нужно.

Шаг 5. Регистрируем Skill

Claude Code: Skills из ~/.claude/skills/ подхватываются автоматически при старте новой сессии. Перезапусти CLI — и можно проверять.

Claude Desktop: Settings → Features → Skills → нажми «Refresh skills» или перезапусти приложение. Skill должен появиться в списке с твоим name и description.

Чтобы убедиться, что Skill виден, попроси в чате: «какие Skills у тебя сейчас доступны?». В ответе должен фигурировать weekly-pr-report.

Запуск и проверка

В новом чате просто пиши:

сделай мне отчёт по моим PR за неделю,
github username — madzhitov

Claude должен:

  1. Вспомнить Skill (видно по фразе вроде «использую weekly-pr-report»).
  2. Вызвать bash scripts/fetch_prs.sh madzhitov 7.
  3. Дождаться JSON, отсортировать по статусам.
  4. Заполнить шаблон и отдать готовый markdown.

У меня первый запуск занимает ~8 секунд (gh search не самый быстрый), повторные — те же 8 секунд, кеш не помогает. Если работаешь над одной задачей и не хочешь дёргать сеть лишний раз — попроси Claude «не запускай скрипт снова, используй прошлый результат».

Шаг 6. Когда Skill не срабатывает

Самая частая проблема — Claude не вызывает Skill сам. Лечится по чек-листу:

  1. Перезапусти Claude Desktop / новую сессию Claude Code.
  2. Проверь, что description содержит ключевые слова из твоего запроса.
  3. Попроси явно: «используй Skill weekly-pr-report».
  4. Загляни в логи. В Claude Desktop — Help → Open Logs. В Claude Code — ставь флаг --debug, видно, какие Skills загрузились.

Расширения

  • Skill «утренний дайджест»: читает unread в Gmail / Slack, делает свод за 5 минут до 10:00. Триггер: «что важного с утра?».
  • Skill «чек-лист публикации поста»: по запросу «опубликовать пост [path]» — проверяет наличие обложки, alt-текстов, длину title/description, прогоняет линтер.
  • Skill «журнал тренировок»: по фразе «записал тренировку: жим 80×5×3» — дописывает в markdown-журнал, считает прогрессию, в конце недели делает свод.
  • Skill «протокол 1:1»: по «сделай заметки для 1:1 с N» — берёт прошлые заметки, открытые задачи N в Jira, формирует agenda.
  • Командные Skills через git: кладёшь Skills в .claude/skills/ репозитория — вся команда работает с одинаковыми инструментами.

Подводные камни

  • Длинный SKILL.md. Если файл >200 строк — Claude съест много токенов на каждом запуске и может проигнорировать часть инструкций. Дроби на несколько Skills.
  • Двусмысленный description. «Помогает с отчётами» — слишком общо, сработает на всё подряд. «Отчёт по PR за неделю» — точно.
  • Пути в скриптах. Когда Claude вызывает bash scripts/fetch_prs.sh, рабочая директория — та, где он сейчас находится, а не папка Skill. Если скрипту нужны соседние файлы — используй $(dirname "$0").
  • Зависимости. Skill ожидает, что gh и jq установлены. Если делишься Skill с командой — добавь раздел «Prerequisites» в SKILL.md и проверку наличия в начале скрипта.
  • Секреты. Никогда не клади токены в Skill. Они уходят в контекст и попадают в логи. Только переменные окружения или системный keychain.
  • Конфликтующие Skills. Если у тебя пять Skills с похожим описанием — Claude угадывает. Делай чёткие, непересекающиеся.

Что в итоге

За час ты:

  1. Понял структуру Skill: SKILL.md + скрипты + шаблоны.
  2. Написал реально используемый Skill для еженедельного отчёта.
  3. Освоил формат description, который надёжно цепляется Claude.
  4. Получил каркас, на который теперь налепливаешь любую другую рутину.

Skills — это не магия, а способ один раз описать «как ты делаешь X», и больше не объяснять это каждый раз. После третьего-четвёртого Skill начинаешь замечать в работе паттерны, которые раньше делал руками — и они один за другим становятся вызовами на одну фразу.
