Проект «За 1 час»: Локальный AI-секретарь на Ollama — без облака и подписок

Что построим: офлайн-версию проекта p15 — утренний разбор почты, классификация и черновики ответов полностью на локальной модели Время: ~75 минут Уровень: Python средний, базовое понимание IMAP, 16+ GB RAM на машине

Зачем этот проект

Проект p15 делает почти то же самое, но через Claude API. У этого подхода есть три неприятных «но»:

  • Приватность. Содержимое каждого письма уезжает в облако. Если в почте врачебные выписки, NDA, переписка с нотариусом — это твой осознанный выбор, и далеко не все готовы его делать.
  • Деньги. Сто писем в день — копейки, тысяча — уже заметно. На длинной дистанции API-счёт капает.
  • Зависимость. Перебои с платежом, региональные блокировки, лимиты — и скрипт встал.

Локальная версия снимает все три пункта. Письма не покидают машину, никакие подписки не нужны, всё работает в самолёте. Платишь только электричеством и временем — обработка медленнее, чем у Claude, но для утренней пачки это нормально.

Что в итоге будет

  • Python-скрипт, запускающийся по cron каждое утро.
  • Чтение inbox через IMAP (Mail.ru / Yandex / Gmail — что угодно с поддержкой app-password).
  • Классификация через локальную Ollama: urgent / fyi / noise / template.
  • На «template» — черновик ответа сохраняется в IMAP-папку «Черновики».
  • Дневной чек-ин в Telegram: «3 срочных, 12 FYI, 47 шума. Срочные: …».
  • Ни одного облачного запроса с содержимым письма — только TG-бот в самом конце.

Требования

  • Python 3.10+.
  • 16 GB RAM минимум (для qwen2.5:7b) или 32 GB (для qwen2.5:14b).
  • Mac с Apple Silicon, Linux или Windows. На CPU тоже работает, но в 5–10 раз медленнее.
  • Почтовый ящик с включённым IMAP и app-password.
  • Telegram-бот (через @BotFather) и свой chat_id.
  • Установленный Ollama (см. шаг 1).

Архитектура

cron (8:00 утра)
    ↓
main.py
    ├─→ IMAP: достать письма за последние 24 часа (тема + первые 1500 символов)
    ├─→ Ollama (qwen2.5): классифицировать каждое (urgent / fyi / noise / template)
    ├─→ для template: сгенерировать draft → положить в IMAP Drafts
    └─→ Telegram: отправить дневной чек-ин

Всё локально, наружу уходит только финальное сообщение в Telegram.

Почему Qwen 2.5, а не Llama 3

На локальных моделях главный критерий — качество русского. Llama 3 и 3.1 умеют русский «по остаточному принципу»: понимают, но в генерации часто скатываются в кальки с английского, путают падежи, формулируют коряво. Qwen 2.5 тренировался на заметно большем объёме китайского и русского, и в задачах на русском уверенно его обходит при том же размере. Для классификации с короткими репликами на русском это критично.

Из практики: на одних и тех же 50 письмах qwen2.5:7b делает 2–3 ошибки классификации, llama3:8b — 7–10. Драфты на русском у Qwen выглядят как нормальный человеческий ответ; у Llama часто «по́жалуйста подтвердите получение данного письма».

Шаг 1: ставим Ollama и тянем модель

Ollama — самый простой способ запустить локальную LLM. Сам ставит, сам обновляет, поднимает HTTP-сервер на localhost:11434.

Установка:

# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# или скачать .dmg / .exe с ollama.com

Тянем модель. Выбор размера зависит от RAM:

  • qwen2.5:7b — 4.7 GB на диске, ~6 GB RAM при работе. Для 16 GB-машин.
  • qwen2.5:14b — 9 GB на диске, ~12 GB RAM. Для 32 GB.
  • qwen2.5:32b — 20 GB, ~28 GB RAM. Если у тебя сервер или Mac Studio.
ollama pull qwen2.5:7b
# или
ollama pull qwen2.5:14b

# проверка — модель должна ответить:
ollama run qwen2.5:7b "Ответь одним словом: какой сегодня день недели? Просто угадай."

Если на 16 GB запустил 14b — система начнёт уходить в swap, и каждый запрос будет идти по 2–3 минуты. Лучше честно остановиться на 7b и при необходимости подкрутить промпт.

Шаг 3: достаём свежие письма

Файл fetch_inbox.py:

import os
from datetime import datetime, timedelta
from dotenv import load_dotenv
from imap_tools import MailBox, AND

load_dotenv()


def fetch_recent_emails(hours=24):
    since = (datetime.now() - timedelta(hours=hours)).date()
    emails = []

    with MailBox(os.getenv("IMAP_HOST")).login(
        os.getenv("IMAP_USER"),
        os.getenv("IMAP_PASS"),
        initial_folder="INBOX",
    ) as mailbox:
        for msg in mailbox.fetch(AND(date_gte=since), mark_seen=False):
            emails.append({
                "uid": msg.uid,
                "from": msg.from_,
                "subject": msg.subject or "(без темы)",
                "date": msg.date.isoformat() if msg.date else "",
                "body": (msg.text or msg.html or "")[:1500],
            })
    return emails


if __name__ == "__main__":
    mails = fetch_recent_emails(24)
    print(f"Получено {len(mails)} писем за 24 часа")
    for m in mails[:3]:
        print(f"  {m['from']} | {m['subject']}")

Запусти — должно вывести количество и первые 3 темы.

Шаг 4: классифицируем через Ollama

Главное отличие от облачной версии — у локальной 7b-модели контекст 8k токенов и она заметно хуже держит длинные batch-запросы. Если на Claude мы могли отправить пачку из 30 писем в одном запросе, то здесь надёжнее идти по одному. Медленнее, но качество классификации не плывёт.

Файл classify.py:

import json
import os
import re
import ollama

MODEL = os.getenv("OLLAMA_MODEL", "qwen2.5:7b")

SYSTEM_PROMPT = """Ты — личный секретарь. Классифицируй письмо в одну из категорий:

- "urgent" — требует ответа сегодня. Прямой вопрос лично мне, дедлайн,
  проблема в проде, срочная просьба от руководства или клиента.
- "fyi" — нужно знать, но отвечать не надо. Уведомления о решениях,
  важные рассылки, отчёты.
- "noise" — можно не открывать. Маркетинг, спам, авто-уведомления
  систем (CI/CD, дайджесты, PR-апдейты).
- "template" — типовой запрос со стандартным ответом: подтверждение
  слота, запрос документов, "можете созвониться в среду?".

Для "template" добавь поле "draft" — текст черновика ответа на русском,
в моём стиле: короткий, без воды, без формальностей вроде
"Добрый день, уважаемый". Просто по делу.

Верни СТРОГО валидный JSON-объект без markdown и без комментариев:
{"category": "urgent", "reason": "клиент спрашивает про дедлайн"}
или для template:
{"category": "template", "reason": "запрос слота",
 "draft": "Привет! Среда 15:00 подходит. Скину ссылку утром."}
"""


def _extract_json(text):
    """Локальные модели иногда оборачивают ответ в ```json ... ``` или комментируют.
    Достаём первый валидный JSON-объект."""
    text = text.strip()
    if text.startswith("```"):
        text = re.sub(r"^```(?:json)?s*", "", text)
        text = re.sub(r"s*```$", "", text)
    # на всякий случай ищем первую {...}-структуру
    match = re.search(r"{.*}", text, re.DOTALL)
    if match:
        text = match.group(0)
    return json.loads(text)


def classify_one(email):
    user_msg = json.dumps({
        "from": email["from"],
        "subject": email["subject"],
        "body_preview": email["body"][:1200],
    }, ensure_ascii=False)

    resp = ollama.chat(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ],
        options={"temperature": 0.2, "num_ctx": 8192},
        format="json",  # ollama умеет принуждать модель к JSON
    )

    try:
        return _extract_json(resp["message"]["content"])
    except json.JSONDecodeError:
        # фолбэк: если модель совсем сошла с ума — считаем шумом
        return {"category": "noise", "reason": "parse_error"}


def classify_all(emails):
    out = []
    for i, e in enumerate(emails, 1):
        result = classify_one(e)
        result["uid"] = e["uid"]
        out.append(result)
        print(f"  [{i}/{len(emails)}] {result['category']:8} | {e['subject'][:60]}")
    return out

Ключевые параметры:

  • temperature=0.2 — для классификации нам нужна предсказуемость, не креатив.
  • num_ctx=8192 — поднимаем контекст до максимума 7b-модели. По умолчанию Ollama даёт 2048, чего мало.
  • format="json" — Ollama переключает декодер в режим, гарантирующий валидный JSON. Без этого 5–10% ответов будут битыми.

Шаг 5: сохраняем черновики в папку Drafts

Эта часть идентична облачной версии — IMAP-протокол одинаков для Claude и для Ollama.

Файл drafts.py:

import os
from email.message import EmailMessage
from imap_tools import MailBox


def guess_drafts_folder():
    host = os.getenv("IMAP_HOST", "")
    if "gmail" in host:
        return "[Gmail]/Drafts"
    if "yandex" in host:
        return "Drafts"
    if "mail.ru" in host:
        return "Черновики"
    return "Drafts"


def save_draft(to_addr, subject, body):
    msg = EmailMessage()
    msg["From"] = os.getenv("IMAP_USER")
    msg["To"] = to_addr
    msg["Subject"] = (
        f"Re: {subject}"
        if not subject.lower().startswith("re:")
        else subject
    )
    msg.set_content(body)

    folder = guess_drafts_folder()
    with MailBox(os.getenv("IMAP_HOST")).login(
        os.getenv("IMAP_USER"), os.getenv("IMAP_PASS")
    ) as mailbox:
        mailbox.append(msg.as_bytes(), folder)

Если не уверен в имени папки — выведи список:

with MailBox(host).login(user, password) as mailbox:
    for folder in mailbox.folder.list():
        print(folder.name)

Шаг 6: дневной чек-ин в Telegram

Файл tg_brief.py:

import os
from telegram import Bot


async def send_brief(stats, urgent_items, draft_count):
    bot = Bot(token=os.getenv("TG_BOT_TOKEN"))

    lines = [
        "📬 *Утренний бриф (локально, без облака)*",
        "",
        f"🔴 Срочное: {stats.get('urgent', 0)}",
        f"🟡 FYI: {stats.get('fyi', 0)}",
        f"⚪️ Шум: {stats.get('noise', 0)}",
        f"✉️ Черновиков подготовлено: {draft_count}",
    ]

    if urgent_items:
        lines.append("")
        lines.append("*Что важно сегодня:*")
        for item in urgent_items[:5]:
            lines.append(f"• _{item['from']}_: {item['subject']}")
            if item.get("reason"):
                lines.append(f"  └ {item['reason']}")

    await bot.send_message(
        chat_id=os.getenv("TG_CHAT_ID"),
        text="
".join(lines),
        parse_mode="Markdown",
    )

Шаг 7: собираем main.py

import asyncio
from collections import Counter
from dotenv import load_dotenv

from fetch_inbox import fetch_recent_emails
from classify import classify_all
from drafts import save_draft
from tg_brief import send_brief

load_dotenv()


def main():
    emails = fetch_recent_emails(hours=24)
    print(f"Достал {len(emails)} писем")

    if not emails:
        asyncio.run(send_brief({}, [], 0))
        return

    results = classify_all(emails)
    email_by_uid = {e["uid"]: e for e in emails}

    stats = Counter()
    urgent_items = []
    draft_count = 0

    for r in results:
        stats[r["category"]] += 1

        if r["category"] == "urgent":
            e = email_by_uid.get(r["uid"], {})
            urgent_items.append({
                "from": e.get("from", "?"),
                "subject": e.get("subject", "?"),
                "reason": r.get("reason", ""),
            })

        if r["category"] == "template" and r.get("draft"):
            e = email_by_uid.get(r["uid"])
            if e:
                save_draft(e["from"], e["subject"], r["draft"])
                draft_count += 1
                print(f"  draft → {e['from']}")

    asyncio.run(send_brief(dict(stats), urgent_items, draft_count))
    print("Готово.")


if __name__ == "__main__":
    main()

Запуск и проверка

Сначала проверь, что Ollama жива:

curl http://localhost:11434/api/tags
# должен вернуть JSON со списком установленных моделей

Дальше — ручной запуск:

python main.py

На 50 письмах и qwen2.5:7b на Apple M2 Pro у меня уходит около 4–5 минут (CPU+GPU). На голом CPU — 12–15 минут. Это нормально для утреннего cron, который ты не видишь.

Что проверить:

  • В Telegram пришёл бриф с цифрами.
  • В папке «Черновики» появились новые драфты на письма-«template».
  • Тексты драфтов читаемые на русском, без англицизмов и «уважаемых коллег».

Когда работает — ставь cron:

crontab -e
# каждый будний день в 8:00:
0 8 * * 1-5 cd /path/to/local-secretary && /path/to/venv/bin/python main.py >> log.txt 2>&1

Сравнение с p15 (Claude-версия)

  • Скорость. Claude обрабатывает 50 писем за 10–15 секунд, локальная qwen2.5:7b — за 4–5 минут на M-чипе. Для крона разница незаметна, для интерактивного использования — да.
  • Качество классификации. Claude промахивается ~1% случаев, qwen2.5:7b — 5–7%, qwen2.5:14b — 2–3%. Чаще всего ошибки между «fyi» и «noise» (что не критично), реже между «urgent» и «fyi» (тут больно).
  • Качество драфтов. Claude пишет ответ «как живой человек, твоего уровня». Qwen 7b пишет нормально, но иногда слишком формально или с лишним «надеюсь, у вас всё хорошо». 14b — заметно ближе к Claude. Решается few-shot-примерами в системном промпте.
  • Деньги. Claude — порядка $0.5–2 в месяц на средний почтовый ящик. Ollama — $0, если не считать электричество.
  • Приватность. У Ollama содержимое писем не покидает машину. Это главный аргумент для медкарт, договоров и личной переписки.

Расширения

  • Автотегирование в почте. Добавляй IMAP-флаги — «Flagged» на urgent, метку «AI-noise» на noise. Потом фильтром в клиенте → шум сразу в архив.
  • Экспорт TODO. Если в письме «сделай X к четвергу» — отдельный класс task, и draft = добавить в Things 3 (URL-схема), Todoist или Obsidian-файл.
  • Пятничный недельный отчёт. Второй cron-джоб в пятницу в 17:00 — пробегает по отправленным письмам за неделю и через Ollama же выдаёт «вот что ты на этой неделе сделал». Удобно для журнала или для отчёта руководителю.
  • Few-shot стиль. Подсунь модели 5–10 своих реальных ответов прямо в SYSTEM_PROMPT — драфты становятся заметно «твоими».
  • VIP-список. «Эти 10 адресов — всегда urgent» хардкодом в коде, до запроса в модель. Письмо от босса или нотариуса не должно зависеть от настроения LLM.

Подводные камни

  • Медленно на CPU. Без GPU 7b-модель отвечает 10–20 секунд на письмо. 50 писем = до 15 минут. Если есть Apple Silicon или дискретная NVIDIA — будет в 3–5 раз быстрее, Ollama её подхватывает автоматически.
  • Контекст 8k у 7b. Длинный тред с историей на 100 круток не влезет. Безопасно — обрезать тело письма до 1200–1500 символов, как в коде выше. Иначе модель начнёт «забывать» начало и галлюцинировать.
  • Модель промахивается чаще, чем Claude. Поэтому скрипт ничего не удаляет и не отправляет сам — только классифицирует и кладёт драфт. Все деструктивные действия за тобой.
  • Ollama иногда не возвращает валидный JSON. Даже с format="json" бывают сбои. Поэтому в коде есть фолбэк-парсинг и «если не распарсилось — считаем noise». Лучше пропустить одно письмо, чем уронить весь джоб.
  • Память. Ollama загружает модель в RAM при первом запросе и держит 5 минут. Если cron бежит раз в сутки — каждый раз будет холодный старт ~15–30 секунд на загрузку весов. Можно прогревать: curl http://localhost:11434/api/generate -d '{"model":"qwen2.5:7b","keep_alive":-1}' на старте машины.
  • HTML-письма. У многих рассылок msg.text пустой, всё в msg.html. Фолбэк в коде есть, но HTML-теги забивают контекст. Если у тебя много HTML — подключи html2text для очистки.

Что в итоге

У тебя есть полностью офлайн-версия секретаря. Письма не покидают машину, никаких подписок, никаких блокировок. По качеству qwen2.5:7b проигрывает Claude на 5–10 процентных пунктов точности классификации и заметно скучнее в драфтах — но эти 5–10% часто стоят того, чтобы медкарта и переписка с банком не уезжали в чужой дата-центр.

Связка p15 + p21 даёт интересный паттерн: рабочую почту с NDA — на Ollama, личную с подписками и встречами — на Claude. Один и тот же main.py, отличаются только classify.py и переменные окружения.

Готово. Утренний разбор inbox теперь делается локально и бесплатно. Дальше — недельный отчёт по отправленным письмам, экспорт TODO в Things/Todoist, или замена Telegram на native-нотификацию macOS. Всё это докручивается на той же Ollama без единого запроса в облако.
