Справочник: инструменты разработчика

Цель: Git, npm, .env, спецификация. Без этого невозможна командная работа и деплой. Время: ~40 минут Главы гайда: 9–12

Зачем тебе этот урок

Этот урок — часть «Справочника по веб-разработке для не-разработчиков». Это не ката (как v1–v10), а карта территории. Здесь — концепты, которые AI генерирует в твоих проектах и которые тебе важно понимать, чтобы не быть слепым.

Без снобизма, без воды, с примерами из реальной жизни. После всех 5 модулей у тебя будет полная картина: от того, как браузер делает запрос, до того, как мониторить продакшен.

9. Git и репозитории — контроль версий

Что такое Git

Git — система контроля версий. Она отслеживает каждое изменение в коде и позволяет: вернуться к любой предыдущей версии, работать нескольким людям над одним проектом, создавать параллельные ветки для экспериментов.

Основные концепции

Репозиторий (repo) — папка проекта, за которой следит Git. Локальный репозиторий — на твоём компьютере. Удалённый (remote) — на GitHub.

Коммит (commit) — снимок состояния проекта в конкретный момент. Как «сохранение» в игре. Коммит фиксирует изменения локально — на сайте ничего не меняется.

git add .                                    # Подготовить все изменения
git commit -m "Добавил страницу каталога"    # Сохранить снимок

Push — отправить коммиты на GitHub. Код уехал в облако, но сайт ещё не обновился.

Деплой — Vercel подхватывает push и публикует сайт. Вот теперь пользователи видят изменения.

Цепочка: коммит (сохранил локально) → push (отправил на GitHub) → деплой (Vercel собрал и опубликовал).

Ветка (branch) — параллельная линия разработки. Основная ветка — main. Хочешь добавить новую фичу — создаёшь ветку, работаешь в ней, потом сливаешь обратно.

git checkout -b feature/catalog    # Создать ветку и переключиться
# ... работаешь ...
git checkout main                  # Вернуться в main
git merge feature/catalog          # Слить изменения

Pull — скачать изменения с GitHub (сделанные другими или на другом компьютере).

git pull origin main               # Скачать последнюю версию

GitHub

GitHub — платформа для хранения репозиториев. Как Google Drive для кода. Vercel подключается к GitHub и автоматически деплоит при каждом push.

.gitignore

Файл, который говорит Git, что НЕ нужно отслеживать:

node_modules/      # Зависимости (тяжёлые, ставятся через npm install)
.env.local         # Секреты (API-ключи, пароли)
.next/             # Сборка Next.js

Никогда не коммить node_modules и .env — первое огромное и восстанавливается автоматически, второе секретное.

🏋️ Практика

  1. Создай аккаунт на github.com (если нет)
  2. В терминале в папке проекта: git init → git add . → git commit -m "First commit"
  3. Создай репозиторий на GitHub, скопируй URL
  4. git remote add origin https://github.com/username/repo.git
  5. git push -u origin main
  6. Открой GitHub — твой код там

10. npm — менеджер пакетов

Что это

npm (Node Package Manager) — магазин готового кода. 2+ миллиона пакетов: от React до библиотеки для отправки email.

Основные команды

npm init                    # Инициализировать новый проект (создаёт package.json)
npm install                 # Установить все зависимости из package.json
npm install grammy          # Установить конкретный пакет
npm install -D typescript   # Установить как dev-зависимость
npm uninstall grammy        # Удалить пакет
npm run dev                 # Запустить скрипт «dev» из package.json
npm run build               # Собрать проект для продакшена

package.json — паспорт проекта

Самый важный файл в любом Node.js проекте:

{
  "name": "my-shop",
  "version": "1.0.0",
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint"
  },
  "dependencies": {
    "next": "^14.0.0",
    "react": "^18.2.0",
    "@supabase/supabase-js": "^2.38.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}

dependencies — пакеты для работы приложения. devDependencies — пакеты только для разработки (TypeScript, линтеры).

package-lock.json

Фиксирует точные версии всех пакетов. Гарантирует одинаковые версии у тебя и на сервере. Коммитится в Git, но не редактируется вручную.

node_modules

Папка со скачанными пакетами. Может весить сотни мегабайт. Не коммитится в Git — восстанавливается командой npm install.

Альтернативы

  • pnpm — быстрее, экономит место на диске
  • yarn — от Facebook, параллельная установка
  • bun — сверхбыстрый, заменяет и npm, и Node.js

🏋️ Практика

  1. Зайди в папку своего Next.js проекта
  2. Открой package.json — найди секции scripts, dependencies
  3. Выполни npm run dev — это запустит скрипт next dev из package.json
  4. Установи пакет: npm install dayjs — библиотека для работы с датами
  5. Открой package.json снова — увидишь dayjs в dependencies

11. Файл .env — секреты проекта

Что это

Файл с переменными окружения (environment variables). Хранит всё, что нельзя класть в код: API-ключи, пароли, строки подключения к базе.

Пример .env.local

# База данных
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

# AI
ANTHROPIC_API_KEY=sk-ant-api03-...

# Платежи
STRIPE_SECRET_KEY=sk_live_...

# Email
RESEND_API_KEY=re_...

Правила

1. Никогда не коммить в Git. Добавь .env.local в .gitignore. Если ты случайно закоммитил API-ключ — считай его скомпрометированным. Пересоздай.

2. Разные файлы для разных сред. .env.local для разработки на твоём компьютере, переменные в Vercel Dashboard для продакшена.

3. Public vs Secret. В Next.js переменные доступны на фронте (в браузере пользователя) только если начинаются с NEXT_PUBLIC_:

# Только на сервере (безопасно)
ANTHROPIC_API_KEY=sk-ant-...

# Видно и в браузере (публично)
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co

Не добавляй NEXT_PUBLIC_ к секретным ключам — они станут видны всем.

Как использовать в коде

const apiKey = process.env.ANTHROPIC_API_KEY;
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;

Где хранить для продакшена

  • Vercel — Dashboard → Settings → Environment Variables
  • GitHub Actions — Settings → Secrets
  • Supabase — Edge Functions → Secrets

🏋️ Практика

  1. Создай файл .env.local в корне проекта
  2. Добавь: NEXT_PUBLIC_APP_NAME=My First App
  3. В page.tsx используй: <h1>{process.env.NEXT_PUBLIC_APP_NAME}</h1>
  4. Перезапусти npm run dev (переменные читаются при старте)
  5. Проверь, что .env.local есть в .gitignore

12. Спека (ТЗ) — что строим и зачем

Что такое спека

Спека (спецификация, ТЗ, PRD) — документ, который описывает что нужно построить, для кого и зачем. Без спеки разработка превращается в «а давай ещё вот это добавим» бесконечно.

Минимальная структура

1. Проблема — что сейчас не так?

Клиенты интернет-магазина не могут отследить статус доставки. Менеджеры тратят 2 часа в день на ответы в мессенджерах.

2. Решение — что строим?

Личный кабинет: история заказов, трекинг доставки, повторный заказ.

3. Целевая аудитория — для кого?

Существующие клиенты, 500-1000 человек, регулярные покупатели.

4. Функциональные требования — что конкретно должно работать?

  • Авторизация через email + magic link
  • Список заказов с фильтрами по дате и статусу
  • Детали заказа: состав, стоимость, трекинг-номер
  • Повторный заказ одной кнопкой

5. Нефункциональные требования — как должно работать?

  • Загрузка < 2 секунды
  • Мобильная адаптация
  • Мультиязычность (RU/EN)

6. Метрики успеха — как понять, что получилось?

  • 50% клиентов зарегистрировались за месяц
  • Время ответа менеджеров сократилось на 40%

Спека для AI

Когда работаешь с Claude Code или v0, спека — это твой промпт. Чем детальнее — тем точнее результат. Вместо «сделай каталог» пиши: «Сделай страницу каталога с сеткой 3 колонки, фильтрами по категориям слева, сортировкой по цене/новизне, карточки с фото, названием и ценой в рублях, по клику — модальное окно с деталями».

🏋️ Практика

  1. Выбери проект, который хочешь построить (магазин, блог, дашборд, бот)
  2. Напиши спеку по шаблону выше — 1 страница максимум
  3. Отдай спеку AI (Claude, ChatGPT): «Вот спека моего проекта. Разбей на этапы разработки и предложи структуру файлов для Next.js»
  4. Сравни результат — насколько детальная спека влияет на качество ответа
