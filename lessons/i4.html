ИИ для разработчиков: вне Cursor и Copilot

Цель: расширить use cases AI в разработке за пределы автодополнения кода Время: ~55 минут

Зачем тебе этот урок

Cursor и Copilot ты уже используешь. Но «ИИ для разработчика» — это куда больше: код-ревью, миграции, документация, отладка, рефакторинг, навигация по большому коду. Этот урок — про инструменты и приёмы, которые удваивают производительность после базового AI-autocomplete.

2. Терминальные агенты — следующий уровень

Claude Code, Aider, OpenHands — это не «чат в IDE». Это агент в твоём терминале, который читает репозиторий, делает изменения, запускает тесты, исправляет ошибки.

Реальный workflow:

# В терминале репозитория:
claude

# Дальше — диалог:
> Перепиши все вызовы fetch() на нашу обёртку httpClient в файлах src/.

# Claude читает файлы, делает изменения, запускает тесты, показывает дифф.

Это решает задачи, которые в IDE-чате тяжелы: «миграция через 50 файлов», «найди все использования X и обнови», «почини все эти тесты».

3. Code review с ИИ

Личный chek-list: возьми свой PR → отправь в Claude/GPT:

Дифф моего PR: [diff]
Контекст: [что я делаю и зачем]

Проверь:
1. Логические ошибки.
2. Edge cases, которые я не учёл.
3. Production-риски (race conditions, deadlocks, утечки).
4. Стиль кода (не соответствует ли соседним файлам).
5. Тесты — что я не покрыл.
6. Безопасность (SQL injection, XSS, утечки данных).
7. Performance — где O(n²) или N+1.

Каждый пункт с примером из моего кода.

На команду: CodeRabbit или Copilot Reviews. Авто-комменты на каждый PR. Качество ~70% полезных комментов; остальное — шум, который ты учишься игнорировать.

4. Документация

«Сгенерируй README» работает плохо. Работает по-другому:

Я хочу написать раздел README про [feature].

Вот ключевые файлы реализации: [paste code].

Сделай:
1. Краткое описание (1 абзац) — что это и зачем.
2. Quick start (5–7 строк).
3. Полный пример с typical use case.
4. Список параметров с типами и дефолтами.
5. Известные ограничения и troubleshooting.

Стиль: примеры с конкретикой, не общие фразы.

5. Дебаг через ИИ

Классический паттерн «вставить ошибку, спросить, что не так» — работает. Лучше:

Стек трейс: [paste]
Контекст: что я делал когда упало.

Релевантные файлы: [paste 2–3 файла, где, по-моему, проблема]

Логи перед ошибкой: [paste].

1. Что произошло (твой best guess).
2. 3 наиболее вероятные причины — от наиболее вероятной к менее.
3. Для каждой — как проверить.
4. Что чинит проблему, если причина X.

Это убирает 90% «попугаев», когда ты копи-пастишь ошибки.

6. Большие миграции

Реальный кейс: «перевести 200 файлов с Class Components на Hooks в React».

  1. Сначала — стратегия. Спроси Claude: «вот один файл, покажи мне рецепт миграции — какие паттерны, какие проблемы».
  2. Утверди рецепт.
  3. Claude Code или Aider в режиме «применить ко всем файлам по очереди» с твоим утверждённым рецептом.
  4. Запускать тесты после каждого файла.
  5. Ты ревьюешь diff, а не пишешь код.

7. Навигация в большом коде

Зашёл в новый проект, 200k строк. Раньше — неделя на onboarding. Сейчас:

Sourcegraph Cody / Cursor с @codebase:

> Где в коде реализована логика отмены подписки?
> Какие сервисы зависят от модуля payments?
> Объясни поток данных от формы регистрации до сохранения в БД.

8. Производственные приёмы

  • Promtbook. Сохраняй свои топ-промпты в notion/markdown. Это твой главный технический актив.
  • System prompt для своего стиля. Описание твоего стандарта кода + примеры → каждый ответ будет в твоём стиле.
  • Claude Projects с прикреплённой документацией твоего проекта — выгоднее, чем каждый раз объяснять контекст.
  • Vector-search над репозиторием (LlamaIndex) — для большого кодбейза.
  • Двухмодельная стратегия. Дешёвая для автодополнения, дорогая для архитектурных вопросов.

9. Чего избегать

  • «AI напишет всю фичу с нуля» — кончается багами, которые ты не понимаешь.
  • Принимать предложения без чтения. Особенно security-критичный код. Реальные случаи: AI вставил eval(), AI отключил CSRF проверку «для упрощения».
  • Загружать секреты в публичный chat. API ключи, токены, продакшен-конфиги.
  • Игнорировать корпоративные политики. Многие компании запрещают копировать код в публичные модели.
  • Слепо верить тестам, которые AI же написал. Часто они тестируют то, что есть, а не то, что должно быть.

10. Метрика, которую стоит мерять

«AI экономит мне N часов в неделю» — туманно. Лучше:

  • Время на типовую задачу до и после.
  • Количество PR в неделю — личный или командный.
  • Время на onboarding нового человека в проект.
  • Качество (баги в проде) — не растёт ли?

11. Тонкости

  • Cursor vs Copilot: Cursor лучше для агентских задач, Copilot — для inline-автодополнения.
  • Claude Sonnet 4.5 — топ для серьёзного кода в 2026 (лидер SWE-Bench Verified). GPT-5 — для широты и скорости. Haiku 4.5 / GPT-5 mini — для дешёвого автодополнения.
  • Большие репо. Inline-инструменты с @codebase работают через embeddings, могут пропустить релевантные файлы. Проверяй.
  • Open-source альтернативы: Continue.dev (бесплатный заменитель Cursor), Aider (open-source аналог Claude Code).

12. Глоссарий

Inline-помощник

AI в редакторе с автодополнением и чатом. Cursor, Copilot, Continue.

Терминальный агент

AI в терминале, действующий через файловую систему и git. Claude Code, Aider.

Codebase-aware

AI-инструмент, индексирующий весь твой репозиторий и понимающий контекст.

Promtbook

Твоя личная или командная коллекция отлаженных промптов для рутинных задач.

13. Практика (55 минут)

  1. Установи Claude Code или Aider в один из своих репо.
  2. Дай ему задачу из 5+ файлов — «сделай рефакторинг X».
  3. Сделай code-review своему последнему PR через промпт выше.
  4. Создай Claude Project с документацией твоего основного проекта.
  5. Запиши в progress.md — что новое в твоём workflow.

14. Проверь себя

1. Чем терминальный агент отличается от IDE-чата?
Действует через файловую систему, может править несколько файлов и запускать команды. IDE-чат — один файл за раз.

2. Какой паттерн для больших миграций?
Утвердить рецепт на одном файле → агент применяет к остальным → ты ревьюешь diff, а не пишешь код.

3. Где ИИ опасен в разработке?
Security-критичный код, прод-конфиги, секреты, слепое принятие тестов AI.

4. Что такое promtbook и зачем?
Личная/командная коллекция отлаженных промптов — твой главный AI-актив.

15. Что должно остаться в голове

  1. AI в разработке — это не только автодополнение. Терминальные агенты + code review + миграции + дебаг.
  2. Claude Code / Aider — для многошаговых правок через файловую систему.
  3. CodeRabbit / Copilot Reviews — авто-комменты на PR.
  4. Промпт-инжиниринг + promtbook + Claude Projects = твой основной актив.
  5. Двухмодельная стратегия экономит деньги.
  6. Безопасность: не вставляй секреты, читай diff перед принятием.
