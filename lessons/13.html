Урок 13. Function Calling — ИИ вызывает твои функции

Цель: понять как работает Function Calling и почему это строительный блок агентов Время: ~45 минут Источник: generative-ai-for-beginners/11

Зачем тебе этот урок

В Фазе 1 ты научился разговаривать с LLM: задавать вопросы, получать ответы, писать промпты. Но у такой модели есть потолок: LLM живёт в своём пузыре — она не знает текущую погоду, не умеет запросить твою базу данных, не может отправить email. И даже если ты просишь вернуть структурированный JSON, каждая модель форматирует его по-своему.

Function Calling — механизм, который закрывает обе проблемы разом:

  1. LLM возвращает строго структурированные данные — никаких сюрпризов с форматом.
  2. LLM может «попросить» выполнить реальное действие во внешнем мире — погода, поиск, база данных, отправка сообщения.

Это архитектурный сдвиг: ты переходишь от чат-бота, который отвечает на вопросы, к агенту, который действует. Function Calling — фундамент всех агентных систем.

1. Проблема, которую решает Function Calling

Представь: ты хочешь сделать бота для HR-отдела. Бот принимает резюме и должен занести данные в CRM: имя, должность, опыт, зарплатные ожидания.

До Function Calling GPT-4 вернёт {"name": "Алексей", "experience": 5}, Claude вернёт {"full_name": "Иванов Алексей", "years": "5 лет"}, Mistral добавит пояснительный текст вокруг JSON. Три модели — три разных ключа, разные типы данных. Твой код упадёт с ошибкой.

После Function Calling ты один раз описываешь схему — и все модели возвращают строго её.

2. Ментальная модель: LLM — диспетчер, а не исполнитель

Ключевое заблуждение: «LLM вызывает функцию». Это неправда. LLM не умеет выполнять код. Она только производит текст.

Что происходит на самом деле:

[Ты] → описываешь функции + вопрос пользователя → [LLM]
[LLM] → возвращает: "вызови функцию X с аргументами Y" → [Ты]
[Ты] → вызываешь настоящую функцию X(Y) → получаешь результат
[Ты] → передаёшь результат обратно → [LLM]
[LLM] → формулирует ответ для пользователя → [Ты]

LLM — умный диспетчер. Она не делает работу сама, но знает, кому передать задачу и с какими параметрами. Реальную работу делает твой код.

3. Анатомия Function Calling: три шага

Шаг 1. Ты описываешь функции

Перед запросом к LLM ты передаёшь список функций в виде JSON-схем. Схема — это описание: как называется функция, что делает, какие принимает параметры.

{
  "name": "get_weather",
  "description": "Получить текущую погоду в городе",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "Название города, например: Москва"
      }
    },
    "required": ["city"]
  }
}

Это просто описание на языке JSON — инструкция для LLM, не настоящий код.

Шаг 2. LLM решает, нужна ли функция

Пользователь пишет «Какая сейчас погода в Казани?» — LLM смотрит на список функций и возвращает:

{
  "function_call": {
    "name": "get_weather",
    "arguments": { "city": "Казань" }
  }
}

Если пользователь пишет «Как дела?» — LLM просто ответит текстом, функция не нужна.

Шаг 3. Ты выполняешь реальный вызов и возвращаешь результат

Твой код (не LLM!) берёт имя функции и аргументы, вызывает настоящий API, получает данные и передаёт обратно в LLM. LLM формулирует финальный ответ для пользователя.

5. Важные нюансы

Function Calling ≠ Tool Use (но это одно и то же)

OpenAI называет это Function Calling (старое API) и Tool Use (новое). Anthropic (Claude) называет это Tool Use. Принцип идентичный — просто разные названия в документации.

Безопасность: не доверяй аргументам слепо

LLM передаёт тебе аргументы для функции — но она может ошибиться или быть обманута через prompt injection. Всегда валидируй аргументы перед выполнением, особенно если функция делает что-то необратимое.

Один запрос может потребовать несколько функций

«Найди курсы по Python и запиши меня на лучший» — это два действия. Современные LLM умеют вызывать несколько функций подряд (parallel tool calls).

6. Практика: бот с двумя инструментами

pip install openai
import json
from openai import OpenAI

client = OpenAI(api_key="твой-ключ")

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Получить текущую погоду в городе",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "Название города"}
                },
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "send_email",
            "description": "Отправить email сообщение",
            "parameters": {
                "type": "object",
                "properties": {
                    "to": {"type": "string"},
                    "subject": {"type": "string"},
                    "body": {"type": "string"}
                },
                "required": ["to", "subject", "body"]
            }
        }
    }
]

def get_weather(city):
    data = {"Москва": {"temp": 20, "condition": "солнечно"},
            "Казань": {"temp": 18, "condition": "облачно"}}
    w = data.get(city, {"temp": 15, "condition": "неизвестно"})
    return json.dumps({"city": city, **w}, ensure_ascii=False)

def send_email(to, subject, body):
    print(f"📧 Email → {to}: {subject}")
    return json.dumps({"status": "sent"})

available_functions = {"get_weather": get_weather, "send_email": send_email}

def run_agent(user_message):
    messages = [{"role": "user", "content": user_message}]
    response = client.chat.completions.create(
        model="gpt-4o-mini", messages=messages, tools=tools, tool_choice="auto"
    )
    message = response.choices[0].message
    while message.tool_calls:
        messages.append(message)
        for tc in message.tool_calls:
            result = available_functions[tc.function.name](
                **json.loads(tc.function.arguments)
            )
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": result})
        response = client.chat.completions.create(
            model="gpt-4o-mini", messages=messages, tools=tools, tool_choice="auto"
        )
        message = response.choices[0].message
    return message.content

print(run_agent("Проверь погоду в Питере и если дождь — предупреди boss@example.com"))

7. Связь с другими уроками

Урок 14 (RAG): функция поиска по векторной БД станет одним из инструментов агента. Урок 16 (Агенты): тот самый while message.tool_calls — это и есть агентный цикл. Урок 28 (MCP): стандартный протокол для подключения инструментов — Function Calling, возведённый в стандарт.

Когда Claude в Cowork вызывает Notion или Asana — это ровно тот же механизм Tool Use. Принцип один везде.
