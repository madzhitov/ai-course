Урок 8. Поиск с эмбеддингами (semantic search)

Цель: понять как ИИ ищет «по смыслу» и сделать свой semantic-поисковик Время: ~60 минут Источник: generative-ai-for-beginners/08

Зачем тебе этот урок

Обычный поиск ищет совпадения слов. Если у тебя в заметках есть запись «как корректно расстаться с компанией», а ты ищешь «как уволиться без скандала» — обычный grep ничего не найдёт. Semantic search найдёт, потому что понимает смысл.

Это фундаментальная техника:

  • Под капотом RAG (урок 14) — самой популярной паттерны для работы с документами.
  • Поиск по своим заметкам, тикетам, документам.
  • Дедупликация (найти похожие вопросы в FAQ).
  • Кластеризация (группировка отзывов по темам).
  • Рекомендации.

К концу урока у тебя будет рабочий поисковик по твоим собственным заметкам, понимающий запросы на естественном языке.

1. Что такое embedding

Идея

Embedding (эмбеддинг, векторное представление) — это превращение текста в массив чисел фиксированной длины, отражающий смысл этого текста. Тексты с близким смыслом имеют близкие векторы; разные — далёкие.

Длина вектора зависит от модели:

  • text-embedding-3-small — 1536 чисел.
  • text-embedding-3-large — 3072 числа.
  • BGE-M3 — 1024.
  • Старая text-embedding-ada-002 — 1536.

Упрощённое представление

Представь, что ты строишь координатную систему смыслов. Каждый текст — точка в этом пространстве. Похожие смыслы — рядом.

"Я хочу есть"        → [0.21, -0.45, 0.12, ...]   (1536 чисел)
"Хочу пиццу"         → [0.20, -0.43, 0.15, ...]   (близко)
"Голоден"            → [0.22, -0.44, 0.10, ...]   (близко)
"Где Эйфелева башня" → [-0.50, 0.31, -0.20, ...]  (далеко)
"Париж — столица"    → [-0.48, 0.30, -0.22, ...]  (далеко от еды, близко к башне)

Конечно реальные числа намного сложнее и не интерпретируемы напрямую — каждое из 1536 «измерений» отвечает за какой-то смысловой аспект, выученный моделью на огромном корпусе.

Откуда берутся эмбеддинги

Тренируются специальные модели (отдельные от chat-моделей):

  • OpenAI: text-embedding-3-small/large.
  • Open-source: BGE, E5, Sentence Transformers, BERT.
  • Cohere: embed-multilingual-v3.
  • Google: text-embedding-005.

Под капотом это нейросеть-трансформер, которая пропускает текст через свои слои и выдаёт вектор. Принцип: текст подаётся на вход, выход последнего слоя усредняется и нормализуется.

2. Косинусное сходство — как мерить «близость» векторов

Когда у нас есть векторы — нам нужна метрика близости. Стандарт — cosine similarity.

Формула на пальцах

Косинус угла между двумя векторами. Значения от -1 до 1:

  • 1.0 — векторы совпадают (одинаковый смысл).
  • 0.7–0.9 — близкий смысл.
  • 0.3–0.6 — связанные темы.
  • 0.0 — не связаны.
  • -1.0 — противоположны (редко на эмбеддингах текста).

Реализация на Python

import numpy as np

def cosine_similarity(a, b):
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# или, если векторы уже нормализованы (как у OpenAI):
# просто скалярное произведение
def dot(a, b):
    return sum(x*y for x, y in zip(a, b))

Альтернативные метрики

  • Euclidean distance — евклидово расстояние. Работает, но cosine обычно лучше для текста.
  • Dot product — для нормализованных векторов = cosine. Быстрее.
  • Manhattan — почти не используется для текста.

3. Pipeline semantic search

Стандартная схема (для всех векторных систем):

┌─────────────────┐    ┌──────────┐    ┌──────────────┐    ┌──────────┐
│ Документы (.md, │ -> │ Chunking │ -> │ Embedding    │ -> │ Vector   │
│ pdf, txt, ...)  │    │          │    │ model        │    │ DB       │
└─────────────────┘    └──────────┘    └──────────────┘    └──────────┘

                                                                │
                            запрос пользователя                  │
                                    │                            │
                                    ▼                            │
                            ┌──────────────┐                     │
                            │ Embedding    │                     │
                            │ model        │                     │
                            └──────────────┘                     │
                                    │                            │
                                    ▼                            │
                            ┌──────────────────────────────────┐ │
                            │ Поиск ближайших по cosine sim    │◄┘
                            └──────────────────────────────────┘
                                    │
                                    ▼
                            топ-K результатов

Этапы

1. Chunking — нарезка документов.

Документ редко влезает целиком в эмбеддинг. Нарезаем на куски по 200–800 токенов с небольшим перекрытием (50 токенов overlap), чтобы не разрывать важные связи.

2. Embedding — превращение в векторы.

Каждый chunk прогоняем через embedding-модель.

3. Storage — хранение в векторной БД.

Сохраняем (id, embedding, original_text, metadata).

4. Query — поиск.

Эмбеддим запрос, ищем top-K ближайших chunks по cosine.

5. Return — отдаём пользователю.

Возвращаем найденные тексты + score близости.

5. Полный пример с Chroma

pip install chromadb openai
from openai import OpenAI
import chromadb

client = OpenAI()
chroma = chromadb.PersistentClient(path="./chroma_db")
collection = chroma.get_or_create_collection("notes")

def embed(text: str) -> list[float]:
    """Получить эмбеддинг текста через OpenAI."""
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return response.data[0].embedding

# 1. Индексация заметок
notes = [
    "Сегодня встретился с Иваном, обсудили сроки запуска MVP.",
    "Купить корм коту, заехать в зоомагазин в среду.",
    "Идея: сервис для автоматической генерации тестов из ТЗ.",
    "Дед-лайн по статье — пятница.",
    "Почитать про векторные базы данных.",
    "В четверг забрать ребёнка из садика в 17:00.",
    "TODO: написать ответ HR в Лаборатории Касперского."
]

# Эмбеддим и кладём в Chroma
embeddings = [embed(note) for note in notes]
collection.add(
    ids=[f"note_{i}" for i in range(len(notes))],
    embeddings=embeddings,
    documents=notes
)

# 2. Поиск
def search(query: str, k: int = 3):
    query_emb = embed(query)
    results = collection.query(
        query_embeddings=[query_emb],
        n_results=k
    )
    return list(zip(results["documents"][0], results["distances"][0]))

# Пробуем
print(search("что мне нужно купить?"))
# → найдёт «корм коту»

print(search("какие у меня дед-лайны?"))
# → найдёт «статья пятница» и MVP

print(search("задачи связанные с детьми"))
# → найдёт «забрать ребёнка»

print(search("есть ли у меня вакансии или офферы?"))
# → найдёт «HR в Лаборатории Касперского»

Заметь — в каждом случае модель находит правильный chunk, хотя прямых совпадений слов нет.

6. Стратегии чанкинга

Простая нарезка

def chunk_text(text: str, chunk_size: int = 500, overlap: int = 50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    return chunks

Минус — режет посередине предложения.

По параграфам

chunks = text.split("\n\n")

Натуральные границы, но размеры разные.

По смыслу (рекомендуется)

Используй RecursiveCharacterTextSplitter из LangChain или его аналог:

def smart_chunk(text, max_size=500):
    # сначала по параграфам, потом по предложениям, потом по словам
    paragraphs = text.split("\n\n")
    chunks = []
    current = ""
    for p in paragraphs:
        if len(current) + len(p) <= max_size:
            current += "\n\n" + p
        else:
            if current: chunks.append(current.strip())
            if len(p) > max_size:
                # длинный параграф — режем по предложениям
                sentences = p.split(". ")
                ...
            else:
                current = p
    if current: chunks.append(current.strip())
    return chunks

Размер chunk — компромисс

  • Маленькие (~100 токенов) — точный поиск, но теряется контекст.
  • Средние (~500) — стандарт.
  • Большие (~2000) — широкий контекст, но смешивает темы.

Для большинства задач 500 + overlap 50 — рабочая точка.

7. Hybrid search — комбо semantic + keyword

Иногда semantic пропускает запросы, где важно точное слово (имя продукта, артикул, аббревиатура). Hybrid search комбинирует:

  • Semantic (эмбеддинги) — для смысла.
  • BM25 / keyword — для точных совпадений.
  • Reranking — пересортировка финальных результатов второй моделью (cross-encoder).

Поддерживается в Weaviate, Qdrant, Elasticsearch + плагины. Для прода почти всегда выигрывает у чистого semantic.

8. Стоимость эмбеддингов

Цены OpenAI:

  • text-embedding-3-small: $0.02 / 1M токенов input.
  • text-embedding-3-large: $0.13 / 1M.

Реально:

  • Эмбеддинг 1000 заметок по 200 токенов = 200k токенов = $0.004. Копейки.
  • Эмбеддинг целой Wikipedia (~3 миллиарда токенов) = $60.

Однажды эмбеддишь — потом только запросы. Запрос — 1 эмбеддинг = ~50 токенов = $0.000001. Очень дёшево.

9. Open-source эмбеддинги

Если не хочешь платить или нужна приватность — open-source модели через sentence-transformers:

10. Тонкости и подводные камни

Метаданные

Сохраняй вместе с эмбеддингами полезные метаданные — потом можно фильтровать:

collection.add(
    ids=["note_1"],
    embeddings=[emb],
    documents=[note],
    metadatas=[{"date": "2026-05-04", "tag": "work", "author": "me"}]
)

# Поиск с фильтром
collection.query(
    query_embeddings=[q_emb],
    n_results=5,
    where={"tag": "work"}
)

Несовпадение моделей при поиске

Если эмбеддил коллекцию моделью X, а ищешь моделью Y — результаты будут полным мусором. Векторные пространства разных моделей несовместимы. Запиши в metadata, какой моделью эмбеддил.

Multilingual проблемы

Не все embedding-модели хорошо работают на русском. Хорошие на русском:

  • OpenAI text-embedding-3-* — отлично.
  • BGE-M3 — отлично, мультиязычно.
  • multilingual-e5-large — отлично.
  • cohere multilingual-v3 — отлично.

Старая ada-002 на русском была слабее, но всё ещё рабочая.

Когда semantic проигрывает

  • Поиск по точным артикулам, ID, кодам.
  • Очень короткие запросы (1–2 слова).
  • Тексты на узком жаргоне, где модель не училась.

Решение — hybrid search (см. секция 7).

Скейл

Cosine similarity между N векторами и одним запросом — O(N). При 1M документов это ~100ms на CPU. Для бо́льших объёмов — приближённый поиск (ANN — Approximate Nearest Neighbor): HNSW, IVF. Все нормальные векторные БД делают это автоматически.

11. Глоссарий

  • Embedding — числовой вектор, представляющий смысл текста.
  • Cosine similarity — мера близости двух векторов (-1...1).
  • Chunk — кусок исходного документа.
  • Chunking — стратегия нарезки документов.
  • Vector DB — хранилище векторов с быстрым поиском.
  • k-NN — k-Nearest Neighbors, поиск k ближайших.
  • ANN — Approximate Nearest Neighbor, быстрый приближённый поиск.
  • HNSW — Hierarchical Navigable Small World, популярный ANN-алгоритм.
  • BM25 — классический keyword-алгоритм.
  • Hybrid search — combo semantic + keyword.
  • Reranking — пересортировка результатов второй моделью.
  • Cross-encoder — модель для reranking, оценивает пару (query, doc).
  • Sentence Transformers — Python-библиотека для embedding-моделей.

12. Практика (60 минут)

Упражнение 1. Свой semantic-поисковик (25 минут)

  1. Возьми 30–50 своих заметок (Obsidian export, txt-файлы, копипаст).
  2. Создай скрипт indexer.py: читает все файлы, разбивает на чанки (по параграфам), эмбеддит и кладёт в Chroma.
  3. Создай search.py: принимает запрос, выводит топ-3 релевантных заметок.
  4. Поиграйся: задавай вопросы на естественном языке, не используя слова из самих заметок.

Упражнение 2. Сравни с grep (10 минут)

  1. Возьми 5 запросов от упр. 1.
  2. Для каждого попробуй также найти через grep по ключевым словам.
  3. Сравни: где semantic умнее? Где grep точнее?

Упражнение 3. Local embedding (15 минут)

  1. Установи sentence-transformers.
  2. Перепиши indexer.py с локальной BGE-M3.
  3. Сравни время и качество с OpenAI-версией.

Упражнение 4. Метаданные и фильтры (10 минут)

  1. В indexer.py добавь metadata: дата создания файла, имя файла, размер.
  2. В search.py добавь фильтр: «только за последний месяц», «только из такого-то файла».

13. Проверь себя

1. Что такое embedding одним предложением?
Числовой вектор фиксированной длины, представляющий смысл текста. Близкие смыслы = близкие векторы.

2. Почему semantic search умнее keyword?
Понимает синонимы, перефразировки, смысловые связи. Находит «купить корм коту» по запросу «что нужно купить».

3. Зачем чанкать документы перед эмбеддингом?
(а) Документ не влезает целиком (лимит embedding-модели). (б) Маленькие куски дают точный поиск. (в) Гранулярность результатов — пользователь видит релевантный кусок, а не всю книгу.

4. Какая мера близости используется?
Cosine similarity (косинус угла). Для нормализованных векторов эквивалентно скалярному произведению.

5. Назови 3 векторные БД.
Chroma, Qdrant, Pinecone (или Weaviate, pgvector, Milvus, LanceDB, FAISS).

6. Я эмбеддил коллекцию ada-002. Можно искать в ней с text-embedding-3-small?
Нет. Векторные пространства разных моделей несовместимы — поиск выдаст мусор. Нужно переэмбеддить всё одной моделью.

7. Стандартный размер chunk?
500 токенов с overlap 50. Зависит от задачи: для точного поиска факта — меньше (~200), для широкого контекста — больше (~1000).

8. Когда нужен hybrid search?
Когда важны точные совпадения (артикулы, имена, аббревиатуры) И смысл одновременно. Чистый semantic иногда пропускает важные точные совпадения.

9. Что такое ANN и зачем?
Approximate Nearest Neighbor — приближённый поиск ближайших векторов. Жертвует точностью ради скорости. Нужен при объёме >100k векторов, иначе линейный поиск медленный.

10. Бесплатные embedding-модели для русского?
BGE-M3, multilingual-e5-large — обе через sentence-transformers, работают локально, качество как у OpenAI.

14. Что должно остаться в голове

  1. Embedding — вектор смысла. База всего semantic-мира.
  2. Cosine similarity — стандартная мера близости.
  3. Pipeline: chunks → embed → vector DB → query embed → top-K.
  4. Chroma для прототипов; Qdrant / pgvector для прода.
  5. Chunking 500 + overlap 50 — рабочая точка.
  6. Hybrid search побеждает чистый semantic в проде.
  7. OpenAI embeddings для удобства; BGE-M3 для приватности и экономии.
  8. Метаданные в БД для фильтров — обязательно.
