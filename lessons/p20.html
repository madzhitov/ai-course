Проект «За 1 час»: AI-помощник продавца Wildberries на YandexGPT

Что построим: скрипт, который по фото товара генерирует готовую карточку для WB и загружает её через Seller API Время: ~90 минут Уровень: Python + базовое понимание REST API Стек: Python 3.10+, requests, YandexGPT API, WB Content API

Что в итоге будет

CLI-утилита, которая:

  • Принимает на вход путь к папке с фото товара и краткое описание («синие женские джинсы, размер 42-50, состав хлопок 98%»);
  • Отдаёт фото + описание в YandexGPT с правильным промптом;
  • Получает готовую карточку: заголовок до 60 символов, описание до 1000 символов, характеристики, ключевые слова;
  • Формирует валидный JSON под WB Content API и (опционально) загружает карточку в личный кабинет продавца;
  • Поддерживает батч-режим: одна команда — папка из 20 товаров — 20 карточек.

Целевой пользователь — селлер с десятками или сотнями SKU, который вручную час сидит над каждой карточкой. После этой утилиты — 30 секунд на товар.

Требования

  • Аккаунт в Yandex Cloud с привязанной картой (любая РФ-карта). Оплата в рублях, по факту использования. Стартовый грант обычно ~4000 ₽;
  • Аккаунт продавца на Wildberries с доступом в «Личный кабинет поставщика»;
  • Python 3.10+, библиотеки requests и python-dotenv;
  • Фотографии товаров — минимум 1, лучше 3–5 ракурсов.

Шаг 1: Yandex Cloud — каталог, сервисный аккаунт, API-ключ

  1. Идёшь в console.cloud.yandex.ru, логинишься через Яндекс ID.
  2. Если каталога нет — Yandex Cloud сам предложит создать. Привяжи карту. Включается биллинг.
  3. В меню слева — Identity and Access Management → Сервисные аккаунты → Создать. Имя wb-bot.
  4. Выдай этому сервисному аккаунту роль ai.languageModels.user на каталог. Без этой роли API будет отвечать 403.
  5. В карточке сервисного аккаунта — Создать новый ключ → API-ключ. Копируешь сразу, повторно не покажет.
  6. Запомни folder_id (он в URL консоли или в шапке каталога) — он нужен в каждом запросе.

Стоимость yandexgpt-lite: примерно 0.20 ₽ за 1000 токенов на вход и столько же на выход. Одна карточка — ~3000 токенов, итого меньше рубля. На 100 карточек — около 60–80 ₽. Это сильно дешевле, чем нанять копирайтера на ту же сотню.

Шаг 2: Токен Wildberries Seller API

  1. Заходишь в seller.wildberries.ru.
  2. Профиль (правый верхний угол) → Настройки → Доступ к API.
  3. Нажимаешь «Создать новый токен». Имя — например ai-card-generator.
  4. В правах выбираешь «Контент» (и опционально «Цены и скидки», если будешь обновлять цены). НЕ давай токену больше прав, чем нужно — если утечёт, ущерб меньше.
  5. Опция «Только для чтения» — снимаем (иначе не сможем создавать карточки).
  6. Копируешь токен. Это JWT-строка длиной ~150 символов.

Endpoint для создания карточек: https://content-api.wildberries.ru/content/v2/cards/upload. Документация — на dev.wildberries.ru, раздел «Контент».

Шаг 4: Промпт-шаблоны под категории

WB сильно разный по требованиям к категориям. Одежда любит размерную сетку и состав, электроника — точные ТТХ, дом — материал и габариты. Поэтому держим шаблоны в отдельных файлах и подгружаем по категории.

prompts/clothes.txt:

Ты — копирайтер маркетплейса. Сделай карточку товара для Wildberries по фото и описанию ниже.

Категория: ОДЕЖДА.

Жёсткие ограничения:
- "title": до 60 символов, начинается с типа товара (Джинсы, Платье, Футболка), без CAPS и без эмодзи
- "description": до 1000 символов, абзацами через 

. Структура: общее описание → состав и качество → для каких случаев → советы по уходу. Без слов "купить", "лучший", "идеальный" — WB не любит маркетинговую воду.
- "characteristics": массив объектов {"name": "...", "value": "..."}. Обязательные: "Состав", "Сезон", "Страна производства" (если не известна — пиши "Россия"). НЕ ВЫДУМЫВАЙ цифр. Если данных нет — оставь поле пустым.
- "keywords": массив из 10-15 слов для поиска, через которые товар найдут (без знаков препинания, lowercase).

Верни СТРОГО JSON по схеме. Никаких комментариев до или после.

Схема:
{
  "title": "string",
  "description": "string",
  "characteristics": [{"name": "string", "value": "string"}],
  "keywords": ["string"]
}

Аналогично electronics.txt (упор на ТТХ: мощность, напряжение, разъёмы) и home.txt (материал, размеры, вес, инструкция по сборке).

Главное правило промпта — «не выдумывай характеристики». Если модели не дать этого ограничения, она радостно напишет про джинсы «состав: хлопок 100%, плотность 320 г/м², пропитка водоотталкивающая» — даже если из фото видно только цвет.

Шаг 5: Вызов YandexGPT

Файл generator.py:

import os
import json
import base64
import logging
from pathlib import Path
import requests

log = logging.getLogger("generator")

YC_URL = "https://llm.api.cloud.yandex.net/foundationModels/v1/completion"


def _read_brief(item_dir: Path) -> str:
    brief = item_dir / "brief.txt"
    return brief.read_text(encoding="utf-8").strip() if brief.exists() else ""


def _encode_photos(item_dir: Path, max_n: int = 3) -> list[str]:
    """YandexGPT (text-only) фото не понимает — для multimodal нужен другой endpoint.
    Пока используем только описания фото (имена файлов как намёк)."""
    photos = sorted(p for p in item_dir.iterdir() if p.suffix.lower() in {".jpg", ".jpeg", ".png"})
    return [p.name for p in photos[:max_n]]


def generate_card(item_dir: Path, category: str = "clothes") -> dict:
    brief = _read_brief(item_dir)
    photo_names = _encode_photos(item_dir)

    prompt_file = Path("prompts") / f"{category}.txt"
    system_prompt = prompt_file.read_text(encoding="utf-8")

    user_text = (
        f"Описание от продавца:
{brief}

"
        f"Имена файлов фото (как доп. подсказка): {', '.join(photo_names)}"
    )

    body = {
        "modelUri": f"gpt://{os.getenv('YC_FOLDER_ID')}/yandexgpt-lite/latest",
        "completionOptions": {
            "stream": False,
            "temperature": 0.3,
            "maxTokens": 2000,
        },
        "messages": [
            {"role": "system", "text": system_prompt},
            {"role": "user", "text": user_text},
        ],
    }

    headers = {
        "Authorization": f"Api-Key {os.getenv('YC_API_KEY')}",
        "Content-Type": "application/json",
    }

    log.info(f"YandexGPT request for {item_dir.name}, category={category}")
    r = requests.post(YC_URL, json=body, headers=headers, timeout=60)
    r.raise_for_status()
    raw = r.json()["result"]["alternatives"][0]["message"]["text"]

    # YandexGPT иногда оборачивает JSON в ```json ... ```. Чистим.
    raw = raw.strip()
    if raw.startswith("```"):
        raw = raw.split("```")[1]
        if raw.startswith("json"):
            raw = raw[4:]
    raw = raw.strip()

    try:
        card = json.loads(raw)
    except json.JSONDecodeError as e:
        log.error(f"Не смог распарсить ответ как JSON: {raw[:500]}")
        raise

    # пост-валидация: title никогда не должен быть длиннее 60
    if len(card.get("title", "")) > 60:
        card["title"] = card["title"][:60].rsplit(" ", 1)[0]
    if len(card.get("description", "")) > 1000:
        card["description"] = card["description"][:1000].rsplit(" ", 1)[0] + "..."

    return card

Заметка про мультимодальность. У YandexGPT есть отдельная мультимодальная модель (yandexgpt-vision в visionai endpoint), которая принимает base64-картинки. Если хочется реального анализа фото — переключайся на неё, формат запроса похожий. Для большинства задач карточек хватает описания от продавца + имени файла (которое селлеры часто называют осмысленно: front.jpg, label.jpg).

Шаг 6: Загрузка карточки в WB

Файл wb_uploader.py:

import os
import json
import time
import logging
import requests

log = logging.getLogger("wb")

WB_UPLOAD = "https://content-api.wildberries.ru/content/v2/cards/upload"


def upload_card(card: dict, vendor_code: str, subject_id: int, brand: str, price_rub: int) -> dict:
    """
    vendor_code — твой внутренний артикул (любая строка).
    subject_id — числовой ID предмета (категории) в WB. Получается отдельным
                 запросом /content/v2/object/all (там список).
    """
    payload = [{
        "subjectID": subject_id,
        "variants": [{
            "vendorCode": vendor_code,
            "title": card["title"],
            "description": card["description"],
            "brand": brand,
            "dimensions": {"length": 30, "width": 20, "height": 5},  # см; ставь свои
            "characteristics": card.get("characteristics", []),
            "sizes": [{
                "techSize": "0",
                "wbSize": "",
                "price": price_rub,
                "skus": [vendor_code]
            }]
        }]
    }]

    headers = {
        "Authorization": os.getenv("WB_TOKEN"),
        "Content-Type": "application/json",
    }

    log.info(f"WB upload: vendorCode={vendor_code}, title={card['title']!r}")
    r = requests.post(WB_UPLOAD, json=payload, headers=headers, timeout=30)

    if r.status_code == 429:
        # rate limit — ждём и пробуем ещё раз
        log.warning("WB rate limit, sleep 30s")
        time.sleep(30)
        r = requests.post(WB_UPLOAD, json=payload, headers=headers, timeout=30)

    r.raise_for_status()
    return r.json()

Обрати внимание: токен WB кладётся в заголовок Authorization как есть, без префикса Bearer. Это нестандартно, но так у WB. Если поставишь Bearer — получишь 401 и долго будешь дебажить.

Шаг 7: Главный скрипт

Файл main.py:

import os
import json
import logging
import argparse
from pathlib import Path
from dotenv import load_dotenv

from generator import generate_card
from wb_uploader import upload_card

load_dotenv()
logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s: %(message)s")
log = logging.getLogger("main")


def process_one(item_dir: Path, category: str, upload: bool, brand: str, price: int, subject_id: int):
    log.info(f"=== {item_dir.name} ===")

    card = generate_card(item_dir, category=category)
    out = item_dir / "card.json"
    out.write_text(json.dumps(card, ensure_ascii=False, indent=2), encoding="utf-8")
    log.info(f"saved {out}")

    if upload:
        vendor_code = item_dir.name  # используем имя папки как артикул
        try:
            res = upload_card(card, vendor_code, subject_id, brand, price)
            log.info(f"WB ответ: {res}")
        except Exception as e:
            log.exception(f"WB upload failed for {item_dir.name}: {e}")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--goods-dir", default="goods", help="папка с подпапками-товарами")
    ap.add_argument("--category", default="clothes", choices=["clothes", "electronics", "home"])
    ap.add_argument("--brand", default="NoBrand")
    ap.add_argument("--price", type=int, default=1990)
    ap.add_argument("--subject-id", type=int, required=False, default=0,
                    help="ID категории WB (обязателен, если --upload)")
    ap.add_argument("--upload", action="store_true", help="реально загружать в WB")
    args = ap.parse_args()

    goods = Path(args.goods_dir)
    items = sorted(p for p in goods.iterdir() if p.is_dir())
    log.info(f"Найдено товаров: {len(items)}")

    for item in items:
        try:
            process_one(item, args.category, args.upload, args.brand, args.price, args.subject_id)
        except Exception as e:
            log.exception(f"Ошибка по {item.name}: {e}")


if __name__ == "__main__":
    main()

Запуск и проверка

Сначала генерим карточки без заливки (dry-run):

python main.py --goods-dir goods --category clothes

Скрипт пройдётся по всем подпапкам, для каждой создаст card.json рядом с фото. Открываешь, читаешь глазами. Если ок — заливаешь:

python main.py --goods-dir goods --category clothes   --upload --brand "MyBrand" --price 2490 --subject-id 192

subject-id ищется через отдельный GET-запрос на /content/v2/object/all с параметром name=джинсы. Сделай это один раз вручную через curl и запиши ID нужных категорий в табличку.

У меня на тесте: 12 товаров одежды → 12 карточек за 4 минуты. Загрузка в WB — ещё минута. Из 12 описаний 2 пришлось руками поправить (модель оба раза подзагнула состав ткани, потому что в brief.txt я этого не указал). Осальные 10 пошли как есть.

Расширения

  • Батч-обработка папки фото. Сейчас один товар = одна подпапка. Можно сделать обратный режим: одна большая папка с файлами вида джинсы-синие-001.jpg, скрипт сам группирует и парсит имя для brief.
  • Авто-обновление по тренду ключевиков. WB сам показывает в кабинете «популярные запросы по категории». Парсишь раз в неделю, скармливаешь YandexGPT и просишь переписать keywords и слегка description. Заметно бустит выдачу.
  • A/B-тестирование заголовков. Генеришь 3 варианта title, через WB API меняешь раз в неделю, смотришь конверсию в кабинете. Через месяц у тебя статистически лучший заголовок.
  • Мультимодальность. Переключи endpoint на yandexgpt-vision и шли реальные base64-фото. Тогда модель сможет описать цвет, фактуру, угол — особенно полезно для категорий вроде декора.
  • Чек на запрещёнку. Перед загрузкой прогоняешь карточку через второй промпт «есть ли тут запрещённые WB обещания: лечит, сертифицирован, гарантирует». Если да — флаг, ручная проверка.

Подводные камни

  • WB банит за враньё в характеристиках. Если карточка обещает «хлопок 100%», а покупатель получает синтетику — будут возвраты, штрафы и в худшем случае блокировка. Лучше пустое поле, чем выдуманное. Промпт это явно требует, но проверяй глазами.
  • YandexGPT любит «эссе» вместо JSON. Иногда возвращает «Вот ваш JSON: ```json {...} ```». Чищу через split — но если будет упорно срываться, добавь в промпт «не пиши ничего кроме JSON» дважды и понизь temperature до 0.1.
  • Rate limit WB API. На /cards/upload — 100 запросов в минуту, на остальных ручках бывает 10. Если льёшь сотни карточек — добавь time.sleep(0.7) между запросами. У меня в коде есть базовый ретрай на 429, но превентивно лучше не упираться.
  • subjectID разный для разных подкатегорий. «Женские джинсы» и «мужские джинсы» — разные ID. Не угадывай: получи список через API и держи у себя справочник.
  • Сезонность характеристик. Для одежды поле «Сезон» обязательное. YandexGPT иногда забывает добавить, особенно если в brief не указано. Сделай пост-валидацию: если поле отсутствует — добавляй "всесезонный" по умолчанию или возвращай товар на ручную обработку.
  • Картинки грузятся отдельно. /cards/upload только создаёт текстовую часть карточки. Фото льются другим endpoint'ом — /content/v3/media/save. Если хочешь полный цикл — добавь и это, но обычно фото удобнее заливать через web-кабинет (drag-n-drop там лучше).

Что в итоге

За полтора часа у тебя получился рабочий конвейер «фото и краткое описание → готовая карточка WB». Стоимость генерации одной карточки — меньше рубля. Времени экономишь — час на товар. На 100 товарах в месяц это уже окупает любой облачный сервис в десятки раз.

Технически ты потрогал два важных российских API: Yandex Cloud Foundation Models (это, по сути, продакшен-ready LLM-as-a-service от Яндекса) и Wildberries Content API (один из самых документированных marketplace API в РФ). Эти знания переиспользуются — от YandexGPT можно перейти к YandexART для генерации изображений, от WB к Ozon Seller API (он устроен похоже).

И главное — это первый честный пример того, как AI реально снимает рутину, а не «генерит контент ради контента». Тут есть конкретный селлер, конкретная задача и измеримая экономия времени.
