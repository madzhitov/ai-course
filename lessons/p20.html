Проект: AI-помощник продавца Wildberries на YandexGPT

Что построим: скрипт, который по фото товара генерирует готовую карточку для WB и загружает её через WB API Время: ~2 часа, из них до 30 минут WB сам создаёт карточку после загрузки Уровень: Python + базовое понимание REST API Стек: Python 3.10+, requests, Pillow, Yandex AI Studio (Qwen3.6 35B и YandexGPT Lite 5), WB API (категория «Контент»)

Что в итоге будет

CLI-утилита, которая:

  • Принимает на вход путь к папке с фото товара и краткое описание («синие женские джинсы, размер 42-50, состав хлопок 98%»);
  • Показывает фото модели Qwen3.6 35B, а то, что она увидела, вместе с описанием отдаёт в YandexGPT с правильным промптом;
  • Получает готовую карточку: заголовок до 60 символов, описание до 1000 символов, характеристики, ключевые слова;
  • Сопоставляет характеристики со справочником предмета WB и (опционально) загружает карточку в кабинет продавца через WB API;
  • Поддерживает батч-режим: одна команда — папка из 20 товаров — 20 карточек.

Целевой пользователь — селлер с десятками или сотнями SKU, который вручную час сидит над каждой карточкой. После этой утилиты — 30 секунд на товар.

Требования

  • Аккаунт в Yandex Cloud с платёжным аккаунтом и привязанной банковской картой. Оплата в рублях, по факту использования. Новым пользователям дают стартовый грант от 4000 ₽ на 60 дней, если привязать карту сразу при создании платёжного аккаунта;
  • Кабинет продавца Wildberries (портал WB Partners). Токен API может создать только владелец кабинета;
  • Python 3.10+, библиотеки requests, python-dotenv и Pillow;
  • Фотографии товаров: минимум 1, лучше 2-3 ракурса (скрипт отправляет модели первые три).

Шаг 1: Yandex AI Studio, API-ключ и каталог

Модели работают в Yandex AI Studio, это часть Yandex Cloud. Нужны две вещи: API-ключ и идентификатор каталога folder_id.

  1. Идёшь в aistudio.yandex.ru, логинишься через Яндекс ID. Если платёжного аккаунта ещё нет, создай его и сразу привяжи карту.
  2. В правом верхнем углу нажми Создать API-ключ, выбери срок действия ключа и нажми Создать. AI Studio сам заведёт сервисный аккаунт с нужными ролями и выдаст ключ с доступом к моделям.
  3. Скопируй секретный ключ сразу: после закрытия окна его не покажут.
  4. Запомни folder_id каталога, в котором создан ключ (он в URL консоли или в шапке каталога). Он нужен в каждом запросе.

Если создаёшь ключ вручную в консоли Yandex Cloud: сервисному аккаунту нужна роль ai.languageModels.user на каталог, а ключу область действия для генерации текста. В документации встречаются две: yc.ai.languageModels.execute и yc.ai.foundationModels.execute. Создать API-ключ может пользователь с ролью resource-manager.admin на каталог.

Цены синхронного режима, с НДС: YandexGPT Lite 0,20 ₽ за 1000 токенов на вход и столько же на выход, Qwen3.6 35B 0,20 ₽ за 1000 входящих и 0,30 ₽ за 1000 исходящих. Текстовая часть одной карточки около 3000 токенов, это меньше рубля. Фото тоже считаются во входящих токенах, поэтому с ними дороже: точную цену карточки посмотри в детализации расходов после первых 2-3 товаров. Это всё равно сильно дешевле, чем нанять копирайтера на ту же сотню.

Шаг 2: Токен WB API

  1. Заходишь в seller.wildberries.ru под владельцем кабинета: создавать токены может только он.
  2. Открываешь раздел Интеграции по API, нажимаешь + Создать токен и выбираешь вкладку Для интеграции вручную.
  3. Тип токена: Персональный. Он для собственных программ на твоём компьютере или сервере. Передавать его третьим лицам и использовать в облачных сервисах нельзя.
  4. Имя, например ai-card-generator. Категория: Контент (и Цены и скидки, если будешь обновлять цены). Не давай токену больше прав, чем нужно: если утечёт, ущерб меньше.
  5. Уровень доступа: Чтение и запись, иначе карточки не создать.
  6. Отметь, что не будешь передавать токен третьим лицам, нажми Создать, потом Скопировать и закрыть. Ещё раз посмотреть токен не получится. Он действует 180 дней, потом создай новый и обнови .env.

Проверить токен можно запросом GET https://content-api.wildberries.ru/ping с токеном в заголовке Authorization. Документация на dev.wildberries.ru, раздел «Работа с товарами».

Шаг 4: Промпт-шаблоны под категории

WB сильно разный по требованиям к категориям. Одежда любит размерную сетку и состав, электроника — точные ТТХ, дом — материал и габариты. Поэтому держим шаблоны в отдельных файлах и подгружаем по категории.

prompts/clothes.txt:

Ты копирайтер маркетплейса. Сделай карточку товара для Wildberries по описанию продавца и списку того, что видно на фото.

Категория: ОДЕЖДА.

Жёсткие ограничения:
- "title": до 60 символов. Тип товара и главное отличие, например "Джинсы прямые с высокой посадкой". Без бренда, пола, возраста, сезона и состава. Без повторов, синонимов, CAPS, эмодзи и спецсимволов.
- "description": до 1000 символов, абзацами через \n\n. Структура: общее описание → материал и качество → для каких случаев. Уход пиши, только если он есть в описании продавца. Без слов "купить", "лучший", "идеальный" и без списков поисковых запросов.
- "characteristics": массив объектов {"name": "...", "value": "..."}. Если ниже дан список характеристик Wildberries, бери названия только из него и заполни обязательные (*), если для них есть факты. НЕ ВЫДУМЫВАЙ: чего нет в описании продавца или на фото, в массив не включай.
- "keywords": 10-15 слов и фраз, по которым товар ищут (lowercase, без знаков препинания). Главные из них должны естественно звучать в описании. Отдельного поля для них у Wildberries нет.

Верни СТРОГО JSON по схеме. Никаких комментариев до или после.

Схема:
{
  "title": "string",
  "description": "string",
  "characteristics": [{"name": "string", "value": "string"}],
  "keywords": ["string"]
}

Аналогично electronics.txt (упор на ТТХ: мощность, напряжение, разъёмы) и home.txt (материал, размеры, вес, инструкция по сборке).

Главное правило промпта — «не выдумывай характеристики». Если модели не дать этого ограничения, она радостно напишет про джинсы «состав: хлопок 100%, плотность 320 г/м², пропитка водоотталкивающая» — даже если из фото видно только цвет.

Правила для названия взяты из справки WB: до 60 символов, только суть, без бренда, пола, возраста, сезона, оценок вроде «лучший» и спецсимволов. Отдельного поля для ключевых слов в карточке WB нет, а списки поисковых запросов в описании WB просит не писать. Поэтому keywords здесь подсказка: главные слова должны просто звучать в описании.

Шаг 5: Вызов моделей Yandex AI Studio

У AI Studio есть OpenAI-совместимый API: один адрес https://ai.api.cloud.yandex.net/v1/chat/completions для всех моделей, ключ в заголовке Authorization: Api-Key ..., каталог в заголовке OpenAI-Project. Фото понимает Qwen3.6 35B, картинки передаются в Base64. Поэтому работаем в два шага: Qwen перечисляет, что видно на фото, а YandexGPT Lite 5 по этим фактам и твоему brief.txt пишет карточку.

Файл generator.py:

import io
import os
import json
import base64
import logging
from pathlib import Path

import requests
from PIL import Image

log = logging.getLogger("generator")

# OpenAI-совместимый API Yandex AI Studio
YC_URL = "https://ai.api.cloud.yandex.net/v1/chat/completions"
VISION_MODEL = "qwen3.6-35b-a3b"  # Qwen3.6 35B: понимает фото в Base64
TEXT_MODEL = "yandexgpt-5-lite"   # YandexGPT Lite 5: пишет карточку
PHOTO_EXT = {".jpg", ".jpeg", ".png", ".webp"}

PHOTO_PROMPT = (
    "Перечисли списком, что видно на фото товара: тип товара, цвет, крой или форма, "
    "заметные детали (застёжка, карманы, принт), текст с ярлыка, если он читается. "
    "Пиши только то, что видно. Состав, размеры и страну производства не угадывай."
)


def _chat(model: str, content, system: str = "", temperature: float = 0.3) -> str:
    folder = os.getenv("YC_FOLDER_ID")
    messages = []
    if system:
        messages.append({"role": "system", "content": system})
    messages.append({"role": "user", "content": content})

    body = {
        "model": f"gpt://{folder}/{model}",
        "messages": messages,
        "temperature": temperature,
    }
    headers = {
        "Authorization": f"Api-Key {os.getenv('YC_API_KEY')}",
        "OpenAI-Project": folder,
        "Content-Type": "application/json",
    }
    r = requests.post(YC_URL, json=body, headers=headers, timeout=120)
    if r.status_code >= 400:
        log.error(f"AI Studio {r.status_code}: {r.text[:500]}")
    r.raise_for_status()
    return r.json()["choices"][0]["message"]["content"]


def _read_brief(item_dir: Path) -> str:
    brief = item_dir / "brief.txt"
    return brief.read_text(encoding="utf-8").strip() if brief.exists() else ""


def _photo_to_data_url(path: Path, max_side: int = 1024) -> str:
    """Уменьшаем фото до 1024 px: меньше токенов и быстрее запрос."""
    img = Image.open(path)
    img.thumbnail((max_side, max_side))
    buf = io.BytesIO()
    img.convert("RGB").save(buf, format="JPEG", quality=85)
    return "data:image/jpeg;base64," + base64.b64encode(buf.getvalue()).decode("ascii")


def describe_photos(item_dir: Path, max_n: int = 3) -> str:
    photos = sorted(p for p in item_dir.iterdir() if p.suffix.lower() in PHOTO_EXT)[:max_n]
    if not photos:
        return ""
    content = [{"type": "text", "text": PHOTO_PROMPT}]
    for p in photos:
        content.append({"type": "image_url", "image_url": {"url": _photo_to_data_url(p)}})
    log.info(f"Фото на распознавание: {item_dir.name}, {len(photos)} шт.")
    return _chat(VISION_MODEL, content, temperature=0.1)


def _charcs_hint(charcs: list) -> str:
    if not charcs:
        return ""
    names = [c["name"] + (" *" if c.get("required") else "") for c in charcs]
    return (
        "\n\nХарактеристики этого предмета на Wildberries "
        "(названия бери только отсюда, * значит обязательная):\n" + "\n".join(names)
    )


def generate_card(item_dir: Path, category: str = "clothes", charcs: list = None) -> dict:
    brief = _read_brief(item_dir)
    photo_facts = describe_photos(item_dir)

    prompt_file = Path("prompts") / f"{category}.txt"
    system_prompt = prompt_file.read_text(encoding="utf-8")

    user_text = (
        f"Описание от продавца:\n{brief}\n\n"
        f"Что видно на фото:\n{photo_facts or 'фото нет'}"
        f"{_charcs_hint(charcs or [])}"
    )

    log.info(f"YandexGPT: {item_dir.name}, category={category}")
    raw = _chat(TEXT_MODEL, user_text, system=system_prompt, temperature=0.3)

    # Модель иногда оборачивает JSON в ```json ... ```. Чистим.
    raw = raw.strip()
    if raw.startswith("```"):
        raw = raw.split("```")[1]
        if raw.startswith("json"):
            raw = raw[4:]
    raw = raw.strip()

    try:
        card = json.loads(raw)
    except json.JSONDecodeError:
        log.error(f"Не смог разобрать ответ как JSON: {raw[:500]}")
        raise

    # Пост-проверка: название на WB до 60 символов, описание держим до 1000
    if len(card.get("title", "")) > 60:
        card["title"] = card["title"][:60].rsplit(" ", 1)[0]
    if len(card.get("description", "")) > 1000:
        card["description"] = card["description"][:1000].rsplit(" ", 1)[0]

    card["photo_facts"] = photo_facts  # чтобы сверить глазами, что модель увидела на фото
    return card

Заметка про фото. Модель видит цвет, крой, детали и текст на ярлыке, но не состав и не размеры. Поэтому в запросе прямо сказано их не угадывать, а то, что модель увидела, сохраняется в card.json в поле photo_facts: сверь его с фото глазами. Если фото в папке нет, скрипт обойдётся одним brief.txt.

Модели в AI Studio обновляются: старые версии отключают, и запрос по старому имени возвращает ошибку 400. Если так случилось, посмотри актуальные имена в списке моделей и поправь VISION_MODEL и TEXT_MODEL.

Шаг 6: Загрузка карточки в WB

Как WB принимает карточку, по документации метода POST /content/v2/cards/upload:

  • характеристики только по числовым id: {"id": 12, "value": ["синий"]}. Тип значения задаёт справочник предмета GET /content/v2/object/charcs/{subjectId}: charcType 1 значит массив строк, 4 значит число;
  • название и описание идут отдельными полями. Характеристики с existNamedField: true тоже передаются отдельно, в массив их не кладём;
  • цвет, пол, страну производства, сезон, ставку НДС и ТН ВЭД WB берёт из своих справочников, значение должно с ними совпадать;
  • dimensions: габариты упаковки в сантиметрах и вес с упаковкой weightBrutto в килограммах. Если их не передать, WB поставит нули;
  • skus это баркоды. Если своих нет, поле не передаём: WB сгенерирует баркоды сам;
  • лимит метода: 10 запросов в минуту, интервал 6 секунд;
  • карточка создаётся асинхронно, до 30 минут. Ответ 200 ещё не значит, что она создана: ошибки смотрят методом POST /content/v2/cards/error/list.

Файл wb_uploader.py:

import os
import re
import time
import logging
import requests

log = logging.getLogger("wb")

WB_API = "https://content-api.wildberries.ru"
UPLOAD_PAUSE = 6  # создание карточек: 10 запросов в минуту, интервал 6 секунд


def _request(method: str, path: str, **kwargs) -> dict:
    headers = {"Authorization": os.getenv("WB_TOKEN"), "Content-Type": "application/json"}
    for _ in range(3):
        r = requests.request(method, WB_API + path, headers=headers, timeout=30, **kwargs)
        if r.status_code == 429:
            wait = int(r.headers.get("X-Ratelimit-Retry", "10"))
            log.warning(f"WB 429: слишком часто, жду {wait} с")
            time.sleep(wait)
            continue
        if r.status_code >= 400:
            log.error(f"WB {r.status_code}: {r.text[:500]}")
        r.raise_for_status()
        return r.json()
    raise RuntimeError("WB всё ещё отвечает 429, попробуйте позже")


def find_subjects(name: str) -> list:
    """ID предмета по названию: поиск по подстроке, например «джинсы»."""
    return _request("GET", "/content/v2/object/all", params={"name": name, "limit": 50})["data"]


def get_charcs(subject_id: int) -> list:
    """Характеристики предмета. Оставляем те, что передаются в массиве characteristics."""
    data = _request("GET", f"/content/v2/object/charcs/{subject_id}", params={"locale": "ru"})["data"]
    # existNamedField=true: поле передаётся отдельным параметром; charcType=0: не используется
    return [c for c in data if not c.get("existNamedField") and c.get("charcType") in (1, 4)]


def get_limits() -> dict:
    """Сколько карточек ещё можно создать: freeLimits + paidLimits минус уже созданные."""
    return _request("GET", "/content/v2/cards/limits")["data"]


def _to_number(value):
    if isinstance(value, list):
        value = value[0] if value else ""
    m = re.search(r"\d+(?:[.,]\d+)?", str(value))
    if not m:
        return None
    num = float(m.group().replace(",", "."))
    return int(num) if num.is_integer() else num


def map_characteristics(card_chars: list, charcs: list) -> tuple:
    """{"name", "value"} из card.json превращаем в {"id", "value"} для WB."""
    by_name = {c["name"].strip().lower(): c for c in charcs}
    result, problems = [], []
    for ch in card_chars:
        name = str(ch.get("name", "")).strip()
        value = ch.get("value")
        if value in (None, "", []):
            continue
        c = by_name.get(name.lower())
        if not c:
            problems.append(f"нет в справочнике предмета: {name}")
            continue
        if c["charcType"] == 4:  # число
            num = _to_number(value)
            if num is None:
                problems.append(f"не число: {name} = {value}")
                continue
            result.append({"id": c["charcID"], "value": num})
        else:  # массив строк
            values = value if isinstance(value, list) else [value]
            values = [str(v).strip() for v in values if str(v).strip()]
            if c.get("maxCount"):
                values = values[: c["maxCount"]]
            result.append({"id": c["charcID"], "value": values})

    filled = {r["id"] for r in result}
    for c in charcs:
        if c.get("required") and c["charcID"] not in filled:
            problems.append(f"не заполнена обязательная: {c['name']}")
    return result, problems


def upload_card(card: dict, vendor_code: str, subject_id: int, brand: str, price_rub: int,
                dimensions: dict, characteristics: list, sizes: list) -> dict:
    """
    vendor_code: ваш артикул (любая строка до 72 символов).
    dimensions: габариты упаковки в см и вес с упаковкой в кг.
    sizes: размеры из размерной сетки, например ["42", "44"]; для товара без размеров пустой список.
    Баркоды (skus) не передаём: WB сгенерирует их сам.
    """
    if sizes:
        size_list = [{"techSize": s, "wbSize": s, "price": price_rub} for s in sizes]
    else:
        size_list = [{"price": price_rub}]

    variant = {
        "vendorCode": vendor_code,
        "title": card["title"],
        "description": card["description"],
        "dimensions": dimensions,
        "characteristics": characteristics,
        "sizes": size_list,
    }
    if brand:
        variant["brand"] = brand

    payload = [{"subjectID": subject_id, "variants": [variant]}]

    log.info(f"WB upload: vendorCode={vendor_code}, title={card['title']!r}")
    res = _request("POST", "/content/v2/cards/upload", json=payload)
    time.sleep(UPLOAD_PAUSE)  # не упираемся в лимит 10 запросов в минуту
    return res


def get_errors(vendor_codes: set) -> dict:
    """Ошибки создания карточек (черновики) по нашим артикулам из последних 100 пакетов."""
    body = {"cursor": {"limit": 100}, "order": {"ascending": False}}
    data = _request("POST", "/content/v2/cards/error/list", json=body)["data"]
    found = {}
    for batch in data.get("items", []):
        for code, errs in batch.get("errors", {}).items():
            if code in vendor_codes:
                found.setdefault(code, []).extend(errs)
    return found

Токен WB кладётся в заголовок Authorization как есть, так показано в документации WB API.

Размеры из --sizes уходят в techSize и wbSize (российский размер). Если у размерного товара размеры не указать, WB создаст размер-заглушку, поэтому для одежды передавай их.

Шаг 7: Главный скрипт

Файл main.py:

def process_one(item_dir: Path, args, charcs: list):
    log.info(f"=== {item_dir.name} ===")
    out = item_dir / "card.json"

    if args.upload and out.exists():
        # Заливаем то, что вы уже проверили и поправили руками, а не новую генерацию
        card = json.loads(out.read_text(encoding="utf-8"))
        log.info(f"беру проверенный {out}")
    else:
        card = generate_card(item_dir, category=args.category, charcs=charcs)
        out.write_text(json.dumps(card, ensure_ascii=False, indent=2), encoding="utf-8")
        log.info(f"saved {out}")

    if not charcs:
        return
    wb_chars, problems = map_characteristics(card.get("characteristics", []), charcs)
    for p in problems:
        log.warning(f"{item_dir.name}: {p}")

    if args.upload:
        if any(p.startswith("не заполнена обязательная") for p in problems):
            log.warning(f"{item_dir.name}: пропускаю загрузку, допишите обязательные характеристики в card.json")
            return
        dims = {"length": args.length, "width": args.width, "height": args.height, "weightBrutto": args.weight}
        sizes = [s.strip() for s in args.sizes.split(",") if s.strip()]
        res = upload_card(card, item_dir.name, args.subject_id, args.brand, args.price, dims, wb_chars, sizes)
        log.info(f"WB ответ: {res}")

    ap.add_argument("--height", type=int, default=0, help="высота упаковки, см")

    args = ap.parse_args()

    if args.find_subject:
        for s in find_subjects(args.find_subject):

    goods = Path(args.goods_dir)
    items = sorted(p for p in goods.iterdir() if p.is_dir())
    log.info(f"Найдено товаров: {len(items)}")

        errors = get_errors({p.name for p in items})

С --upload скрипт не генерирует карточку заново, а берёт уже проверенный тобой card.json. Товар без обязательных характеристик он не отправляет и пишет в лог, чего не хватает.

Запуск и проверка

Сначала найди ID предмета. Поиск идёт по подстроке:

python main.py --find-subject джинсы

Скрипт напечатает ID, предмет и родительскую категорию. Выбери подходящий и запиши ID в табличку, чтобы не искать снова.

Потом генерим карточки без заливки (dry-run). С --subject-id модель получает список характеристик этого предмета и пишет их названия так, как их ждёт WB:

python main.py --goods-dir goods --category clothes --subject-id ID_ПРЕДМЕТА

Скрипт пройдётся по всем подпапкам, для каждой создаст card.json рядом с фото. Открываешь, читаешь глазами. Если ок — заливаешь:

python main.py --goods-dir goods --category clothes --subject-id ID_ПРЕДМЕТА \
  --upload --brand "MyBrand" --price 2490 --sizes 42,44,46 \
  --length 30 --width 20 --height 5 --weight 0.6

Начни с одного товара: положи в отдельную папку только его. Бренд должен быть в справочнике WB. Если бренда нет, не передавай --brand. Габариты и вес укажи свои, по упаковке. Перед загрузкой скрипт выводит лимиты на создание карточек: можно создать (freeLimits + paidLimits) минус уже созданные карточки, включая корзину.

Через 30 минут проверь, не застряли ли карточки в черновиках:

python main.py --goods-dir goods --check-errors

Если ошибки есть, поправь card.json и загрузи товар ещё раз: карточка уйдёт из списка ошибок, когда WB примет исправленный вариант.

Рассчитывай, что часть карточек придётся править руками. Чаще всего модель додумывает то, чего нет в brief.txt, например состав ткани. Поэтому состав и размеры пиши в brief.txt сам.

Расширения

  • Батч-обработка папки фото. Сейчас один товар = одна подпапка. Можно сделать обратный режим: одна большая папка с файлами вида джинсы-синие-001.jpg, скрипт сам группирует и парсит имя для brief.
  • Обновление описаний под поисковые запросы. Если видишь в аналитике кабинета, по каким запросам ищут твой товар, раз в неделю отдавай их YandexGPT и проси поправить description, чтобы главные слова звучали в тексте. Списком запросы в описание не вставляй: WB просит так не делать.
  • A/B-тестирование заголовков. Генеришь 3 варианта title, через WB API меняешь раз в неделю, смотришь конверсию в кабинете. Через месяц у тебя статистически лучший заголовок.
  • Модель посильнее. Поменяй TEXT_MODEL на YandexGPT Pro 5.1 (yandexgpt-5.1, 0,80 ₽ за 1000 токенов) и сравни карточки на пяти товарах.
  • Чек на запрещёнку. Перед загрузкой прогоняешь карточку через второй промпт «есть ли тут запрещённые WB обещания: лечит, сертифицирован, гарантирует». Если да — флаг, ручная проверка.

Подводные камни

  • WB банит за враньё в характеристиках. Если карточка обещает «хлопок 100%», а покупатель получает синтетику — будут возвраты, штрафы и в худшем случае блокировка. Лучше пустое поле, чем выдуманное. Промпт это явно требует, но проверяй глазами.
  • YandexGPT любит «эссе» вместо JSON. Иногда возвращает «Вот ваш JSON: ```json {...} ```». Чищу через split — но если будет упорно срываться, добавь в промпт «не пиши ничего кроме JSON» дважды и понизь temperature до 0.1.
  • Лимиты WB API. На создание карточек 10 запросов в минуту с интервалом 6 секунд, на большинство других методов «Контента» 100 в минуту. В коде пауза 6 секунд после каждой загрузки и повтор после 429 по заголовку X-Ratelimit-Retry.
  • Лимит на число карточек. У продавца есть бесплатный и платный лимит на создание карточек, остаток показывает GET /content/v2/cards/limits. Проверяй его до большой загрузки. Код 402 в WB API к этому лимиту не относится: его получают сервисы из Каталога решений для бизнеса.
  • subjectID угадывать нельзя. Похожие товары могут относиться к разным предметам, и у каждого свой набор характеристик. Ищи ID через --find-subject и держи у себя справочник.
  • Обязательные характеристики. Они свои у каждого предмета, в справочнике это поле required. Скрипт пишет в лог, какие не заполнены. Не подставляй значения по умолчанию: лучше допиши факт в card.json сам или верни товар на ручную обработку.
  • Картинки грузятся отдельно. /cards/upload создаёт только текстовую часть карточки, а без фото товар покупателям не показывают. Фото добавляются после создания карточки: методом /content/v3/media/save по прямым ссылкам или /content/v3/media/file файлом. Обычно их удобнее залить через кабинет.
  • Токен на 180 дней. Запиши, когда он истечёт. После этого WB начнёт отвечать 401: создай новый токен и обнови .env.

Что в итоге

За пару часов у тебя получился рабочий конвейер «фото и краткое описание → готовая карточка WB». Текстовая часть карточки стоит меньше рубля, фото добавляют сверху. Времени экономишь — час на товар. На 100 товарах в месяц это уже окупает любой облачный сервис в десятки раз.

Технически ты потрогал два важных российских API: Yandex AI Studio (OpenAI-совместимый доступ к YandexGPT и открытым моделям) и WB API, раздел «Контент» (один из самых документированных marketplace API в РФ). Эти знания переиспользуются: от YandexGPT можно перейти к Alice AI ART для генерации изображений, от WB к Ozon Seller API (он устроен похоже).

И главное — это первый честный пример того, как AI реально снимает рутину, а не «генерит контент ради контента». Тут есть конкретный селлер, конкретная задача и измеримая экономия времени.
