Мини-проект·P22

Проект «За 1 час»: Локальный RAG по своим документам — приватный поиск без облака

Что построим: систему семантического поиска по PDF — медкарта, договоры, выписки, рабочие материалы — полностью офлайн Время: ~90 минут Уровень: Python средний, понимание основ эмбеддингов полезно, 16+ GB RAM

Зачем этот проект

Типичная ситуация: 50 PDF — выписки из банка, медицинские протоколы, договоры аренды, скан паспорта, налоговые квитанции, рабочие методички. Когда нужно найти «сколько я плачу за коммуналку в среднем за полгода» или «что у меня в полисе ДМС про стоматологию» — приходится открывать файлы по одному, листать, искать словом, ругаться.

Облачные ассистенты эту задачу решают, но в них надо закидывать документы — а медкарта в чужом дата-центре это совсем не то, чего хочется. Локальный RAG (Retrieval-Augmented Generation) делает то же самое, но всё хранится у тебя на диске: эмбеддинги, индекс, ответы — ничего наружу.

За 90 минут получим CLI: python rag.py index ~/Documents/мои-доки один раз, потом python rag.py ask "..." — и ответ с цитатами и ссылками на конкретные документы и страницы.

Что в итоге будет

  • Индексатор PDF: извлекает текст (включая таблицы), режет на чанки, считает эмбеддинги.
  • Локальная векторная база ChromaDB — хранится в папке проекта.
  • CLI с двумя командами: index (проиндексировать папку) и ask (спросить).
  • Поиск top-k релевантных фрагментов → подсовываем Ollama → получаем ответ со ссылками на источники.
  • Опциональный Streamlit-интерфейс в одну страницу.
  • Ни одного облачного запроса. Всё локально, всё бесплатно, всё офлайн-совместимо.

Требования

  • Python 3.10+.
  • 16+ GB RAM (для qwen2.5:7b и embeddings одновременно).
  • Установленный Ollama (если не ставил — см. проект p21, шаг 1).
  • Папка с PDF/TXT-документами, которые хочешь сделать поисковыми.
  • ~3 GB свободного места на диске под модели и индекс.

Архитектура

ИНДЕКСАЦИЯ (однократно или по cron):
docs/*.pdf
  → pdfplumber: извлечь текст постранично
  → split: разбить на чанки 500–800 токенов с overlap 100
  → sentence-transformers: посчитать embedding для каждого чанка
  → ChromaDB: положить (text, embedding, metadata{file, page})

ЗАПРОС:
"Сколько я плачу за коммуналку?"
  → sentence-transformers: embedding запроса
  → ChromaDB: top-5 ближайших чанков
  → Ollama (qwen2.5): "вот вопрос, вот контекст, ответь и сошлись"
  → ответ + список источников

Шаг 2: извлечение текста из PDF

Я перебрал три библиотеки. PyPDF2 ломается на сложных layout, PyMuPDF (fitz) быстрый и хороший, но лицензия AGPL — для open-source проектов норм, для корпоративного использования бывают вопросы. Pdfplumber медленнее, но из коробки умеет таблицы и проще ставится. Берём его.

Файл extract.py:

import pdfplumber
from pathlib import Path


def extract_pdf_pages(path):
    """Возвращает список (page_number, text) для PDF."""
    pages = []
    with pdfplumber.open(path) as pdf:
        for i, page in enumerate(pdf.pages, 1):
            text = page.extract_text() or ""
            # таблицы — отдельно, склеиваем построчно
            for table in page.extract_tables() or []:
                rows = ["	".join(c or "" for c in row) for row in table]
                text += "

[TABLE]
" + "
".join(rows) + "
[/TABLE]"
            if text.strip():
                pages.append((i, text))
    return pages


def extract_any(path):
    """PDF — постранично, TXT — целиком как одна "страница"."""
    p = Path(path)
    if p.suffix.lower() == ".pdf":
        return extract_pdf_pages(p)
    if p.suffix.lower() in (".txt", ".md"):
        return [(1, p.read_text(encoding="utf-8", errors="ignore"))]
    return []

Тестируем:

python -c "from extract import extract_any; print(extract_any('docs/example.pdf')[0][1][:300])"

Шаг 3: чанкинг

Эмбеддинг хорошо работает на коротких связных кусках. Если кинуть в модель целиком 20-страничный договор — получится размытое усреднение «договор о чём-то». Если резать на абзацы по 50 слов — потеряем контекст. Опытно лучше всего ~500–800 токенов с overlap 100 (чтобы фраза, попавшая на границу, всё равно нашлась).

Файл chunk.py:

def chunk_text(text, chunk_size=600, overlap=100):
    """Грубая разбивка по словам. Для русского работает достаточно хорошо.

    chunk_size — примерное число слов в куске (≈ 800 токенов для русского).
    overlap — сколько слов перекрывается между соседними чанками.
    """
    words = text.split()
    if not words:
        return []

    chunks = []
    step = chunk_size - overlap
    for start in range(0, len(words), step):
        chunk = " ".join(words[start:start + chunk_size])
        if chunk.strip():
            chunks.append(chunk)
        if start + chunk_size >= len(words):
            break
    return chunks

Можно использовать tiktoken для точного подсчёта токенов, но для нашей задачи разбиение «по словам» работает не хуже и не тянет лишних зависимостей.

Шаг 4: эмбеддинги и ChromaDB

Для русского лучшая бесплатная мультиязычная модель — sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2. 384-мерные эмбеддинги, ~120 MB на диске, работает мгновенно даже на CPU. Поддерживает 50+ языков, на русском показывает себя на уровне OpenAI ada-002.

Если у тебя много документов и хочется качества повыше — возьми paraphrase-multilingual-mpnet-base-v2 (768-мерные, ~420 MB, точность выше на 5–10%).

ChromaDB — самая простая локальная векторная БД. Хранит всё в SQLite + parquet-файлах в указанной папке. Никакого сервера, никаких портов.

Файл store.py:

import chromadb
from sentence_transformers import SentenceTransformer

EMBED_MODEL = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"

_model = None
_client = None
_collection = None


def get_model():
    global _model
    if _model is None:
        _model = SentenceTransformer(EMBED_MODEL)
    return _model


def get_collection(persist_dir="./chroma_db"):
    global _client, _collection
    if _collection is None:
        _client = chromadb.PersistentClient(path=persist_dir)
        _collection = _client.get_or_create_collection(
            name="documents",
            metadata={"hnsw:space": "cosine"},
        )
    return _collection


def embed_texts(texts):
    model = get_model()
    # normalize — для cosine-similarity это обязательно
    return model.encode(texts, normalize_embeddings=True).tolist()

Шаг 5: индексатор

Файл indexer.py:

import hashlib
from pathlib import Path
from tqdm import tqdm

from extract import extract_any
from chunk import chunk_text
from store import get_collection, embed_texts


def _chunk_id(file_path, page, chunk_idx):
    raw = f"{file_path}::{page}::{chunk_idx}"
    return hashlib.md5(raw.encode()).hexdigest()


def index_folder(folder, exts=(".pdf", ".txt", ".md")):
    collection = get_collection()
    folder = Path(folder)
    files = [p for p in folder.rglob("*") if p.suffix.lower() in exts]
    print(f"Найдено {len(files)} документов")

    for path in tqdm(files, desc="Документы"):
        try:
            pages = extract_any(path)
        except Exception as e:
            print(f"  пропускаю {path.name}: {e}")
            continue

        ids, docs, metas = [], [], []
        for page_num, text in pages:
            for chunk_idx, chunk in enumerate(chunk_text(text)):
                ids.append(_chunk_id(str(path), page_num, chunk_idx))
                docs.append(chunk)
                metas.append({
                    "file": path.name,
                    "path": str(path),
                    "page": page_num,
                })

        if not docs:
            continue

        # считаем эмбеддинги пачками по 64 — оптимально для CPU
        embeddings = []
        for i in range(0, len(docs), 64):
            embeddings.extend(embed_texts(docs[i:i + 64]))

        # upsert — если документ переиндексируем, старые куски заменятся
        collection.upsert(
            ids=ids,
            documents=docs,
            embeddings=embeddings,
            metadatas=metas,
        )

    print(f"В индексе теперь {collection.count()} чанков")

Шаг 6: поиск и ответ через Ollama

Файл query.py:

import ollama
from store import get_collection, embed_texts

MODEL = "qwen2.5:7b"

SYSTEM_PROMPT = """Ты — ассистент для поиска по личным документам пользователя.

Тебе дают вопрос и фрагменты документов с пометками источников.
Отвечай ТОЛЬКО на основании этих фрагментов. Не придумывай.

Правила:
- Если в фрагментах есть прямой ответ — давай его и в конце укажи источники
  в формате [файл.pdf, стр. N].
- Если в фрагментах нет нужной информации — честно скажи "в документах
  этого не нашёл" и не выдумывай.
- Если в фрагментах есть цифры — приводи их точно, не округляй на свой вкус.
- Отвечай кратко, по делу, на русском.
"""


def search(query, top_k=5):
    collection = get_collection()
    query_emb = embed_texts([query])[0]
    results = collection.query(
        query_embeddings=[query_emb],
        n_results=top_k,
    )
    hits = []
    for doc, meta, dist in zip(
        results["documents"][0],
        results["metadatas"][0],
        results["distances"][0],
    ):
        hits.append({
            "text": doc,
            "file": meta["file"],
            "page": meta["page"],
            "score": 1 - dist,  # cosine distance → similarity
        })
    return hits


def ask(question, top_k=5):
    hits = search(question, top_k=top_k)

    if not hits:
        return "В индексе нет документов. Сначала запусти `index`.", []

    context = "

---

".join(
        f"[Источник: {h['file']}, стр. {h['page']}]
{h['text']}"
        for h in hits
    )

    user_msg = f"Вопрос: {question}

Фрагменты документов:

{context}"

    resp = ollama.chat(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ],
        options={"temperature": 0.1, "num_ctx": 8192},
    )
    answer = resp["message"]["content"]
    return answer, hits

Шаг 7: CLI

Файл rag.py:

import sys
from indexer import index_folder
from query import ask


def main():
    if len(sys.argv) < 2:
        print("Использование:")
        print("  python rag.py index <папка>")
        print("  python rag.py ask "<вопрос>"")
        sys.exit(1)

    cmd = sys.argv[1]

    if cmd == "index":
        if len(sys.argv) < 3:
            print("Укажи папку: python rag.py index ./docs")
            sys.exit(1)
        index_folder(sys.argv[2])

    elif cmd == "ask":
        if len(sys.argv) < 3:
            print("Укажи вопрос: python rag.py ask "..."")
            sys.exit(1)
        question = " ".join(sys.argv[2:])
        answer, hits = ask(question)
        print("
=== ОТВЕТ ===
")
        print(answer)
        print("
=== ИСТОЧНИКИ ===")
        for h in hits:
            print(f"  • {h['file']} стр. {h['page']}  (similarity {h['score']:.2f})")

    else:
        print(f"Неизвестная команда: {cmd}")
        sys.exit(1)


if __name__ == "__main__":
    main()

Расширения

  • Разные индексы под категории. Создай несколько коллекций в Chroma: medical, legal, finance. Запросы — только в одну, иначе медицинский термин может «зацепить» юридический документ.
  • OCR для сканов. Если у тебя фото-документы или сканы без текстового слоя — добавь Tesseract: pip install pytesseract, перед extract_text() прогоняй страницу через OCR. Качество на русском печатном тексте — 95%+ при разумном разрешении.
  • Голосовые запросы. Whisper.cpp локально транскрибирует речь — добавляешь кнопку записи в Streamlit, прогоняешь через Whisper, кидаешь текст в ask(). Идеально для «спросить про лекарство, когда руки в тесте».
  • Авто-индексация по cron. Если документы добавляются регулярно (например, банк раз в месяц шлёт выписку) — раз в день python rag.py index ~/Downloads/банк/. Upsert по hash не дублирует уже проиндексированное.
  • Гибридный поиск. К семантическому добавь BM25-поиск (через rank_bm25) и объедини результаты. Семантика хороша для смысла, BM25 — для точных слов и номеров. Вместе — заметно лучше top-k.

Подводные камни

  • Качество эмбеддингов на специфической лексике. Мультиязычная MiniLM хорошо понимает обычный русский, но медицинские термины («гиперэхогенное включение», «АТ-ТПО») или юридические формулы знает хуже. Если вопрос совсем не находится — попробуй переформулировать «человеческими словами» или подними top_k до 10–15.
  • Скорость на большом корпусе. 100 PDF индексируется за 5–10 минут, 1000 — уже за час+. Запускай в фоне или ночью. ChromaDB сам по себе шустрый, бутылочное горлышко — pdfplumber на парсинге.
  • Что делать, если top-k не нашёл нужный документ. Это нормальная ситуация: эмбеддинг — не магия. Подними n_results=10, переформулируй вопрос, или добавь BM25 (см. расширения). В крайнем случае grep по тексту чанков из ChromaDB.
  • Hallucinations при пустом контексте. Если в top-k попадут нерелевантные чанки — qwen2.5:7b может попробовать «дотянуть» ответ из своих знаний. Поэтому в SYSTEM_PROMPT жёстко: «если не нашёл — скажи что не нашёл». Раз в неделю проверяй сомнительные ответы вручную.
  • Чанк-граница режет таблицу. Финансовая таблица из 100 строк попадёт в 3–4 чанка, и в один из них — без заголовка. Запрос «сумма за март» может промахнуться. Лечится либо большим overlap (200 слов вместо 100), либо специальной обработкой таблиц (записывать заголовок в каждый чанк-фрагмент).
  • Безопасность хранения. ChromaDB складывает распознанный текст и эмбеддинги в обычные файлы в ./chroma_db/. Если в индексе медкарта и кто-то получает доступ к диску — он получает доступ и к содержимому. Шифруй раздел (FileVault / LUKS), не клади chroma_db/ в общие облака типа iCloud Desktop.

Этика и аккуратность

  • Не индексируй чужие документы без согласия. Договор контрагента — это часто его конфиденциальная информация, даже если у тебя физически есть копия.
  • Помни, что распознанный текст лежит у тебя в чистом виде. Если ноутбук уедет в ремонт — индекс надо удалить (или зашифровать ФС заранее).
  • RAG — не юрист и не врач. Ответ из медкарты «у тебя нашли X» — повод сходить к врачу, а не диагноз.

Что в итоге

За 90 минут собрали полностью офлайн-систему: индексируешь папку документов, спрашиваешь обычным языком, получаешь ответ с цитатами. Никаких подписок, никаких облаков, никаких утечек. Связка pdfplumber + sentence-transformers + ChromaDB + Ollama — это, по сути, тот же стек, что в дорогих корпоративных RAG-продуктах, только без вендора над тобой.

Дальше — добавляй OCR для сканов, индексы по категориям, голосовые запросы через Whisper. Архитектура линейно растёт: новый шаг — новый модуль, остальное не трогаешь.

Готово. У тебя локальный поиск по личным документам, который ничем не делится с миром. Дальше — индексируй медкарту, договоры, рабочие методички и забудь про «где-то у меня это было». Если захочется поднять качество — поменяй модель эмбеддингов на mpnet или добавь BM25-гибрид в один день работы.
