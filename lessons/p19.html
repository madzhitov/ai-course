Проект «За 1 час»: TG-бот для саммари чатов на GigaChat (РФ-стек)

Что построим: Telegram-бот, который делает выжимку из пересланной переписки — без VPN, через GigaChat Время: ~75 минут Уровень: базовый Python + понимание HTTP Стек: Python 3.10+, python-telegram-bot, gigachat SDK, .env

Что в итоге будет

Полностью рабочий Telegram-бот, который:

  • Принимает любое длинное сообщение или пачку пересланных подряд;
  • Склеивает их в один текст, режет на чанки (контекст у GigaChat скромный — 8192 токена);
  • Отдаёт каждый чанк в GigaChat Lite/Pro, получает мини-саммари, потом сшивает в один TL;DR;
  • Команды: /start, /summary, /stats;
  • Работает на любом российском VPS — Yandex Cloud, Selectel, или прямо локально через ngrok.

Это РФ-аналог проекта p1 (там Claude). Разница принципиальная: оплата с любой РФ-карты, никакого VPN, не блокируется. Бесплатный тир — 1 миллион токенов в месяц для физлица. Для пет-проекта этого хватит на годы.

Требования

  • Python 3.10 или выше;
  • Аккаунт в Telegram и созданный бот (через @BotFather);
  • Учётка в Сбер ID (любая, обычно есть у каждого);
  • Доступ к developers.sber.ru — регистрация занимает 10 минут;
  • Желание один раз разобраться с SSL-сертификатом Минцифры (рассказываю ниже).

Никакой БД, никакого Redis. Всё в памяти процесса — для личного использования и небольшой группы коллег этого более чем достаточно.

Шаг 1: Регистрация в developers.sber.ru (10 минут)

  1. Идёшь на developers.sber.ru, нажимаешь «Войти» — заходишь через Сбер ID. Если у тебя есть Сбербанк Онлайн — учётка уже есть.
  2. В шапке выбираешь GigaChat API → подключить.
  3. Выбираешь тариф Freemium (для физлиц). Это и есть тот самый 1М токенов в месяц.
  4. Принимаешь оферту. Если попросит подтвердить телефон — подтверждаешь.
  5. После активации в личном кабинете появится раздел «Мои проекты». Создай проект (название любое, например «summary-bot»).
  6. В проекте нажимаешь «Сгенерировать новый Client Secret» — копируешь Authorization Key. Это base64-строка вида NzE4Yzg3ZDAt...:OWY1ZGY5.... Сохрани сразу в надёжное место — повторно показать его нельзя, только перевыпустить.

Этот Authorization Key — не сам access token. Это пара client_id:client_secret в base64. Каждые 30 минут SDK будет менять его на короткоживущий access token через OAuth2. Это нормальный flow, SDK всё делает сам.

Шаг 2: SSL-сертификат Минцифры — почему это вообще проблема

API GigaChat живёт на домене gigachat.devices.sberbank.ru, и сертификат там подписан российским корневым центром (Минцифры). В системные хранилища macOS/Linux/Windows этот корень по умолчанию не входит — поэтому Python ругается:

SSLError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed

Есть два пути:

Для экспериментов (быстро): просто отключаешь проверку. SDK поддерживает флаг verify_ssl_certs=False. Для пет-проекта на своём ноуте — нормально.

Для прода: качаешь корневой сертификат Минцифры и добавляешь в trust store. Файл лежит на сайте Минцифры — gosuslugi.ru/crt (раздел «Корневой сертификат Минцифры»). Скачиваешь russian_trusted_root_ca.cer, кладёшь рядом с проектом и в SDK передаёшь ca_bundle_file="russian_trusted_root_ca.cer".

На macOS можно ещё добавить в системный keychain, но проще через файл — переносимо.

Шаг 3: Создаём бота в Telegram (2 минуты)

  1. В Telegram находишь @BotFather, шлёшь /newbot.
  2. Имя для отображения — что угодно («My Summary Bot»).
  3. Username — должен заканчиваться на _bot (например rm_summary_bot).
  4. Получишь токен вида 1234567:AABBccDD.... Сохраняем.

Шаг 5: Минимальная обёртка над GigaChat

Файл llm.py:

import os
from gigachat import GigaChat
from gigachat.models import Chat, Messages, MessagesRole

SYSTEM_PROMPT = """Ты делаешь краткое саммари переписки из мессенджера.

Формат ответа:

📌 ТЕМЫ
- (1-3 пункта, о чём говорили)

✅ РЕШЕНИЯ
- (что решили; если ничего — пиши «решений нет»)

⚠️ ВОПРОСЫ И ЗАДАЧИ
- (что ждут от участников чата)

📅 ДЕДЛАЙНЫ
- (даты, если упоминаются)

Будь краток. Только факты. Без воды и без вступлений."""


def summarize_chunk(text: str) -> str:
    """Один вызов GigaChat для куска текста."""
    with GigaChat(
        credentials=os.getenv("GIGACHAT_AUTH_KEY"),
        scope=os.getenv("GIGACHAT_SCOPE", "GIGACHAT_API_PERS"),
        model="GigaChat",  # Lite — бесплатный. Pro — платный.
        verify_ssl_certs=False,  # для прода — ca_bundle_file=...
    ) as giga:
        payload = Chat(
            messages=[
                Messages(role=MessagesRole.SYSTEM, content=SYSTEM_PROMPT),
                Messages(role=MessagesRole.USER, content=text),
            ],
            temperature=0.3,
            max_tokens=800,
        )
        response = giga.chat(payload)
        return response.choices[0].message.content


def merge_summaries(parts: list[str]) -> str:
    """Если чанков было много — сшиваем мини-саммари в одно общее."""
    if len(parts) == 1:
        return parts[0]

    joined = "

---

".join(parts)
    merge_prompt = (
        "Тебе даны несколько фрагментов саммари длинной переписки. "
        "Сшей их в одно итоговое саммари по тому же формату "
        "(ТЕМЫ / РЕШЕНИЯ / ВОПРОСЫ / ДЕДЛАЙНЫ). Убери дубли, оставь главное."
    )
    with GigaChat(
        credentials=os.getenv("GIGACHAT_AUTH_KEY"),
        scope=os.getenv("GIGACHAT_SCOPE", "GIGACHAT_API_PERS"),
        verify_ssl_certs=False,
    ) as giga:
        payload = Chat(
            messages=[
                Messages(role=MessagesRole.SYSTEM, content=merge_prompt),
                Messages(role=MessagesRole.USER, content=joined),
            ],
            temperature=0.2,
            max_tokens=1000,
        )
        return giga.chat(payload).choices[0].message.content

Обрати внимание: SDK сам ходит за access token'ом по OAuth2 при первом запросе, кеширует, обновляет. Тебе вообще не надо думать про bearer-токены.

Шаг 6: Разбиваем длинный текст на чанки

У GigaChat (Lite) контекст — 8192 токена. Это примерно 20–25 тысяч символов на русском. Если переписка длиннее — упрёмся. Простое решение: режем по ~12000 символов с небольшим overlap, чтобы не разорвать мысль на границе.

Файл chunker.py:

CHUNK_SIZE = 12000
OVERLAP = 500


def split_text(text: str) -> list[str]:
    if len(text) <= CHUNK_SIZE:
        return [text]

    chunks = []
    start = 0
    while start < len(text):
        end = min(start + CHUNK_SIZE, len(text))
        # стараемся резать по 

, чтобы не рвать сообщение пополам
        if end < len(text):
            nl = text.rfind("

", start, end)
            if nl > start + CHUNK_SIZE // 2:
                end = nl
        chunks.append(text[start:end])
        start = end - OVERLAP if end < len(text) else end
    return chunks

Шаг 7: Сам бот

Файл bot.py:

import os
import asyncio
import logging
from collections import defaultdict
from datetime import datetime
from dotenv import load_dotenv

from telegram import Update
from telegram.ext import (
    Application,
    CommandHandler,
    MessageHandler,
    ContextTypes,
    filters,
)

from llm import summarize_chunk, merge_summaries
from chunker import split_text

load_dotenv()
logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")
log = logging.getLogger("bot")

# user_id -> список (timestamp, text)
buffer: dict[int, list[tuple[datetime, str]]] = defaultdict(list)
# user_id -> счётчик использований
stats: dict[int, int] = defaultdict(int)

BUFFER_WAIT_SEC = 2.0  # сколько ждём после последнего сообщения, прежде чем суммировать


async def cmd_start(update: Update, ctx: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text(
        "Привет! Я суммаризирую длинные чаты через GigaChat.

"
        "Перешли мне одно или несколько сообщений из любого чата — "
        "через пару секунд получишь TL;DR.

"
        "Команды:
"
        "/summary — принудительно собрать саммари по тому, что в буфере
"
        "/stats — сколько раз ты пользовался ботом"
    )


async def cmd_stats(update: Update, ctx: ContextTypes.DEFAULT_TYPE):
    uid = update.effective_user.id
    await update.message.reply_text(f"Ты сделал {stats[uid]} саммари.")


async def cmd_summary(update: Update, ctx: ContextTypes.DEFAULT_TYPE):
    uid = update.effective_user.id
    if not buffer[uid]:
        await update.message.reply_text("Буфер пуст. Перешли сначала сообщения.")
        return
    await process_buffer(update, uid)


async def on_text(update: Update, ctx: ContextTypes.DEFAULT_TYPE):
    uid = update.effective_user.id
    text = update.message.text or update.message.caption or ""
    if not text.strip():
        return

    buffer[uid].append((datetime.utcnow(), text))
    log.info(f"buffer[{uid}] = {len(buffer[uid])} msgs, total {sum(len(t) for _, t in buffer[uid])} chars")

    # отложенная сборка: ждём BUFFER_WAIT_SEC. Если за это время пришли ещё — выходим.
    await asyncio.sleep(BUFFER_WAIT_SEC)
    last_time = buffer[uid][-1][0]
    if (datetime.utcnow() - last_time).total_seconds() < BUFFER_WAIT_SEC - 0.3:
        return  # пришли свежие сообщения, отработает следующий вызов

    await process_buffer(update, uid)


async def process_buffer(update: Update, uid: int):
    full_text = "

".join(t for _, t in buffer[uid])
    buffer[uid] = []

    if len(full_text) < 200:
        await update.message.reply_text("Слишком короткое для саммари (нужно от 200 символов).")
        return

    chunks = split_text(full_text)
    notice = await update.message.reply_text(
        f"⏳ Делаю саммари... ({len(chunks)} {'кусок' if len(chunks) == 1 else 'кусков'})"
    )

    try:
        # GigaChat SDK — синхронный, гоняем в thread pool, чтобы не блокировать loop
        loop = asyncio.get_running_loop()
        parts = []
        for i, ch in enumerate(chunks, 1):
            log.info(f"summarize chunk {i}/{len(chunks)}, {len(ch)} chars")
            part = await loop.run_in_executor(None, summarize_chunk, ch)
            parts.append(part)
        final = await loop.run_in_executor(None, merge_summaries, parts)
    except Exception as e:
        log.exception("GigaChat call failed")
        await notice.edit_text(f"Ошибка при обращении к GigaChat: {e}")
        return

    stats[uid] += 1
    await notice.edit_text(final)


def main():
    token = os.getenv("TG_TOKEN")
    if not token:
        raise SystemExit("TG_TOKEN не задан в .env")

    app = Application.builder().token(token).build()
    app.add_handler(CommandHandler("start", cmd_start))
    app.add_handler(CommandHandler("stats", cmd_stats))
    app.add_handler(CommandHandler("summary", cmd_summary))
    app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, on_text))

    log.info("Bot started, polling...")
    app.run_polling(allowed_updates=Update.ALL_TYPES)


if __name__ == "__main__":
    main()

В консоли увидишь Bot started, polling.... Идёшь в Telegram, находишь своего бота, шлёшь /start. Потом — открываешь любой групповой чат, выделяешь 10–15 сообщений (зажимаешь, потом «Forward»), пересылаешь боту. Через 2 секунды после последнего сообщения он начинает работать и через 5–10 секунд (зависит от длины) присылает структурированный TL;DR.

У меня на проверке: переписка из рабочего чата на ~40 сообщений (≈18 тыс. символов) — саммари 4 пункта по темам, 2 решения, 1 вопрос ко мне. Заняло около 6 секунд. Стоимость — около 4000 токенов, то есть бесплатно в рамках месячного тира.

Деплой: куда поставить

Локально через ngrok — для теста сойдёт, но бот живёт, пока ноут включён.

Yandex Cloud Compute Cloud — самый предсказуемый вариант для РФ. Виртуалка 2 vCPU / 1 Gb / 10 Gb HDD — около 350 ₽/мес. Поставил Python, склонировал репу, systemd-юнит, и забыл.

Selectel — то же самое, тарифы примерно те же, но интерфейс чуть проще.

Расширения

  • Разные форматы саммари. Команды /tldr (одно предложение), /actions (только задачи и дедлайны), /decisions (только что решили). Просто параметризуй системный промпт.
  • Классификация важности. Перед саммари просишь GigaChat поставить тег: срочно / обсудить / фон. Полезно для рабочих чатов — за 5 секунд понимаешь, надо ли вообще читать.
  • Перевод. Если пересылают переписку на английском — GigaChat нормально с ней справляется, а можно явно попросить «суммируй и переведи на русский».
  • Личный дайджест по утрам. Юзер привязывает чат, бот в 9:00 присылает саммари за вчера. Это уже требует БД (хранить последний обработанный message_id), но архитектурно — то же самое.
  • Голос. GigaChat умеет в распознавание речи (SaluteSpeech). Пересылаешь голосовое — бот сначала транскрибирует, потом суммирует. Полезно для длинных голосовых от любителей наговаривать пять минут вместо двух строк.

Подводные камни

  • SSL. Если запустил с verify_ssl_certs=False — это нормально для теста, но в проде поставь корневой сертификат Минцифры через ca_bundle_file=.... Иначе MITM теоретически возможен.
  • Контекст 8k токенов. Это мало по меркам современных моделей. Без chunking длинный чат тебе никто не суммаризирует — поэтому split_text обязателен.
  • Авторизация раз в 30 минут. SDK сам обновляет access token, но если бот висит долго без активности — первый запрос после простоя может занять чуть дольше (идёт за новым токеном). Лучше не пугаться, просто добавь логирование.
  • Rate limit. Freemium — 1М токенов в месяц и не более 1 запроса в секунду. Если запустишь массовую обработку чанков параллельно — словишь 429. Делай последовательно (как у меня в коде), или ставь asyncio.Semaphore(1).
  • Сообщения с медиа. Если пересылаешь сообщение с фото и подписью, в message.text подписи не будет — она в message.caption. У меня в коде это учтено (or update.message.caption), но изображения как таковые этот бот не понимает.
  • Утечка ключа. Authorization Key от GigaChat — это фактически логин+пароль к твоему лимиту. Никогда не коммить в репо, никогда не присылай скриншотом. Утёк — сразу перевыпускай в личном кабинете.

Что в итоге

За 75 минут у тебя в Telegram живёт собственный личный assistant, который снимает боль непрочитанных чатов. Без VPN, без зарубежной карты, без подписки. На бесплатном тире проживёт год минимум. Это — рабочий пример того, что РФ-стек для AI-проектов давно перестал быть «второсортным»: GigaChat по качеству для саммари сравним с gpt-4o-mini, а в личных проектах разницы ты просто не заметишь.

Заодно ты понял, как устроен типичный AI-pipeline: пользователь → бот → разбиение на чанки → LLM → merge → ответ. Эта же схема работает для RAG, для классификации, для агентов — меняется только содержимое промпта.

Готово! Дальше — добавь к боту команду /tldr с укороченным форматом и запусти на Yandex Cloud. Через неделю использования сам поймёшь, какие ещё команды тебе нужны лично. Это самый честный способ развивать пет-проект — собственным трением.
