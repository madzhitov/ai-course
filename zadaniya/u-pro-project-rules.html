Правила проекта для агента

Материал обновлён 27.11.2026

Файл AGENTS.md на одну страницу: где код, как работать с ветками, что агенту можно без спроса и что только с вашего согласия, что считать готовым. Агент читает его в начале каждой сессии

около 30 мин · продвинутый · без VPN · задача «Написать правила проекта для агента»

Черновик на согласовании: текст может уточняться.

Чем делать

SourceCraft Code Assistant, GigaCode, ГигаЧат

Что подготовить

  • Проект в папке под git: сайт, бот, скрипты или документация
  • Агент, который читает файлы проекта, или обычный чат-ИИ
  • 10 минут, чтобы вспомнить, что агент уже ломал или делал не так

Делать по шагам

Шаги

1. Опишите проект и боли

Пока без ИИ. Коротко: что за проект, где он работает, чем собирается и проверяется. И главное: что агент уже делал не так. Каждая такая ошибка станет правилом.

2. Соберите черновик правил

Отправьте промпт в чат или агенту в проекте. Правила должны быть короткими и в повелительном наклонении: агенту нужно «делай так», история ему ни к чему.

Составь файл AGENTS.md для моего проекта. Это правила, которые агент читает в начале каждой сессии.
Проект и что шло не так: [проект и что шло не так]

Разделы:
1) Где код и куда его нельзя класть.
2) Git: ветка на каждую задачу, как называть, когда пушить. В main только с моего согласия.
3) Ключи: где лежат, что никогда не попадает в git и в чат.
4) Можно без спроса / только с моего «да». Во второй список: влить в main, выкатить, удалить данные, потратить деньги, написать людям.
5) Что считать готовым: какие команды проекта должны пройти.
6) Куда писать итог сессии.
Каждое правило одной строкой, без пояснений. Не больше одной страницы. Если чего-то не знаешь о проекте, оставь [уточнить: …], не выдумывай.

3. Проверьте каждое правило

Прочитайте черновик. Правило, которое нельзя проверить, агент выполнить не сможет: «пиши аккуратно» вычеркните, «перед словом готово запусти npm test» оставьте. Заполните все [уточнить].

  • Каждая ошибка из первого шага превратилась в правило
  • У каждого правила есть проверка: команда, файл или действие
  • Список «только с моего да» включает выкладку, удаление и деньги
  • В файле нет ключей, паролей и адресов серверов
  • Файл помещается на один экран-два

4. Положите файл в проект

Сохраните как AGENTS.md в корне проекта и закоммитьте. SourceCraft Code Assistant по документации добавляет AGENTS.md из корня в контекст (в VS Code функцию нужно включить). Claude Code читает CLAUDE.md: сделайте его ссылкой на тот же файл, чтобы правила не расходились. Если ваш агент или чат файл сам не читает, вставляйте его первым сообщением.

5. Проверьте на агенте

Откройте новую сессию и спросите агента о правилах, не подсказывая.

Прочитай правила проекта. Ответь коротко: что тебе нельзя делать без моего согласия, какие команды надо запустить перед словом «готово» и куда записать итог сессии.
  • Агент назвал правила из файла, общих советов нет
  • Если ответ мимо, правило переписано короче и проверено ещё раз

Если получилось почти

  • Правил получилось три страницы. Попросите: «сократи до одной страницы, оставь только то, что агент нарушал или может нарушить»
  • Агент знает правила, но всё равно делает по-своему. Перенесите самое важное правило в начало файла и добавьте к нему проверку: «перед словом готово покажи вывод npm test»
  • В правила попал пароль или адрес сервера. Уберите и замените на «ключи в .env, см. .env.example»
